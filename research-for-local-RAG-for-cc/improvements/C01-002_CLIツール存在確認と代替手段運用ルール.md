# C01-002 CLI ツール存在確認と代替手段運用ルール

## 1. はじめに

### 1.1 要改善点概要

Claude Code は内部のシステム指示で `gh` / `jq` / `ripgrep` 等の外部 CLI ツールの利用を推奨するが、これらは Claude Code インストーラに同梱されておらず、ユーザ環境に未インストールであることがある。Claude が「インストール済み前提」で実行を試みて初めて欠落が判明し、空打ち（実行失敗 → 別経路への切り替え）が発生する構造的問題がある。

具体的な発覚事象として、C01 相談中に PR 作成のため `gh pr create` を Bash 経由で実行したところ、`gh: command not found` エラーが発生。MCP の `mcp__github__create_pull_request` への切り替えで対処したが、事前にツール存在確認をしていれば 1 回の試行で正解経路を選択できていた。

## 2. 発生事象の整理

### 2.1 発生事象

2026-05-10、C01 相談の作業として `git push -u origin <branch>` 後に `gh pr create ...` を Bash で実行したところ:

```
/usr/bin/bash: line 28: gh: command not found
```

確認の結果、Git Bash for Windows 環境に `gh` CLI は未インストール。`C:/Program Files/GitHub CLI/` も `~/AppData/Local/Programs/GitHub CLI/` も存在しなかった。

代替として、既に `settings.local.json` の allow リストに登録済みだった `mcp__github__create_pull_request` ツール（GitHub MCP Server 経由）に切り替え、PR #3 作成は成功。

### 2.2 発生経緯

1. **2026-05-10**: C01 相談の PR 作成段階で、Claude Code のシステム指示「Use the `gh` command via the Bash tool for ALL GitHub-related tasks」に従い `gh pr create` を実行 → 失敗
2. **事後の存在確認**: `which gh` で PATH 上に存在しないことを確認、複数の標準インストール先パスにも未配置を確認
3. **MCP 経由でリカバリ**: `mcp__github__create_pull_request` ツールを ToolSearch でロード → 直接呼び出しで PR 作成成功
4. **作業指示者との振り返り**: Anthropic がシステム指示で推奨するツール群が必ずしもユーザ環境にインストールされていない構造的問題を確認。本要改善点として起票

## 4. 特記事項/補足事項

- 本要改善点の動機となった根本構造は **「Anthropic がシステム指示で推奨するツールの全量を、ユーザが自前で把握・インストールする必要がある」** という Claude Code 配布形態のギャップ。Anthropic 側の改善（インストーラのオプションパック化 / 推奨ツール一覧の公式ドキュメント化 / `claude doctor` のようなツール存在チェック）が将来的に提供される可能性もあるが、それまでの繋ぎとして本ルール整備が必要
- C01-003（公式ドキュメント調査 Skill 化）と同じく、**「バックエンドの存在確認 + 代替経路への自動切り替え」** という共通パターンを持つ。実装段階で共通化可能なロジックは抽象化を検討する
- **公式ドキュメント側の確認結果（2026-05-10）**: ローカル版 Claude Code 向けの「推奨外部ツール一覧」ページは公式ドキュメントには存在しない。代わりに、機能ごと・場面ごとの個別記述として散在している（`ripgrep` は同梱 / `gh` は PR モニタリング機能と `/web-setup` で必要 / `Git for Windows` は Windows での Bash tool 利用に推奨 等）。一方、`Claude Code on the web` 向けには「Installed tools」表（クラウドセッション環境の pre-installed tools）があり、ローカル環境への導入推奨ツールの参考情報として有用
- **ワンライナー実装パターンの工夫（C01-002 採用候補 A の補足）**: メタルール実装時、`command -v <tool> && <処理> || <代替>` 形式のワンライナーを使えば Claude Code 側のツール呼び出しコストは 1 回で済む（`which` より `command -v` 推奨。POSIX 標準・外部コマンド非依存）。ただし compound command の各サブコマンドが独立に permission チェックされる仕様（公式 permissions.md）のため、`command` / `echo` 等の builtin も allow リスト登録が必要
