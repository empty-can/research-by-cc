# F02-010 レビュー対象成果物の資産性質改善

## 1. はじめに

### 1.1 要改善点概要

レビュー対象成果物（フェーズ報告書等）の資産性質（関連資産の分散具合・抽象度の複層化・純粋なボリューム等）が、Round 3 取り込み時の収束回数や、レビュー全体の効率に大きな影響を与える。資産性質の改善ガイドライン（成果物作成段階での品質担保ルール）を整備することで、レビュー収束に要する反復回数を削減できる可能性が高い。

### 1.2 サマリ

| 項目 | 内容 |
| --: | :-- |
| **カテゴリ** | テンプレート運用 / 文書品質 |
| **優先度** | 中 |
| **スコープ** | 横断 |
| **ステータス** | 未対処 |
| **影響範囲** | 全フェーズの成果物作成（フェーズ報告書・統合報告書・設計書 等）。改善が反映されればレビュー Round 3 の整合性確認が短時間で収束しやすくなり、Round 4/5 差戻しリスクも低減する |
| **関連 ID** | F02-009（記載ルール・観点規定）と関連性は強いが、観点・効果範囲が広いため別票で起票 |
| **採用案** | — |

## 2. 発生事象の整理

### 2.1 発生事象

2026-05-05 の改訂版クロスレビューテンプレート検証作業（02.99 報告書を対象とした 3 ラウンド対話型クロスレビュー）において、Round 3 のセルフレビュー反復回数に観点別の差が観察された:

- 論理整合性レビューア再対応（Opus）のセルフレビュー反復: **4 巡**
- 実用性レビューア再対応（Sonnet）のセルフレビュー反復: **1 回**

論理整合性側で反復回数が多くなった主要因は、レビュー対象成果物（02.99 報告書）の資産性質に起因する論点が複数発生したこと:

- **関連資産の分散**: §9.1（報告書側）と `ハマりどころ.md` の状態が別ファイルで管理され、§9.1 の「未追記」記述が `ハマりどころ.md` 現状（追記済み）と乖離していた。I3 として指摘され、レビューイ・レビューア間の事実認識補正に Round 2/3 で工数増
- **抽象度の複層化**: §3.7（2 軸）と §4 H1（3 軸）で対立軸の表現が異なり、I1/I2 の判定根拠追跡に工数増
- **純粋なボリューム**: 報告書 666 行（中規模）。今回は問題なかったが、これを超える成果物では Round 1 の誤検知チェックコストが指数的に増える可能性

### 2.2 発生経緯

詳細な議論経緯は以下のファイルを参照:

- `reports/02.基礎調査/99.最終基礎調査報告/レビュー/テンプレート検証_セルフレビュー運用考察_2026-05-05.md` §2.3「もう一段の観察 — Round 3 の偏り」

主要な経緯:
1. Round 3 の反復回数差（論理整合性 4 巡 vs 実用性 1 回）について作業指示者から見解を求められた
2. 「Round 3 のレビューアの繰り返し目的に照らすと、繰り返しの上限値を設けるべきではない」「繰り返し回数の多さが気になる場合でも、繰り返しに上限を設けることで回数を抑制するのは適切な対応とは言えない」「取り込み対象資産の性質の見直しによって収束までに要する回数を削減できないかを検討するべき」と作業指示者から方向性提示（同考察ファイル §2.3 作業指示者の回答）
3. F02-009 と関連性は強いが「観点や効果範囲は異なる（資産性質の見直しと改善の方が検討すべき観点の範囲や数が多く、また改善による効果範囲も広い）」との判断から別票での起票指示（同 §2.3 / §4.5）

## 3. 原因分析

### 3.1 直接原因

- フェーズ報告書・統合報告書の作成段階で、関連資産との状態同期・抽象度の整合・標準ボリュームに関する **品質ガイドラインが未整備**
- 同種の論点について作成者（Claude Opus 等）が事前に意識する仕組みが存在せず、事後にレビューで発見・補正することになっている

### 3.2 根本原因

> 対処着手時に `/5-whys` スキルで根本原因分析を実施予定。

## 4. 同件調査

> 対処着手時に実施予定。02 フェーズの 02.99 統合報告書以外に、各サブタスク報告書（01〜08）でも同種の問題が発生していたか、また 03/04/05 フェーズで同件・類件が観察されるかを継続観察する。

## 5. 再発防止策

> 対処着手時に `/5-whys` の対策セクションを参照して案出予定。
> 暫定的な対応方向の素案として:
> - **関連資産の分散対応**: 状態同期が必要な箇所はリンク注記 / 単一ソース化 / 報告書側に「最新状態は ハマりどころ.md §X 参照」と明記し本文側で状態を断定しない、等のルール化
> - **抽象度の複層化対応**: 主要軸（仮説・対立軸・分類等）の定義を 1 箇所に集約し他箇所は参照に切り替えるルール化
> - **純粋なボリューム対応**: フェーズ報告書の標準ボリューム上限の目安（例: 1 報告書あたり 500〜800 行）を CLAUDE.md または運用ガイドに規定
> - これらガイドラインを個別調査フォルダの CLAUDE.md または `.claude/rules/` に追加（横断スコープのため後者が望ましい可能性）

## 6. 特記事項/補足事項

- 本要改善点は F02-009 と関連性が強いが、効果範囲がより広い（資産性質改善はレビュー効率のみならず文書品質全体・後続フェーズ参照時の理解負荷低減にも寄与）。F02-009 の対処（レビュー時の規定整備）と並行して、F02-010 の対処（成果物作成段階の品質担保）を進めることで、両面から品質向上を図れる
- 本要改善点が解消されると、Round 3 整合性確認の収束回数削減のみならず、Round 4/5 差戻しリスクも実質低減する見込み
