## 事実

### RAG構成要素

| 要素 | 採用物 | 備考 |
|------|--------|------|
| 埋め込みモデル | `all-MiniLM-L6-v2` | `zotero-mcp` 側で使用。日本語精度が低い |
| 埋め込みモデル（補完） | `bge-m3` | `zotero-local-rag` 側で使用。より高精度 |
| ベクトルDB | Chroma | `CHROMA_DIR` で保存先を設定 |
| 検索手法 | セマンティック検索（意味検索） | キーワード一致ではなく意味ベース |

### ツール構成

- `zotero-mcp`: 既存のMCPサーバー。`all-MiniLM-L6-v2` で書誌情報ベースの検索
- `zotero-local-rag`: 著者が構築。PDF全文をChromaでインデックス化し `bge-m3` で検索

### Claudeとの連携方法

- `zotero-mcp` と `zotero-local-rag` を **MCP経由で協調動作** させるカスタムプロンプト運用
- `rag_search` ツール（全文検索優先）と `zotero_get_item_metadata` ツール（書誌情報確認）を組み合わせる
- Claude Desktop / Claude.ai からMCPサーバーとして呼び出す形式

### Zoteroとの連携

- Zoteroのローカルディレクトリを直接参照（サーバー同期不要）
- メタ情報のないPDFも含め全資料をインデックス化
- 段落単位の検索結果に `itemKey` を付与し、書誌情報との照合を実現

### 環境

- OS: Windows 11
- Python: 3.10.1
- 主要環境変数: `EMB_PROFILE: "fast"`, `HF_HUB_OFFLINE: "1"`, `TRANSFORMERS_OFFLINE: "1"`

### 既存ツール（Beaver）の課題として挙げられた点

- サーバー依存・同期必須
- セッション制限

## 観察と示唆

- `zotero-mcp`（MCP標準）単体では日本語の埋め込み精度が不足する。日本語コンテンツが多い環境では `bge-m3` 等の多言語モデルへの置き換えが必要になる可能性がある（著者が実際に課題として認識）。
- MCP経由の連携は Claude Desktop / Claude.ai との接続において実用実績がある。Claude Code との直接連携については本記事では言及なし。
- ベクトルDBとして Chroma が軽量・ローカル運用で採用されている。ChromaはOSSかつ商用無料であり、本調査の関心領域に合致する。
- 「全文インデックス化」アプローチは、書誌情報だけでなくPDF本文まで検索対象に含める点で RAG の典型的な利点を活かしている。
- ローカルLLM（LM Studio + Qwen / Llama）の手順も記述されているが、本調査の関心外。ただしベクトルDB・埋め込みモデルの選定部分は共通して参照可能。
