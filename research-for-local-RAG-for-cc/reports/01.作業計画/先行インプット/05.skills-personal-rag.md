## 事実

### Skills アプローチの方式

- Skills は `SKILL.md`（自然言語の指示書）＋ スクリプトをディレクトリに置くだけで Claude Code が自動認識・実行するしくみ
- 常駐プロセス不要。Claude Code がエージェントとして CLI コマンドを都度実行する形態
- 自然言語で「インデックス化して」「検索して」と指示でき、エージェントが `SKILL.md` の手順に従いコマンド実行

### Skills 版 vs MCP 版の対比（著者が両方実装）

| 項目 | MCP 版 | Skills 版 |
|------|--------|-----------|
| DB | PostgreSQL + pgvector | SQLite（ファイル 1 つ） |
| 埋め込みモデル次元数 | 1024 次元 | 384 次元 |
| 実行方式 | 常駐 HTTP サーバー | CLI 都度起動 |
| 検索応答速度 | 約 0.1 秒 | 約 9 秒（モデル再ロード込み） |
| リソース要件 | 高め | 軽量 |

### 採用構成要素（Skills 版）

- **DB**: SQLite（ファイル単体で完結するため選択）
- **埋め込みモデル**: `intfloat/multilingual-e5-small`（384 次元、約 500 MB）
- **検索方式**: コサイン類似度
- **パッケージ管理**: `uv`（`uv sync` のみでセットアップ完了）
- **関連度スコア付与**: R²AG（EMNLP 2024）の簡易実装。検索結果に `[関連度: 0.92 (高)]` 形式のメタデータを付与し、エージェントが重要度判断しやすくする

### Claude Code との連携方法

- Skills ディレクトリに `SKILL.md` とスクリプトを配置すると Claude Code が自動認識
- 検索コマンド例: `uv run python workspace_rag.py search -w /path/to/workspace -q "クエリ"`
- インデックス化・HTTP サーバー起動も自然言語で依頼可能

### ハマりどころ・問題点

- **CLI 起動遅延**: 約 20 万チャンク環境でモデル再ロードのたびに約 8〜9 秒かかる
- **対処**: 常駐 HTTP サーバー化（systemd ユーザーサービスとして設定）することで約 0.1 秒に短縮。ただしそれは実質 MCP 版と同方向の構成になる

## 観察と示唆

- Skills アプローチは「埋め込みベース RAG」の一形態であり、ベクトル検索 vs キーワード検索の対立ではない。違いは「MCPサーバー（常駐プロセス）か CLI（都度起動）か」という実行方式の違い
- 軽量さを優先するなら SQLite + 384 次元モデル + Skills の組み合わせが有効。ただし検索頻度が高い用途では常駐サーバー化が必要になり、結果として MCP 版に近づく
- `uv` による環境構築の容易さは導入コスト低減に寄与（`uv sync` のみ）
- 関連度スコア（R²AG）の付与はエージェントへの情報品質シグナルとして有効。ローカル RAG 設計時に採用を検討する価値あり
- `intfloat/multilingual-e5-small` は日本語対応の小型モデルとして具体的な選択肢になりうる
