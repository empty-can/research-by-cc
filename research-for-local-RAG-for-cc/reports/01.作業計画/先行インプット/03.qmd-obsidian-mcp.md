## 事実

### RAG 構成要素

| 要素 | 採用技術 |
|------|----------|
| 埋め込みモデル | embedding-gemma-300M-Q8_0（約 300 MB） |
| ベクトル DB | sqlite-vec（SQLite ベース） |
| 全文検索 | SQLite FTS5（BM25） |
| リランキング | qwen3-reranker-0.6b |

- 検索は 3 層ハイブリッド：BM25 全文検索 → ベクター検索 → LLM リランキング
- 完全ローカル実行（外部 API 不要）

### 環境要件・インストール手順

```bash
# 前提: Bun 1.0.0 以上、macOS は Homebrew 版 SQLite が必要
brew install sqlite
bun install -g https://github.com/tobi/qmd
qmd --version
```

### Vault 登録・インデックス作成

```bash
qmd collection add ~/Documents/ObsidianVault --name obsidian
qmd context add qmd://obsidian "個人メモ"
qmd embed   # 初回は数分〜数十分かかる
```

### Claude Code MCP 設定

`~/.claude/settings.json` に追記：

```json
{
  "mcpServers": {
    "qmd": {
      "command": "qmd",
      "args": ["mcp"]
    }
  }
}
```

- 設定変更後は Claude Code の再起動が必要

### MCP で提供されるツール

| ツール名 | 機能 |
|----------|------|
| `qmd_search` | BM25 全文検索 |
| `qmd_vsearch` | ベクター検索 |
| `qmd_query` | ハイブリッド検索（3 層） |
| `qmd_get` | 単一ドキュメント取得 |
| `qmd_multi_get` | 複数ドキュメント取得 |
| `qmd_status` | インデックス状態確認 |

### ハマりどころ・トレードオフ

- 初回 `qmd embed` はドキュメント数に応じて数分〜数十分かかる
- 大量ドキュメント環境では初回検索に遅延が生じる可能性あり
- ストレージ効率：qmd は埋め込みをそのまま保存（比較対象の LEANN は 97% 削減）
- macOS では Homebrew 版 SQLite が必須（システム同梱版では sqlite-vec が動作しない場合あり）

## 観察と示唆

- qmd は「インストール → コレクション登録 → `qmd embed` → MCP 設定」の 4 ステップで Claude Code と接続できる。手順が単純で導入障壁は低い。
- BM25 + ベクター + LLM リランキングの 3 層構成は、キーワード不一致でも意味的に関連する文書を拾える点で、単純な全文検索より優れる。
- 埋め込みモデル（300 MB）とリランキングモデル（0.6B）はいずれも小型であり、CPU 環境でも動作する可能性が高い。
- sqlite-vec を用いることで追加の DB サーバーが不要。単一の SQLite ファイルで完結する構成は運用コストが低い。
- ストレージ効率の課題（LEANN との比較で言及）は、大規模 Vault では検討が必要になる場合がある。
- Obsidian 以外の Markdown ドキュメント群にも同様の手順で適用可能と推測される（`qmd collection add` で任意ディレクトリを指定）。
