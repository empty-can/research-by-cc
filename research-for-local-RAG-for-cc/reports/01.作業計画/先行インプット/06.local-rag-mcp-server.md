## 事実

### RAG 構成要素

| 要素 | 採用技術 | 備考 |
|---|---|---|
| 埋め込みモデル | intfloat/multilingual-e5-large | 1024 次元、ローカル実行 |
| ベクトル DB | PostgreSQL + pgvector 拡張 | Docker で起動 |
| ドキュメント変換 | MarkItDown ライブラリ | Markdown・テキスト・PPTX・PDF 対応 |
| パッケージ管理 | uv | Python 環境 |
| MCP フレームワーク | 独自実装（LangChain 非依存） | 著者明言 |

### セットアップ手順（要点）

```bash
# リポジトリ取得・依存解決
git clone <repo>
cd mcp-rag-server
uv sync

# PostgreSQL + pgvector を Docker で起動
docker run --name postgres-pgvector \
  -e POSTGRES_PASSWORD=password \
  -p 5432:5432 \
  -d pgvector/pgvector:pg17

# DB 作成
docker exec -it postgres-pgvector psql -U postgres -c "CREATE DATABASE ragdb;"
```

.env に PostgreSQL 接続情報・ドキュメントディレクトリ・埋め込みモデル設定を記載。

### Claude Code への MCP 登録コマンド

```bash
claude mcp add mcp-rag-server -- uv run --directory /path/to/mcp-rag-server python -m src.main
```

### Cline / Cursor 向け MCP 設定（JSON）

```json
"mcp-rag-server": {
  "command": "uv",
  "args": ["run", "--directory", "/path/to/mcp-rag-server", "python", "-m", "src.main"]
}
```

### MCP ツール構成（使用例より）

- ドキュメントのインデックス化（チャンクサイズ・オーバーラップをパラメータ指定可）
- インデックスのクリア
- ベクトル検索

### 設計方針（著者明言）

- LangChain 等「変化の激しいライブラリ」に依存しないことで長期安定性を優先
- 管理操作（インデックス化・クリア）は CLI、検索は MCP で役割分担

## 観察と示唆

- multilingual-e5-large はローカル実行でき、日本語対応・無料。他記事でも登場しており有力候補。
- pgvector は PostgreSQL の拡張であり、Docker イメージ `pgvector/pgvector:pg17` で手軽に起動可能。追加 DB ソフト不要でハードルが低い。
- LangChain 非依存の自作実装は保守性の観点では有利だが、導入時の実装コストがかかる。既製 OSS を使う場合との比較が必要。
- Claude Code への MCP 登録が `claude mcp add` 1 コマンドで完結する点はシンプル。`uv run --directory` でパスを渡す形式は他の Python 系 MCP と共通パターン。
- 記事内にハマりどころ・既知の制限の記載はなく、成功事例のみ。実際の運用上の問題（初回モデルダウンロード時間・メモリ使用量等）は不明。
