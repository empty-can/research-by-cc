## 第 1 部: 公式が「RAG」と呼んでいる機能（あれば）

**結論: 存在しない。**

唯一の `RAG` 出現箇所は glossary の以下記述のみ（`claude-code-llms-full.txt:18563`）:

> "This glossary defines Claude Code terminology. Each entry links to the page where the concept is covered in depth. For model-level concepts like tokens, temperature, and RAG, see the [platform glossary](https://platform.claude.com/docs/en/about-claude/glossary)."

つまり Anthropic は RAG を **Claude Code のレイヤーではなく Claude プラットフォーム（モデル）のレイヤーの概念** として位置付けている。Claude Code 自体には埋め込みベクトル化・セマンティック検索・ベクトルストアといった機能は **公式ドキュメント内に一切存在しない**。

## 第 2 部: RAG 的用途に流用可能な標準機能

「大量ドキュメントから必要情報を最小コンテキストで取得する」という RAG の目的に寄与する Claude Code 標準機能を、機能カテゴリ別に整理する。

### 2.1 Skill 系（段階的開示による on-demand 知識ロード）

#### 機能名: Agent Skills（`SKILL.md`）

- **公式ドキュメント上の位置**: `claude-code-llms-full.txt:35590-36400`（メインページ `docs/en/skills`）、SDK 版は行 50792–51100
- **概要**: `SKILL.md` ファイルに記述された指示・知識・ワークフロー。Claude が関連性を判断して自動ロードするか、ユーザーが `/skill-name` で明示呼び出しする。
- **RAG 観点でのカバー範囲**:
  - **「progressive disclosure（段階的開示）」を公式に標榜**（行 30748）。
  - セッション開始時にロードされるのは `description`（最大 1,536 文字、行 35780）のみ。
  - 呼び出されて初めて `SKILL.md` 本文がコンテキストに入る（行 35877 の比較表）。
  - SKILL.md からさらに supporting files（`reference.md`, `examples.md` 等）を参照する構造で、本文も「必要なときだけ Claude に読ませる」構成が可能（行 35824–35846, 36169–36210）。
  - **公式に Skill 本文は 500 行以下を推奨**（行 35846 Tip）。
  - 動的コンテキスト注入: ``!`command``` 構文で skill ロード時に shell コマンドの出力を Claude に渡す（行 35964–36013）。
- **トリガー方式**:
  - 自動（モデル判定）: `description` をモデルが評価して関連時にロード
  - 明示: `/skill-name` でユーザーが呼ぶ
  - `disable-model-invocation: true` で明示呼び出しのみに制限可能（行 35784, 35850–35888）
  - `user-invocable: false` で逆に Claude のみが呼べる「背景知識」用途も可能
  - `paths:` frontmatter で「特定ファイル編集時のみ自動ロード」のスコープ限定が可能（行 35792）
- **スコープ**:
  - Enterprise / Personal（`~/.claude/skills/`）/ Project（`.claude/skills/`）/ Plugin の 4 階層（行 35673）
  - サブディレクトリの `.claude/skills/` も `--add-dir` 配下 / monorepo の子パッケージで再帰的に発見される（行 35686–35712）
- **制約・限界**:
  - Skill 本文は一度ロードされると **そのセッション中ずっとコンテキストに残る**（行 35885）。再度ファイルから読み直しはされない。
  - コンパクション後の再注入は **各 skill 最大 5,000 トークン、全 skill 合計 25,000 トークンまで**（行 35888）。それを超えた古い skill はドロップ。
  - 1 skill の `description + when_to_use` 合計は **1,536 文字でカット**（行 35780）。
  - サブエージェント内では `skills:` フィールド指定時に **on-demand ではなくフルプリロード** に変わる（行 16974, 35882, 38049–38067）。
- **代替機能との位置関係**: CLAUDE.md（毎セッション全文ロード） vs Skill（on-demand）の比較表（行 16809–16823）と CLAUDE.md vs Rules vs Skills の比較表（行 16826–16839）が公式に存在。「200 行を超えたら CLAUDE.md から Skill へ」が公式推奨。

#### 関連: Bundled skills

- `/simplify`, `/batch`, `/debug`, `/loop`, `/claude-api` などプリインストール skill（行 35607–35611, 18611）
- RAG 観点では直接寄与しないが、Skill アーキテクチャの組み込み実例として参照価値あり

### 2.2 Memory / CLAUDE.md 系（毎セッション自動ロード）

#### 機能名: CLAUDE.md（プロジェクトメモリ）

- **公式ドキュメント上の位置**: 行 25977–26410
- **概要**: ユーザーが書く永続指示。毎セッション開始時にコンテキストへ全文ロード。
- **RAG 観点でのカバー範囲**:
  - **「always-on context」の役割**。RAG 的な「on-demand 取得」とは対極だが、頻出参照される知識を一度のセッションで安定供給できる。
  - サブディレクトリの CLAUDE.md は **遅延ロード**（行 26124, 13731）。 → ディレクトリ階層を擬似的な「コンテキストパーティション」として使える。
  - `@path/to/file` import で外部ファイルを取り込める（最大 5 hop、行 26066–26092）。
- **トリガー方式**: 自動（セッション開始時 / サブディレクトリの場合は Claude がそのディレクトリの Read を発火した時）
- **スコープ**: Managed policy / User（`~/.claude/CLAUDE.md`）/ Project（`./CLAUDE.md`）/ Local（`./CLAUDE.local.md`）の 4 階層（行 26029–26034）
- **制約・限界**:
  - **200 行以下推奨**（行 26054, 16960 Tip）。それ以上で adherence が低下と明記。
  - `@path` import で物理ファイルを分割しても **launch 時に全部ロードされる**ためコンテキスト削減にはならない（行 26054 末尾, 26394）。
  - コンパクション後は **プロジェクトルート CLAUDE.md と auto memory のみ再注入**。ネスト CLAUDE.md は次のファイル読み込みまで失われる（行 13287, 26398）。
- **代替機能との位置関係**: 「200 行を超えたら reference 性のものは Skill か `.claude/rules/` へ移行」が公式推奨。

#### 機能名: `.claude/rules/`（path-scoped rules）

- **公式ドキュメント上の位置**: 行 26142–26226
- **概要**: CLAUDE.md を分割するためのルールファイル。`paths:` frontmatter で「特定ファイル編集時のみ自動ロード」を実現。
- **RAG 観点でのカバー範囲**:
  - **path-scoped rule は path_glob_match が成立したときだけ Claude のコンテキストに追加される**（行 26166–26203）。
  - すなわち「特定ディレクトリで作業する時だけ関連リファレンスを引いてくる」というドメイン特化型の擬似 RAG として機能する。
- **トリガー方式**: 自動（`paths:` グロブにマッチするファイルを Claude が読んだとき）
- **スコープ**: User（`~/.claude/rules/`）/ Project（`.claude/rules/`）
- **制約・限界**:
  - コンパクション後は **`paths:` 付きルールは失われる**（行 13286, 13291）。次にトリガーファイルが読まれるまで再注入されない。

#### 機能名: Auto memory（`MEMORY.md`）

- **公式ドキュメント上の位置**: 行 26297–26360（claude-code v2.1.59+）
- **概要**: Claude 自身が会話中の学びを蓄積するメモリ。リポジトリ単位で `~/.claude/projects/<project>/memory/` に保存。
- **RAG 観点でのカバー範囲**:
  - **これが Claude Code 内で最も RAG に近い構造**。
  - `MEMORY.md` は「インデックスファイル」として機能し、`debugging.md`, `api-conventions.md` 等の topic file への参照を持つ（行 26331–26341）。
  - セッション開始時に **`MEMORY.md` の先頭 200 行 or 25KB のみ**ロード（行 26347）。
  - topic file は **on-demand**: Claude が必要と判断したときに通常の Read で読み出す。
- **トリガー方式**: 自動（セッション開始時にインデックスのみロード）+ on-demand（Claude 判定で topic file を Read）
- **スコープ**: リポジトリ単位（git repo の root から決定）、全 worktree で共有、マシンローカル
- **制約・限界**:
  - **マシン間で共有されない**（行 26343）。クラウド/別端末との同期なし。
  - `MEMORY.md` インデックスが 200 行 / 25KB を超えると、超過部分は startup ロードされない。

### 2.3 Subagent / Agent SDK 系（コンテキスト分離による疑似 RAG）

#### 機能名: Subagents（`Agent` ツール）

- **公式ドキュメント上の位置**: 行 37646–38500（メインページ `docs/en/sub-agents`）、tools-reference 行 39342–39361
- **概要**: 独立したコンテキストウィンドウを持つ子エージェント。サブエージェントは自前で大量ファイル読み・検索を行い、**親には要約のみ返す**。
- **RAG 観点でのカバー範囲**:
  - **これが Claude Code 内で「大量ファイル → 必要情報のみ取得」という RAG の中核ニーズを最も忠実に再現する標準機構**。
  - 親のコンテキストには subagent の中間 tool call は一切残らず、最終テキスト結果のみ返る（行 39344, 16804）。
  - ビルトインの `Explore` subagent は **Haiku モデル + read-only ツール限定** で「codebase 探索の専用 RAG worker」のような位置付け（行 37683–37692, 37718）。
  - `Plan` subagent は plan mode 中の調査用（行 37695–37703）。
  - skill との組み合わせ: skill に `context: fork` + `agent: Explore` を指定すると、skill 内容を Explore agent に流し込み「研究タスク → 要約」を実行できる（行 36015–36058）。
- **トリガー方式**:
  - 自動（Claude が `description` から判定して `Agent` ツールを呼ぶ）
  - 明示: `@<agent-name>` メンション、`Use the X subagent to ...` のような自然言語、`--agent <name>` フラグでセッション全体を subagent 化（行 38262–38307）
- **スコープ**: Managed > CLI flag > Project（`.claude/agents/`） > User（`~/.claude/agents/`） > Plugin（行 37807–37815）
- **制約・限界**:
  - **Subagent は他の subagent を spawn できない**（行 37702, 38380）。ネスト構造不可。
  - 結果がメインに返るときに、複数 subagent を並列で走らせて全員が詳細結果を返すとコンテキストを食う（行 38347 Warning）。
  - Subagent 内では skill が **on-demand ロードではなくフルプリロード** される設計（行 16974, 38049–38067）。
  - フォアグラウンド subagent は permission prompt を出すが、バックグラウンドは「prompt が必要な tool call は auto-deny」される（行 38311–38317）。
- **代替機能との位置関係**: 「Skill vs Subagent」「Subagent vs Agent team」の公式比較表（行 16789–16865）あり。

#### 関連: Agent teams（experimental）

- 行 18567（glossary）, 13371–13383 ほか
- 複数の独立 Claude Code セッションが peer-to-peer メッセージで協調。RAG 観点では「並列で別領域を調査」用途に流用可能だが、**約 7 倍のトークン消費**（行 13483）。本調査スコープでは優先度低。

### 2.4 MCP 系（外部 RAG への接続経路）

#### 機能名: MCP servers（Model Context Protocol）

- **公式ドキュメント上の位置**: 行 24717–25745（メインページ `docs/en/mcp`）、SDK 版は行 44686–
- **概要**: 外部ツール・データソースへの標準接続プロトコル。stdio / HTTP / SSE / WebSocket トランスポート対応。
- **RAG 観点でのカバー範囲**:
  - **「Claude Code から外部 RAG システムを呼ぶ標準経路」として最も適合する**。本調査で構築予定のローカル RAG（ベクトル DB + 検索 API）を MCP サーバーとしてラップすれば、Claude Code から `Skill` のように使える。
  - 3 種の MCP 資産が利用可能:
    1. **Tools**（行 24722–24735）: Claude が呼べる関数。検索 API はここで提供。
    2. **Resources**（行 25586–25625）: `@server:protocol://path` で @-mention 可能なデータ。ファイル風に attachment として注入。
    3. **Prompts**（行 25707–25745）: `/mcp__servername__promptname` でスラッシュコマンドとして呼べる定型プロンプト。
  - **MCP Tool Search**（行 25627–25705, 18713）が default 有効: ツール定義スキーマを **on-demand** 化してコンテキスト節約。本質的に「MCP ツール群に対する Skill-like progressive disclosure」。
  - `alwaysLoad: true` で常時ロード化も可能（行 25685–25705）。
- **トリガー方式**:
  - Tools: Claude が判定（または ToolSearch で発見）して呼ぶ
  - Resources: ユーザーが `@server:resource` で @-mention（自動 fetch & attach）
  - Prompts: ユーザーが `/mcp__name__prompt` で明示
- **スコープ**: Local（`~/.claude.json`）/ Project（`.mcp.json`）/ User（`~/.claude.json`）/ Managed（行 24955–24996）
- **制約・限界**:
  - MCP tool 出力は **default 10,000 トークン警告、`MAX_MCP_OUTPUT_TOKENS` で拡張可**（行 24884）。
  - Tool description と server instructions は **各 2KB で truncate**（行 25647）。
  - 接続失敗時は exponential backoff で 5 回まで自動再接続（行 24865–24869）。stdio サーバーは再接続なし。
  - ツール接続を信頼できるサーバーに限定する責任はユーザー側（行 24741 Warning, prompt injection）。
- **代替機能との位置関係**: 「MCP vs Skill」の公式比較（行 16867–16884）あり。要旨: **MCP は接続性、Skill は使い方の知識**。本調査では「ローカル RAG = MCP server で公開」「使い方ガイド = Skill」の組み合わせが推奨パターンとなる。

### 2.5 Hook / Slash command 系（preprocessing による context 削減）

#### 機能名: Hooks（特に PreToolUse / UserPromptSubmit / InstructionsLoaded）

- **公式ドキュメント上の位置**: 行 20336–20620（hook events 定義）、20480–20513（InstructionsLoaded）
- **概要**: ライフサイクルイベントで実行されるコマンド / HTTP / MCP tool / prompt / subagent ハンドラ。
- **RAG 観点でのカバー範囲**:
  - **「Claude が大量データを読む前に preprocessing して必要部分だけ渡す」用途で公式が推奨**（行 13419–13468）:
    > "Custom hooks can preprocess data before Claude sees it. Instead of Claude reading a 10,000-line log file to find errors, a hook can grep for ERROR and return only matching lines, reducing context from tens of thousands of tokens to hundreds."
  - **UserPromptSubmit hook** で `additionalContext` JSON フィールドを返すと、ユーザープロンプト送信時に追加コンテキストを注入できる（行 20515–20573）。これを使えば「ユーザーが何か聞いた瞬間に外部 RAG に問い合わせて結果を context に追加」が実装可能。
  - **InstructionsLoaded hook**（行 20480–20513）: CLAUDE.md / rules ファイルがロードされたタイミングで発火。observability 用で blocking 不可だが、load 追跡用に有用。
  - **SessionStart hook** で `additionalContext` を返すと session 開始時に context 注入可能（行 20370–20388）。
- **トリガー方式**: ライフサイクルイベント自動発火
- **スコープ**: User / Project / Managed / Plugin（plugin hook は managed の `allowManagedHooksOnly` 制約下）
- **制約・限界**:
  - UserPromptSubmit hook の default timeout は **30 秒**（他の hook は 600 秒）（行 20521）。
  - hook 出力（stdout や `additionalContext`）はそのままコンテキストに乗るため、大きな出力は逆効果。

#### 機能名: `fileSuggestion` setting（カスタム `@` ファイル検索）

- **公式ドキュメント上の位置**: 行 34408–34442
- **概要**: `@`-mention 時のファイル autocomplete を **カスタムスクリプトに委譲**できる設定。
- **RAG 観点でのカバー範囲**: monorepo 等で「事前構築インデックス」を活用可能と公式が明記:
  > "The built-in file suggestion uses fast filesystem traversal, but large monorepos may benefit from project-specific indexing such as a pre-built file index or custom tooling."
  - 標準は filesystem traversal。`fileSuggestion.command` を指定すると JSON で `{"query": "..."}` を stdin 受信し、改行区切りパスを stdout 返却するスクリプトが呼ばれる。
  - **本調査のローカル RAG が「ファイルパス検索」も提供するなら、ここに統合する設計が可能**。
- **トリガー方式**: ユーザーが `@` を入力した瞬間
- **スコープ**: settings 経由（user / project / local / managed）
- **制約・限界**: 返却パスは **最大 15 件**（行 34427）。

### 2.6 取得ツール系（WebFetch / Glob / Grep / Read 等）

#### `Read` ツール（行 39503–39516）

- 絶対パス指定で読み込み。サイズ閾値超過時はエラー → `offset` / `limit` でレンジ読み込みを要求。PDF は 10 ページ超なら `pages` パラメータ必須。
- RAG 観点: 直接の RAG 機能ではないが、subagent と組み合わせれば「subagent が大量 Read → 要約 → 親に返却」のパターンで擬似 RAG として機能。

#### `Glob` ツール（行 39394–39404）

- ファイル名パターンマッチ、結果は **最大 100 ファイル**、modification time ソート。
- `.gitignore` は default で **無視しない**（Grep と異なる）。
- RAG 観点: ファイル特定の高速プリミティブ。

#### `Grep` ツール（行 39406–39420）

- ripgrep ベース、`files_with_matches` / `content` / `count` の 3 出力モード。
- `glob` / `type` で範囲指定、`multiline` 対応。
- `.gitignore` を **尊重する**（gitignore されたファイルはスキップ）。
- RAG 観点: 公式に「local Grep は cost ほぼゼロ」というニュアンスが context-window / cost ページに頻出（例: 行 13418–13423）。本調査でも「Claude Code 公式 docs ローカル DL + Grep」が RAG の繋ぎ戦略として暫定運用されている。

#### `WebFetch` ツール（行 39517–39532）

- URL + プロンプトを取り、内部の **small fast model で要約**してから Claude に返す。
- **lossy by design**: 抽出プロンプト次第で情報が落ちる。生 HTML が欲しい場合は `mcp__fetch__fetch` か `curl` 推奨。
- 15 分キャッシュ。HTTP → HTTPS 自動アップグレード。
- RAG 観点: 外部 web の RAG 的取得には使えるが、ローカル RAG の趣旨とは外れる。

#### `WebSearch` ツール（行 39534–39546）

- Anthropic web search backend に対する query。タイトル + URL のみ返す（ページ本文は返さず）。`WebFetch` と組み合わせて使う。
- 1 call 内で最大 8 回 backend 検索を行うことがある。
- バックエンドは固定。他プロバイダで検索したい場合は **MCP server を追加せよ** と公式記載（行 39540）。

#### `Agent` ツール（subagent spawn、行 39342–39361）

- 2.3 節参照。最重要の RAG 的活用機構。

#### `ListMcpResourcesTool` / `ReadMcpResourceTool`

- MCP リソースの列挙と取得（行 39286, 39293）。MCP 経由 RAG の中核 API。

#### `ToolSearch` ツール（行 39307, 25627–25705）

- MCP tool search の internal API。**MCP ツール群に対する RAG 的アクセス**を実現するための公式ツール。

## 最重要発見トップ 3（メインセッション優先確認推奨）

1. **Claude Code 自体には「ベクトル化 / 埋め込み / セマンティック検索」と呼ばれる機能は存在しない。**公式 glossary（行 18563）が RAG を Claude プラットフォーム層の概念として明示的に切り離している。したがって本調査の「ローカル RAG」は **Claude Code の外側に構築し、MCP server として接続する** のが公式アーキテクチャ上の素直な選択となる（MCP の項参照: 行 24717–25745）。

2. **Skill / Subagent / MCP Tool Search の 3 つが、Claude Code 内蔵の "RAG 的" progressive disclosure 機構である。** 公式が "progressive disclosure" 用語を使っているのは Skill のみ（行 30748）だが、思想は全 3 機能に共通: ①一覧（description / tool name / agent description）だけ常時保持 → ②必要時にフル内容ロード。とくに **Subagent（特に `Explore`）は「大量ファイルを読んで要約だけ親に返す」用途で最も RAG ニーズに直接刺さる標準機構**（行 37651–37692, 38329–38350）。本調査の「ローカル RAG なし版」のベースライン構成として、これらの組み合わせで Anthropic 純正の到達点を測定する価値が高い。

3. **`fileSuggestion` setting（行 34408–34442）と UserPromptSubmit hook の `additionalContext`（行 20540–20573）が、外部 RAG を Claude Code に "差し込む" 公式拡張ポイントである。** MCP 以外にも、`@`-mention の autocomplete をカスタムスクリプトに委譲する `fileSuggestion`、ユーザープロンプト発火時に外部システムから context 注入する UserPromptSubmit hook という 2 つの "差し込み口" が用意されている。本調査で構築するローカル RAG の Claude Code 連携設計時には、MCP server 化以外にこれら 2 経路も比較検討する価値がある（とくに「ファイルパス検索」用途は MCP より `fileSuggestion` の方が自然）。
