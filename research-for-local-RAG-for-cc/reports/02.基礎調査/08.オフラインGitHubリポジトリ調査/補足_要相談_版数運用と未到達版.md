## 1. 議論の対象範囲（A-5 の整理）

### 1.1 元の検討事項

論理整合性テンプレートの末尾に置かれている「変更履歴」表は、現状以下の 3 行を雛型として予め用意しています:

```markdown
|版|日付|内容|
|--|--|--|
|0.8|{{YYYY-MM-DD}}|初版作成（{{作成者}}）|
|0.9|{{YYYY-MM-DD}}|レビューイFB取り込み(第1回)（{{取り込み実施者}}）|
|1.0|{{YYYY-MM-DD}}|作業指示者指摘取り込み（{{取り込み実施者}}）|
```

副作用として、**作業指示者レビューが不要な軽量成果物**（補足調査など）では、0.9 / 1.0 行が永遠に空のまま残るケースがあります。

### 1.2 元ドキュメントで提示された改善提案

| 案 | 内容 |
|---|---|
| 改善提案 A | 雛型は 0.8 行のみとし、フェーズ到達時に行追加（柔軟） |
| 改善提案 B | 現状維持し、未到達行は「（未到達）」等で明示（フロー可視化重視） |

### 1.3 ユーザーが追加で提示した案

検討項目一覧票 A-5 の判断コメント欄で、以下の 2 案が提示されています:

#### 案 X: 最終承認者レビュー = 1.0 ベース（初版を逆算）

> もともと版数 1.0 は、その成果物の最終承認者のレビューが完了したことを意味する数字であり、そこまでの間に何回他のレビューステップがあるかの逆算で初版のバージョンを決めればよいと考えています。
>
> よって作業指示者レビュー不要なケースでは、クロスレビューアによるレビュー指摘すべてが何らか対応されたタイミングで 1.0 となり、つまり、そのフローにおけるクロスレビューアによる報告書作成時の初版バージョンは 0.9 となります。

#### 案 Y: 改訂履歴スキップ表記

> しかし、これを Claude 向けのルールとするには Claude にとっては無駄にややこしいだけの可能性もあり、その場合は改訂履歴に、フロー上不要なレビューに相当する版数に「フロー上不要なためスキップ」といったコメントを記載するというルールにするのもアリかと考えます。

## 2. 各案の比較整理

### 2.1 案 X（最終承認者レビュー = 1.0 ベース）

#### 動作イメージ

| ケース | 初版 | 中間版 | 最終版 |
|---|---|---|---|
| クロスレビュー + 作業指示者レビュー | 0.8 | 0.9（FB取り込み） | 1.0（作業指示者指摘取り込み） |
| クロスレビューのみ（作業指示者レビュー不要） | 0.9 | — | 1.0（クロスレビュー指摘対応完了） |
| セルフレビューのみ（クロスレビューも不要） | 1.0（？） | — | 1.0（？） |

#### メリット
1. **「1.0 = 最終承認状態」が成果物横断で統一される**: どの成果物でも、1.0 が出れば「すべての必須レビューが完了した」と読める
2. **未到達版が雛型に発生しない**: 軽量成果物では 0.9 が初版として登場し、空の 0.9/1.0 行が雛型に残らない

#### デメリット
1. **成果物ごとに「初版番号」が異なる**: Claude が「この成果物の初版はいくつになるか」を判断する必要があり、判断ロジックが暗黙化する
2. **初版判断のロジックが複雑**: 「作業指示者レビューが必須か」「クロスレビューが必須か」の組み合わせで初版が変わる。Claude が成果物の性質を正確に把握する必要がある
3. **件数推移表のフォーマットが揺れる**: 初版が 0.8 か 0.9 か 1.0 かで、推移表の列が変わる。Claude が雛型を都度調整する必要がある
4. **後付けで「やっぱり作業指示者レビューを追加したい」場合の対応コスト**: 初版 0.9 の成果物に作業指示者レビューを追加するとなると、版数体系を遡及的に修正する必要が出る可能性

### 2.2 案 Y（改訂履歴スキップ表記）

#### 動作イメージ

すべての成果物で雛型の変更履歴を一律「0.8 / 0.9 / 1.0」の 3 行とし、フロー上不要な版数には「フロー上不要なためスキップ」と注記する。

例（作業指示者レビュー不要なケース）:
```markdown
| 版 | 日付 | 内容 |
|---|---|---|
| 0.8 | 2026-05-04 | 初版作成（Claude Opus 4.7） |
| 0.9 | 2026-05-04 | レビューイFB取り込み（Claude Opus 4.7） |
| 1.0 | （フロー上不要なためスキップ） | 作業指示者レビュー不要のため |
```

または件数推移表側でも「該当版なし」を明示:
```markdown
| ラベル | 0.8 | 0.9 | 1.0 |
|---|---|---|---|
| CRITICAL | 1 | 0 | （スキップ） |
| IMPORTANT | 2 | 0 | （スキップ） |
| SUGGESTION | 0 | 0 | （スキップ） |
| POSITIVE | 1 | 1 | （スキップ） |
```

#### メリット
1. **雛型が一律**: どの成果物でも同じ雛型を使えるため、Claude のパターン学習が容易
2. **件数推移表のフォーマット統一性**: 全成果物で同じ列構造の推移表になり、読み手の予測可能性が高い
3. **「スキップ」明示の意図が伝わる**: 「忘れた」「未到達」「構造的に不要」の区別が改訂履歴に残る
4. **将来的な拡張性**: 軽量成果物に作業指示者レビューを追加する場合、雛型変更不要で「スキップ」を「（実施日・内容）」に書き換えるだけ

#### デメリット
1. **雛型に空または「スキップ」行が残る**: 視覚的な「ノイズ」が発生
2. **「フロー上不要なためスキップ」の判断責任**: 「なぜスキップなのか」を Claude が判断する必要がある（ただしこれは案 X でも同じ判断が必要）

## 3. Claude の推奨

### 3.1 推奨案

**案 Y（改訂履歴スキップ表記）を推奨**。

### 3.2 推奨理由

1. **Claude にとっての判断負荷が低い**:
   - 案 X では「成果物ごとの初版番号判断」が必要だが、案 Y では雛型を一律で使えるため、Claude が間違いにくい
   - 「フロー上不要のためスキップ」と書く判断は、案 X の「初版を 0.8/0.9/1.0 のどれにするか」よりも単純（「該当版が必要か否か」の二値判断）

2. **件数推移表のフォーマット統一性**:
   - 案 X では推移表の列数が成果物ごとに変わる
   - 案 Y では常に 3 列で統一され、空の列には「スキップ」と明記する
   - レビュー報告書を機械的に集約・分析する場合（例: 全プロジェクトの指摘件数推移を比較）にも、フォーマット統一の方が扱いやすい

3. **将来的な拡張性**:
   - 案 Y は「後から作業指示者レビューを追加する」場合、版数 1.0 の行を「スキップ」から「（実施日・内容）」に書き換えるだけで対応可能
   - 案 X では既に出た版数を遡及的に修正する必要が出る可能性

4. **意図の可視化**:
   - 「スキップ」と明記することで、「なぜこの版が無いのか」の理由が記録に残る
   - 軽量成果物の運用ルールを変更（例: 作業指示者レビューを必須化）した場合、過去の「スキップ」記録から影響範囲が把握しやすい

### 3.3 ハイブリッド案（参考）

案 Y の派生として、以下の運用も可能:

#### 案 Y'（雛型は案 Y、ただし「フロー上不要」が確定している場合は雛型から該当行を削除可）

- 雛型は案 Y と同じ 3 行
- 成果物作成時、「この成果物は作業指示者レビューが構造的に不要」と確定している場合のみ、該当行を雛型から削除してよい
- 「未到達」の行は残す（後で到達する可能性があるため「スキップ」とは書かない）

これは案 Y のメリットを維持しつつ、視覚的ノイズを抑える折衷案。ただし、削除判断の責任が Claude に発生するため、案 Y そのものの方がシンプルです。

## 4. Claude の確認事項

### Q1. 案 Y 採用時の運用ルール記載先
案 Y を採用する場合、運用ルール（「スキップ表記の使い方」「判断基準」）はどこに記載するのが妥当か。`§1（テンプレート整合性とREADME詳細化）` で整理した階層構造に沿うと、`.claude/templates/cross-review/README.md` の「§ 版数管理」が適切と考えますが、合っているか。

### Q2. 「未到達」と「スキップ」の使い分け
- **未到達**: 「該当フェーズが将来発生する可能性があるが、まだ到達していない」（例: 0.9 版作成中の時点での 1.0 行）
- **スキップ**: 「該当フェーズが構造的に発生しない」（例: 軽量成果物の 1.0 行 = 作業指示者レビュー不要）

この区別を明確化する想定でよいか。

### Q3. 件数推移表でのスキップ表記
件数推移表（および §3.1.1 で提案した観点 × 版数の拡張表）で「スキップ」行をどう表現するか:
- A（推奨）: 「（スキップ）」と各セルに記載
- B: 列全体を削除（雛型から取り除く）
- C: 列ヘッダに「1.0（スキップ）」と表記し、各セルは空欄

Claude の推奨は A（明示的に各セルに記載することで「忘れた」と区別しやすい）。

> 案 Y を採用する場合、運用ルール（「スキップ表記の使い方」「判断基準」）はどこに記載するのが妥当か。`§1（テンプレート整合性とREADME詳細化）` で整理した階層構造に沿うと、`.claude/templates/cross-review/README.md` の「§ 版数管理」が適切と考えますが、合っているか。

> ### Q2. 「未到達」と「スキップ」の使い分け
