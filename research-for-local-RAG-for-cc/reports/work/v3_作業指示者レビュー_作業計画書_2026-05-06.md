## CRITICAL

### U-C1: 「成功条件 3」の実測値が指す具体的な指標が §0 単独で読み取れない

**該当箇所**:
- [§0.3 成功条件](v3_作業計画書_2026-05-06.md#03-成功条件プロジェクト完了の定義) 項 3 「評価指標（§5.5 05.有効性検証）に対する実測値が記録されている」
- 関連: [§5.5.4 評価指標](v3_作業計画書_2026-05-06.md#554-評価指標ドラフト最終確定は-05-01)

**観点**: 1 意思決定材料の十分性 / 7 押し戻し条件

**指摘内容**:

承認者は §0 単独で承認可否を判断できる構成と謳われている（[§0 冒頭](v3_作業計画書_2026-05-06.md#0-冒頭サマリ承認判断のための要点)）が、§0.3 成功条件の「評価指標に対する実測値」が **何の指標で、どの水準に達したら成功なのか** が §0 では一切読み取れない。リンク先 §5.5.4 を辿っても **指標は 8 項目列挙されているが、合格水準（閾値）が示されていない**（最終確定は 05-01 で行うとされる）。

承認者として「成功条件をすべて満たしたら成功」と宣言された以上、**条件の中身が不確定なまま承認するのは「白紙委任」になる**。「実測値が記録されている」だけなら、どんな悪い値でも条件を満たすことになり、成功条件として機能していない。

**期待する対応**:

以下のいずれかで対応してほしい:

1. §0.3 で「成功条件 3 は『記録の有無』であり、合否水準の確定は 03-02 / 05-01 の TBD4 で別途承認を経る」旨を明記し、**承認権限が分割されている事実** を承認時に明示する
2. または成功条件 3 を「評価指標に対する **暫定合格水準（03-02 / 05-01 で確定予定）** の実測値が記録されている」と書き換え、合格水準確定が別承認ポイントになることを §0 で明示する
3. §11 見直しトリガーに「TBD4（合格水準）確定時に作業指示者再承認」を追記する

要するに、現状の §0.3 は「成功 = 記録すれば成功」という弱い条件になっているため、押し戻し可能な閾値を承認時に確認できる構成に変える必要がある。

### U-C2: 「打ち切り条件 4（コスト 3 倍超）」の基準値（当初見積り）が計画書内に存在しない

**該当箇所**:
- [§0.4 打ち切り条件](v3_作業計画書_2026-05-06.md#04-打ち切り条件プロジェクト中断の定義) 項 4 「想定外コスト（ストレージ・メモリ・実行時間）が当初見積りの 3 倍超」
- [§9.1 打ち切り条件](v3_作業計画書_2026-05-06.md#91-打ち切り条件再掲04-より) 項 4 同じ

**観点**: 7 押し戻し条件 / 1 意思決定材料の十分性

**指摘内容**:

打ち切り条件 4 は「**当初見積りの 3 倍超**」という基準値を前提としているが、計画書内のどこを探しても「当初見積り」の **具体値（ストレージ何 GB、メモリ何 GB、実行時間何分）が示されていない**。基準値が宙に浮いた打ち切り条件は、発動可否の判断が承認者にも担当 Agent にも行えない。

執筆ガイドライン §G2-6（データドリブン）にも反する。「当初見積り」が今後どこかで確定するなら、確定タイミングと確定責任者を明示すべき。

**期待する対応**:

以下のいずれかで対応してほしい:

1. §0.4 / §9.1 に「当初見積り」が **どのフェーズ（おそらく 03-02 設計時または 04 各検証着手時）で確定する想定か** を明記する
2. または「3 倍超」を「03-02 で確定する見積りに対する 3 倍」と書き換え、見積り確定が打ち切り条件発動の前提条件であることを示す
3. §11 見直しトリガーに「03-02 完了時に当初見積り確定 → §0.4 / §9.1 を実値で更新」を追記する

打ち切り条件は **承認者が「これなら止める」と納得できる具体値** が揃って初めて押し戻し条件として機能する。現状は「3 倍」という比率だけが残っており、機能していない。

### U-I1: H/TBD 追跡マトリクス（§3.3）の「-」の意味が読み取れない

**該当箇所**: [§3.3 H/TBD と検証タスクの追跡マトリクス](v3_作業計画書_2026-05-06.md#33-htbd-と検証タスクの追跡マトリクス)

**観点**: 5 認知負荷 / 1 意思決定材料の十分性

**指摘内容**:

マトリクスの各セルに「入力」「検証」「確定」「-」「暫定確定」「最終確定」の語が使われている。執筆者の意図は推測可能（「-」は無関係）だが、表内に **凡例が一切ない**。承認者として読むと:

- 「H2 / 02-01 = -」と「H2 / 04 = 検証」は読めるが、**マトリクス左上「H0 / 02-01 = 入力」と「H0 / 04 = 検証」と「H0 / 05 = 検証」で同じ仮説に対して 3 度何かが起きる流れ** が表だけでは追えない
- 「暫定確定」と「最終確定」の違いも凡例がないと初見で意味不明
- §3.3 の本文側に説明が無く、表の前後に脚注もない

承認者は「この表は意思決定材料として何を保証しているのか」を 1 分で読み解けない。執筆ガイドライン §G3-8（図表 self-contained）にも違反。

**期待する対応**:

§3.3 冒頭に 3〜5 行の凡例を追加してほしい。例:

> **表記凡例**:
> - **入力**: そのフェーズで H/TBD を確定させる前提情報を産出する
> - **検証**: 仮説の真偽を実測または分析で検証する
> - **確定**: TBD を文献調査または設計で確定する
> - **暫定確定 / 最終確定**: 暫定値を後続フェーズで上書き確定する 2 段階運用
> - **-**: 当該フェーズでは触れない

あるいは「入力 / 検証 / 確定」の 3 動詞が同じ行で混ざって意味を持つことを示す 1 文を追加するだけでも改善される。
