## 1. 執筆過程の所感

### 1.1 ガイドラインの適用しやすさ

| 観点 | 適用しやすさ | コメント |

### 1.2 困難だった観点（Top 3）

1. **G1-3 Diátaxis モード** — 計画書のような複数モード混在ドキュメントでは、章単位ですら単一モードに収まらず、機械的なモード判定が困難。実用上は「Reference 寄り（§2 前提・§3 仮説・§5 フェーズ計画）」「Explanation 寄り（§9 Devil's Advocate）」「Reference + How-to 混在（§5 各サブタスク完了条件）」のような大まかな自意識に留まった
2. **G3-2 全文「重み検査」** — 計画書という性質上、「削除可能だが残しておくと安心」な前提情報（例: §1.1 大前提）が複数あり、機械的に「No → 削除」とは判断しづらい。承認者の知識レベルに応じた濃淡判断が要る
3. **冒頭サマリ（§0）と本文（§1〜§5）の役割分担** — 「§0 で結論、§1〜§5 で詳細」という Minto 構造を取りつつ、Agent が §5 だけ読めば実行できる完結性も保つ必要がある。両立のため §0 を「承認判断用」、§1〜§5 を「実行・追跡用」と明示的に役割分割した

### 1.3 ガイドラインへの改善案

| # | 改善案 | 動機 |
|---|---|---|
| C1 | **G1-3 Diátaxis モードに「複数モード混在ドキュメントの扱い方」を追記** | 計画書・最終報告書のような複数モード混在ドキュメントでは「章ごとに単一モード」が崩れる。「節レベルでモードを意識」「混在を許容する場合は冒頭でモードを宣言」のようなガイダンスがあると実用的 |
| C2 | **G1-2 冒頭サマリに「読者別読み方ガイド」を追加** | 計画書では「承認者向け要約」と「実行 Agent 向け要約」のニーズが異なる。冒頭で「§0 のみで承認判断 / §5 が実行用」のような読み方ガイドを示す観点があると有用 |
| C3 | **G3-7 Devil's Advocate の「再反論深度」のガイダンス** | 「最強の反論」を書くと、執筆者として再反論したくなり、無限の議論に陥る。「1 段の反論まで書き、棄却根拠 or 残存リスクで打ち切る」運用を明示すると収束しやすい |
| C4 | **G2-3 パターン化構造に「テンプレート例」を提供** | サブタスク記述等で同一構造を採るとき、執筆者ごとにテンプレート設計が分かれる。ガイドラインに 1〜2 例（サブタスク用 / 検証対象用）を提示すると揺らぎが減る |
| C5 | **G3-2 重み検査に「保険文の扱い」を明記** | 「念のため書いておく前提」は削除候補だが、承認者層が広いと残す価値がある。「想定読者の最低知識レベルを基準に判断する」を明文化すると判断しやすい |
| C6 | **G3-5 Specificity の where に「計画書段階の扱い」を追記** | 計画書では「証拠（実測値）」がまだ存在しない。where が「先行インプット由来」「文献由来」となるケースの処理方針が明文化されると迷いが減る |
| C7 | **§4.1 計画書要件に「打ち切り条件の独立化」を明記** | 「成功条件」だけでなく「打ち切り条件」を必須化することで、承認時のリスク把握が明確になる。v3 では §0.4 / §9.1 で対応したがガイドライン要件には未明記 |
