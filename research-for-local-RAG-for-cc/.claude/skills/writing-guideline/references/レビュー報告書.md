# レビュー報告書 固有観点

クロスレビュー報告書・作業指示者レビュー報告書執筆時に共通観点（`common/01〜03`）に加えて適用する追加観点。

## 1. テンプレートに従う

レビュー報告書は `.claude/skills/cross-review/templates/` 配下のテンプレート（論理整合性観点・実用性観点・作業指示者+人間読み手観点）に従う。テンプレ運用詳細は `.claude/skills/cross-review/references/runtime-rules.md`（クロスレビュー Skill から参照される）。

## 2. 構造設計フェーズの追加観点

### 2.1 想定読者は事前知識を持つ前提

レビュー報告書の想定読者（執筆者・他レビューア・作業指示者）は、レビュー対象成果物の前提知識を既に持っている。G1-1 想定読者像では「**事前知識を持つ前提**」と宣言し、**前提知識の明示は最小限で良い**。

> **理由**: レビュー報告書は完成版の品質指摘集なので、前提知識の説明に紙幅を割くと指摘そのものが薄まる。読者の前提を信頼することで、指摘の情報密度を上げる。

## 3. 執筆中フェーズの追加観点

### 3.1 内外参照の相互リンク化が特に重要

G1-4 内外参照の相互リンク化は、レビュー報告書では **指摘ごとの該当箇所への直接リンク** として特に重要。レビュー対象成果物の該当行・該当節へのリンクを各指摘エントリに必ず付ける。

```markdown
良い例:
### I3. ハマりどころ.md との状態同期不整合
- **該当箇所**: [§9.1 サブタスク 07 残課題](../report.md#91-サブタスク-07-残課題)
- **問題**: 「未追記」記述が ハマりどころ.md 現状と乖離

悪い例:
### I3. ハマりどころ.md との状態同期不整合
- §9.1 で記述揺れあり（リンクなし）
```

> **理由**: レビュー指摘は該当箇所を確認してから対応判断する。手動辿りはレビュー収束の最大ボトルネックの一つ。リンク化により対応判断時間が大幅に短縮できる。
