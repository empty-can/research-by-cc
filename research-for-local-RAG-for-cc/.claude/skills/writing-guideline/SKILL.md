# 執筆ガイドライン

ドキュメント執筆段階で予防的に適用すべき品質観点集。クロスレビューテンプレ（`.claude/templates/cross-review/`）と対をなし、執筆段階で吸収しきれなかった指摘がレビュー段階で発見される双方向の品質ループを構築する。

## 1. 適用範囲とタイミング

ドキュメント執筆は以下の 3 フェーズで進行する。各フェーズで参照する観点は、共通観点（`references/common/`）+ 種別固有観点（`references/<種別>.md`）の組み合わせ。

| 段階 | 参照すべきファイル |
|---|---|
| 構造設計（章立て決定） | [common/01_構造設計編.md](references/common/01_構造設計編.md) + 該当する種別ファイル |
| 執筆中 | [common/02_執筆中編.md](references/common/02_執筆中編.md) + 該当する種別ファイル |
| 完成直前のセルフチェック | [common/03_完成前セルフチェック編.md](references/common/03_完成前セルフチェック編.md) + 該当する種別ファイル |
| 完成後 | [執筆者見解レポート.md](references/執筆者見解レポート.md) を別ファイルとして作成 |

### 種別固有観点（種別ファイル）

| ドキュメント種別 | 参照ファイル |
|---|---|
| 計画書 | [references/計画書.md](references/計画書.md) |
| 調査報告書（フェーズ報告書・統合報告書） | [references/調査報告書.md](references/調査報告書.md) |
| レビュー報告書（クロスレビュー・作業指示者レビュー） | [references/レビュー報告書.md](references/レビュー報告書.md) |
| 改訂提案・運用考察ドキュメント | [references/改訂提案.md](references/改訂提案.md) |

## 2. クロスレビュー観点との関係

本ガイドラインは執筆段階の予防チェックリスト、`.claude/templates/cross-review/` 配下のレビュー観点は完成版に対する事後チェック。両者の重複は意図的で、執筆段階で吸収しきれなかった指摘がレビュー段階で発見されることを前提とした双方向品質ループを構築する。

### Reader-AI フレッシュ読み観点の適用判断

クロスレビューの「Reader-AI フレッシュ読みテスト」観点は、対象ドキュメントの **想定読者の前提知識レベル** に応じて適用要否を判断する。

| 想定読者の前提 | フレッシュ読み観点の扱い | 判断根拠 |
|---|---|---|
| **事前文脈なし**（外部公開資料・新規参加者向け資料・初出ドキュメント等） | **必須適用** | フレッシュな読者の理解可否を直接検証する以外に検出が難しい |
| **事前文脈あり**（内部継続作業の計画書・統合報告書・特定読者向けレビュー報告書等） | **除外可** | 他観点（前提知識明示・冗長矛盾チェック・Devil's Advocate 等）で代替検出可能、Reader Agent 起動コスト削減のメリットあり |

判断基準: G1-1「想定読者像の事前宣言」で「事前文脈なし、本ファイルのみ参照」と宣言した場合は **必須適用**。

> **除外時の留意点**: 他観点で代替検出可能だが、完全代替には至らない。Reader-AI 固有の検出能力（執筆者の暗黙前提・指示語の連鎖・複数解釈可能な術語等の可読性問題）は他観点では完全には肩代わりできないため、想定読者像を慎重に判断すること。

## 4. ガイドライン違反時の扱い

執筆中にガイドライン違反を発見した場合、その場で修正を原則とする。修正困難な場合（構造に深く関わる等）は、ドキュメント末尾の「申し送り事項」に記載し、後続のレビューで対応判断を仰ぐ。

## 5. メンテナンス情報

本ガイドラインの整備履歴・関連バックログ・改善案の提案ルートは [references/メンテナンス資料.md](references/メンテナンス資料.md) に集約。執筆作業中の読み込みは不要。
