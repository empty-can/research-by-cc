# Skill 作成ガイドライン兼セルフレビュー観点

新規 Skill の作成時、および既存 Skill の編集時に自動ロードされる path-scoped rule。Skill の責務分離・記述原則・セルフレビュー観点を集約する。

## 1. 責務分離の3層構造

Skill は以下の3層に責務を分けて構成する。1層に複数の責務を載せない。

| 層 | ファイル | 役割 | 読み手 |
|---|---|---|---|
| **利用者向け** | `README.md` | Skill 概要 / 利用方法 / 利用シーン / 注意事項 | 作業者・将来の Skill 編集者 |
| **Claude 向け** | `SKILL.md` | Claude が主体で実施する作業のフロー | Claude（Skill 実行時にロード） |
| **処理本体** | スクリプト（`.sh` / `.ps1` 等） | Skill の実処理（ファイル操作・パス解決等） | 機械実行 |

**配置原則**:

- 機械的に実行可能な処理は **原則すべてスクリプトに実装する**。SKILL.md には「どのスクリプトを実行するか」だけを書く
- 利用者向け情報（仕組みの説明・利用シーン・運用上の注意）は **README.md にのみ書く**。SKILL.md には書かない
- README.md は Claude が自動ロードしないため、Claude のコンテキスト消費に影響しない

## 2. SKILL.md 記述の原則

### 2.1 含めてよい内容（3カテゴリ）

| カテゴリ | 内容 |
|---|---|
| **(a) Skill 仕様上の必須要素** | frontmatter（`description` / `allowed-tools` / `name` / `argument-hint` 等） |
| **(b) Claude が主体で実施する作業のフロー** | 実行する Tool（スクリプト・内蔵 Tool・Agent 委任）、実行順序、結果に対するアクション |
| **(c) スクリプト化できずメタ的・抽象的な処理** | ユーザーへの確認・対話、判断分岐、エラー時の応答テンプレ、Tool 実行前のデータ整理、複数 Agent のオーケストレーション等 |

### 2.2 含めるべきでない内容

| 項目 | 移動先 |
|---|---|
| Skill 概要・背景・利用シーン | README.md |
| 利用者向けの注意事項 | README.md |
| 既に CLAUDE.md やルールに記載済みの方針の再掲 | （削除し参照のみ） |
| 抽象動詞による作業指示（「処理する」「準備する」等の解釈余地のあるもの） | 具体表現に置換 |

### 2.3 端的かつ曖昧性を排除した表現

| NG（解釈余地あり） | OK（曖昧性なし） |
|---|---|
| 「内容に基づいて作業を開始する」 | 「読み込んだ内容を作業者からの新規メッセージとして処理する」 |
| 「ファイルを確認する」 | 「Read tool で `<path>` を読み込む」 |
| 「適切に処理する」 | 「終了コードが 0 の場合は X、非ゼロの場合は Y」 |
| 「内容を見なして判断する」 | 具体的な判断条件を明示する |

**原則**:
- 命令形を使う（「実行する」「読み込む」）
- Tool 名・コマンド・パスを **明示** する（Claude に「どの Tool を使うか」を考えさせない）
- 判定は数値・終了コード・特定文字列等で **決定論的に** 書く

## 3. allowed-tools の絞り込み方針

### 3.1 厳密に列挙する原則

`allowed-tools` は **想定される最小集合に絞る**。広い `Bash` や `*` を避ける。

| 例 | 評価 |
|---|---|
| `Bash` | × 任意の Bash コマンドが実行可能で範囲が広すぎる |
| `Bash(.claude/skills/<name>/<script>.sh)` | ◎ 当該スクリプトのみ |
| `Bash(cat -n *)` | ○ cat -n の引数限定 |
| `Read` | ○ 読み取り全般を許可（Skill が複数ファイルを読む場合） |
| `Read, Write` | ○ ファイル編集系 Skill |

### 3.2 典型パターン

| Skill 性質 | allowed-tools 例 |
|---|---|
| スクリプト1本実行 + 結果読み込み | `Bash(<script_path>), Bash(cat -n *)` |
| 複数ファイル参照 | `Read, Glob, Grep` |
| ファイル編集系 | `Read, Write, Edit, Bash(ls:*)` |
| Agent 委任系 | `Agent(<subagent_type>), Read` |

## 4. 思考時間短縮の観点

Claude が Skill 実行時に思考時間を要する原因は、ほぼ「SKILL.md の解釈余地」に集約される。以下の対策を講じる:

| 思考誘発要因 | 対策 |
|---|---|
| 「これは実行指示か、補足か」を判別する記述 | 利用者向け説明を SKILL.md から削除（README.md へ移動） |
| 抽象動詞（処理する・確認する・準備する・見なす） | 具体的な Tool 名・コマンド・判定条件に置換 |
| 場合分けの詳細解説 | 終了コード等の単純判定に簡素化 |
| ルール・方針の再掲 | スクリプトに完全委譲 / 参照のみに留める |
| `allowed-tools` が広い | 最小集合に絞り込み Claude の Tool 選択肢を狭める |

## 5. セルフレビュー観点チェックリスト

新規作成・編集完了時に以下を確認する。

### 5.1 構成チェック
- [ ] 責務が3層（README.md / SKILL.md / スクリプト）に分離されているか
- [ ] スクリプトに実装可能な処理が SKILL.md に書かれていないか
- [ ] 利用者向け情報が SKILL.md に混入していないか

### 5.2 SKILL.md 内容チェック
- [ ] frontmatter に必須項目（`description` / `allowed-tools`）が記載されているか
- [ ] 含めてよい内容（§2.1 の 3 カテゴリ）に限定されているか
- [ ] 抽象動詞・解釈余地のある表現を排除できているか
- [ ] Tool 名・コマンド・パスが明示されているか
- [ ] 判定が決定論的（終了コード等）になっているか

### 5.3 allowed-tools チェック
- [ ] 想定される最小集合に絞れているか
- [ ] Bash の引数パターンが具体的か（`Bash` 単独で済ませていないか）

### 5.4 動作チェック
- [ ] スクリプトを単独実行して期待通りの標準出力・終了コードを返すか
- [ ] エラー系（ファイル不在等）の挙動が想定通りか

## 6. 端的記述で陥りがちな注意事項

「端的に記述すること」を優先する余り、以下を **省略しないよう注意** する:

### 6.1 必須要素の省略リスク

| 省略しがちな項目 | 省略の影響 |
|---|---|
| `allowed-tools` frontmatter | Claude が想定外の Tool を選択する可能性 |
| エラー時の応答テンプレ | エラー時に Claude が独自の応答文を生成し、毎回内容が揺らぐ |
| 引数の有無・形式 | 引数を取る Skill で「引数なしで呼ばれた時の挙動」を Claude が判断することになる |
| 順序の明示（番号付き手順） | 並行実行か順次実行かを Claude が判断することになる |

### 6.2 判断基準

「端的さ」と「必要情報の網羅性」が衝突する場合:

- **Claude の判断を介さず決定論的に動かしたい部分**: 必要情報を網羅して書く（端的さより明確さ優先）
- **本質的に Claude の判断が必要な部分**（例: ユーザー入力に対する応答内容）: 端的に書いて Claude に任せる

### 6.3 セルフレビュー時の追加質問

§5 のチェック後、以下も自問する:

- 「この記述で **Claude が判断を要する箇所** はどこか？」を列挙する
- 列挙された判断箇所が「本質的に Claude の判断が必要な部分」か「決定論化できる部分」かを区別する
- 後者なら追加情報を書き足す
