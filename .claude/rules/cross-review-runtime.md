# クロスレビュー実施時の運用ルール（v3.0α）

レビュー報告書（`**/レビュー/**/*.md`）を読み書きする際、またはクロスレビューテンプレート（`.claude/templates/cross-review/*.md`）を編集する際に自動ロードされる詳細運用ルール。

> 基本概要（テンプレート 3 種の役割・使い方・指摘ラベル定義・態度区分等）は `.claude/templates/cross-review/README.md` を参照。本ファイルはレビュー実施時の **詳細運用仕様** に絞る。
>
> **v3.0α 暫定運用中**: L3 該当項目（指摘記載内容フォーマット移行・除外基準運用詳細・件数表セクション再構成）は運用しながら詰めて v3.1 で正式化。既存資産（過去成果物）は機械的置換せず、新規執筆ドキュメントから本ルールを適用する。

## セルフレビュー運用ルール（H4 該当）

レビューア・レビューイのセルフレビューは **前半フェーズ（新規 NG 検出）と後半フェーズ（誤検知チェック）を明確に分離** して実施する。

### レビューアセルフレビュー（フェーズ分離あり）

- **前半（新規 NG 検出）**: 上限 **5 回**（モデル共通）。終了条件 = 直近の試行で新規 NG 検出ゼロ。CRITICAL 候補が含まれている間は上限なし
- **後半（誤検知チェック）**: 上限 **Opus 3 回 / Sonnet 4 回**（暫定、v3.1 で 3 回統一目指す）。終了条件 = 直近の試行で誤検知判定ゼロ。CRITICAL 候補が誤検知判定で全て外れた時点で通常上限に切り戻し
- **観点（前半）**: 各観点に新規指摘候補があるか / 典拠は明確か / 重複・冗長指摘がないか
- **観点（後半）**: 事実認定として正しいか / ラベル選定が適切か（CRITICAL 過剰計上なし）/ 典拠ベース反論で覆る指摘がないか

### レビューイセルフレビュー（フェーズ分離なし）

- **上限**: **3 巡**（モデル共通）。Round 4/5 差戻しリスク回避を優先
- **観点**: 立場表明が全件完了 / 防衛的記述になっていないか（典拠ベース反論か）/ 補正情報の十分性

### レビューア再対応（Round 3）セルフレビュー

- **上限**: なし（取り込み後文書整合性確認は収束が確実なため打ち切り理由なし）
- **観点**: 取り込み後の文書整合性 / 取り下げ・重要度変更の判断根拠の明確性 / 件数表とレビューア確認セクションの連動

### レビューイ上限見直し時のチェック観点

(1) Round 4/5 発生頻度（5 回中 20% 超で見直し）/ (2) 主目的別カウント（立場判定・防衛的記述チェック・補正情報十分性確認）/ (3) 対象成果物の性質（規模・関連資産分散）

## レビューア確認セクションの仕様（B1 該当、L3 暫定仕様）

各指摘エントリ内、レビューイ回答の直後にレビューア確認セクションを追加する。

### 配置位置

- 「レビューイからの回答・見解・補足（問題点）」直下に「レビューア確認: 問題点」
- 「レビューイからの見解・指摘・補足（修正案）」直下に「レビューア確認: 修正案」

### 確認セクションの記入項目

| 項目 | 内容 |
|---|---|
| **レビューア態度** | 受容 / 取り下げ / 重要度変更 / 再指摘 / 修正採用 |
| **理由** | レビューイ回答に対する判断根拠（典拠ベース） |
| **最終結論** | 受容: 元指摘確定 / 取り下げ: 撤回 / 重要度変更: 例 IMPORTANT → SUGGESTION / 再指摘: 0.9.1 発行 / 修正採用: 改変版で確定 |
| **収束ステータス** | 達成 / 1ラウンド継続 / 議論継続 |

### 態度区分の定義

- **受容**: レビューイの完全同意・部分同意を踏まえ元の指摘・修正案を確定
- **取り下げ**: 典拠ベース反論で事実誤認・前提取り違えと判明 → 撤回（件数表で「取り下げ累計」に計上）
- **重要度変更**: ラベル変更（IMPORTANT → SUGGESTION 等）。新ラベルで現役件数に計上、旧ラベルから除外
- **再指摘**: レビューイ反論を踏まえても問題が残ると判断 → 0.9.1 発行で再ラウンド
- **修正採用**: レビューイ提案を踏まえた改変版を採用

### 収束ステータスの判定基準（M2 該当）

| ステータス | 判定基準 |
|---|---|
| **達成** | 最終修正案が双方合意で確定し新規論点なし |
| **1ラウンド継続** | レビューイ追加案の採否判断にレビューア側で再検証が必要 |
| **議論継続** | 認識不一致が残る |

## 指摘記載ルール（F02-009 由来）

### 事実認定型 vs 表現改善型の区分

- **事実認定型**（「X は誤っている」「Y は不整合」）: 典拠（参照箇所）・誤りの認定根拠が必須
- **表現改善型**（「X の表現は曖昧」「Y は冗長」）: 改善後の具体例（修正案で明示）が必須

### 根拠記述要件

すべての指摘に **典拠** または **判断根拠** を記述。推測ベースの場合はその旨を明示（例: 「推測ですが」）。

### IMPORTANT / SUGGESTION 境界の補助基準（M3 該当）

- **本文全体を精読しなければ理解できない問題か**: Yes → IMPORTANT 寄り / No → SUGGESTION 寄り
- **サマリ表など本文を読まずに参照される箇所への影響があるか**: Yes → IMPORTANT 寄り / No → SUGGESTION 寄り

### 指摘エントリの観点フィールド（H3 該当）

各指摘の見出し直下に「**観点**: <観点名>」を 1 行追加（例: `**観点**: 論理整合性`）。

### 観点別サマリ表の振り分けルール（M6 該当）

1 指摘は **主観点に 1 件計上**。複数観点にまたがる場合は影響が大きい観点を主観点とし、副次観点はコメント注記。

## 判断依頼サマリの運用（A4・A5 該当、L3 暫定仕様）

### 記載フォーマット（A4）

優先度列は廃止し、**優先度ごとに見出しで区分** したサマリ表を作成する。

```markdown
##### CRITICAL（{現役件数} 件、判断依頼対象 {サマリ件数} 件）

| ID | タイトル | 差し戻しリスク | 態度表明 |
|---|---|---|---|
| ... | ... | ... | ... |
```

### 除外基準（A5、サマリ表に記載しない指摘）

- **除外基準 1**: 優先度が `IMPORTANT` 未満（= `SUGGESTION` 以下）
- **除外基準 2**: レビューイ完全同意 + レビューア受容のみで対応案受入の追認判断指摘

> 除外された指摘も本文中の指摘エントリには残す。サマリ表のみから除外。

### 判定タイミング・判定者

- **判定タイミング**: Round 3 完了後、判断依頼サマリ表を作成する時点
- **判定者**: レビューア（Round 3 担当者）
- **判定方法**: 除外基準 1 はラベルで機械的判定 / 除外基準 2 はレビューア確認セクションの態度を判定

### 「該当なし」の処理（M5 該当）

該当ラベルの指摘がない場合は、ラベル見出しを残し、表の代わりに「該当なし」を独立行で 1 行記載する。

## 件数表の運用ルール（M1 該当）

### バージョン列

- 0.8 版作成時点では 0.9 / 1.0 列は `<TBD>` で良い
- バージョン値の差分が無い場合は `同左` または `←` と記述（A7 該当、視覚的に把握しやすくするため）

### 取り下げ件数

- Round 3 で取り下げが発生した場合、件数表は **取り下げ後の現役件数** を記録
- 別途「取り下げ累計」行を追加して累計を記録（例: 0.8 版 10 件 → Round 3 で 1 件取り下げ → 0.9 版「9 件 + 取り下げ累計 1 件」）

### 重要度変更

- 新ラベルで現役件数に計上、旧ラベルから除外
- 「変動なし」と区別するため、変更履歴欄にも変更内容を記録

### 件数表のセクション分け（A8 該当、L3 暫定仕様）

バージョン単位ではなく **重要度単位** でセクション分け（CRITICAL 推移 / IMPORTANT 推移 / SUGGESTION 推移 / POSITIVE 推移）。CRITICAL や IMPORTANT といった重点的指摘の状況把握を容易にする。

## 用語の使い分け（v3.0α 反映）

| 用語 | 意味 |
|---|---|
| **差し戻し** | 承認権限者が承認時に「これでは GO できない」と判断し、レビュー成果物を執筆者に戻すこと（イベント・原因。観点 7「承認の差し戻し条件」由来） |
| **手戻り** | 上流工程の不備に起因して、後続工程の作業がやり直しになること（現象・結果） |
| **取り下げ** | レビューア指摘が事実誤認・前提取り違えで覆ること（Round 2/3 のレビューア確認セクションで処理） |

差し戻しは手戻りの代表的な原因の一つ。「差し戻し」を未然に防ぐことが「手戻り」の予防に直結する。
