# mechanism-builder 自律発案・再開プロトコル

`mechanism-builder` Skill の起動前フロー。A-1（自律検知）と A-3（保留タスク再開）を規定する。設計・実装フェーズ（B フロー）は `.claude/skills/mechanism-builder/SKILL.md` に委ねる。

## A-1. 自律検知フロー

### 検知トリガー

以下のいずれかを観測した場合に仕組み化の機会と判断する:

- 同じ手順・チェックリスト・プロンプトをやり取り内で 2〜3 回以上繰り返している
- 「これは CLAUDE.md に書くべき? Rule にすべき? Skill 化すべき?」と判断が揺れている
- Claude 自身が繰り返し実行しているパターンで、仕組み化による効率化が見込める

### Step 2: 提案と承認確認

実装に着手する前に、ユーザーへ提案する:

> 「**○○ の処理 / □□ の作業を、☆☆☆ という [Skill / Rule] として仕組み化することを提案します。**
> この提案について承認いただけますか？」

- **承認** → Step 3 へ
- **非承認** → 終了（現在の作業を継続）

### Step 3: タイミング確認

> 「**今すぐ着手しますか？それとも残タスクとして記録し、後ほど着手しますか？**」

- **今すぐ** → `.claude/skills/mechanism-builder/SKILL.md`（B フロー）へ進む
- **後ほど** → 提案内容をタスクとして記録し、メインタスクを再開する

---

## A-3. 保留タスクからの再開

### 認識トリガー

- ユーザーが「あの仕組み化を進めよう」等、記録済み提案への着手を示す発言をした
- ユーザーが `/mechanism-builder`（引数なし）を実行した際に保留中の仕組み化タスクが存在する

### フロー

1. 記録済み提案を提示する:
   > 「**[提案内容] の仕組み化タスクが保留中です。着手しますか？**」

2. 提案内容が依然有効か確認する（状況変化があれば内容を修正）

3. **着手する** → `.claude/skills/mechanism-builder/SKILL.md`（B フロー）へ進む
   **着手しない** → 終了
