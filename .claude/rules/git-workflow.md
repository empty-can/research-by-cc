# Git 運用ルール

本リポジトリは Git 化済み・GitHub 公開済み。コミット統制の運用ルール。`paths:` を持たないため毎セッション無条件ロードされる。

## コミット候補のタイミング

Claude は以下のタイミングで「コミット候補」として作業指示者に提案する:

- 個別調査フォルダ内のフェーズが完了したとき
- クロスレビュー報告書を作成・更新したとき
- 依頼者レビュー指摘を反映した改訂版を作成したとき
- 共通設定（`.claude/` 配下）の更新を完了したとき
- ルート CLAUDE.md / README.md の方針変更を反映したとき

## コミット実行の可否

- **Claude は自動コミットしない**。コミット候補として提案し、依頼者の明示承認を経て初めて commit を実行する
- 提案には「コミットメッセージ案」と「対象ファイル群」を含める
- `git add -A` / `git add .` は使わず、**対象ファイルを明示指定**する

## コミットメッセージの方針

- 1 行目は `<種別>: <要約>` 形式（種別例: `feat` / `fix` / `docs` / `chore` / `refactor` / `review`）
- 本文（任意）は「なぜ」を中心に記載。「何を」は diff から読める
- レビュー反映コミットは `review: 〜への対応反映` のように明記

## `.gitignore` の方針

- **個人ローカル設定**（`.claude/settings.local.json` / `CLAUDE.local.md`）— ユーザ個別の権限・補足指示。共有しない
- **作業中の一時物**（`.claude/work/` / `.claude/workspace/` / `scratch/` / `*.tmp`）— 完了後に削除されるか、別途コミット対象に昇格
- **エージェントメモリのローカル分**（`.claude/agent-memory-local/`）— セッション固有
- **環境変数・機密情報**（`.env*`（`.env.example` 除く）/ `secrets/`）— `permissions.deny` との二重防御
- **言語別ビルド成果物**（`node_modules/` / `__pycache__/` 等）
- **IDE / OS** ローカル設定 — 個別環境依存

> **Git 運用の意義**: 差分レビューで改訂前後の差分だけ読めばよくトークン・コンテキストを節約できる／`git log` がそのままプロジェクトジャーナルになる／`git show <commit>:<path>` で過去版を現状ファイルを汚さず参照できる／誤削除・誤上書きから回復可能／GitHub 公開済みのため Issue・PR で外部の指摘を受けられる。これらにより、各 CLAUDE.md の「変更履歴」は Git 化以降は重複管理を避けて簡潔化してよい。
