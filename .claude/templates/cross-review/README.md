# cross-review テンプレート

クロスレビュー報告書の雛型。3 種同梱:

| ファイル | 担当レビュアー | 観点（既定） |
|---|---|---|
| `論理整合性_template.md` | Claude Opus（独立第三者） | 論理整合性・カバレッジ十分性・調査目的との整合性・仮説の妥当性 |
| `実用性_template.md` | Claude Sonnet（独立第三者） | 完了条件明瞭性・命名規則遵守・文書構造・検証パターン具体性 |
| `作業指示者レビュー_template.md` | 作業指示者（人間） | 自由記入。観点欄は記入時に補足。 |

## 使い方

1. レビュー対象のフェーズ配下に `レビュー/` フォルダを作成
2. 上記 3 ファイルを `<観点名>_<日付YYYY-MM-DD>.md` の名前でコピー
   - 例: `クロスレビュー_論理整合性_2026-05-01.md`
3. 各ファイル冒頭の `{{...}}` プレースホルダを埋める
4. Opus / Sonnet レビューは Agent に委任（`.claude/skills/orchestrate/` のパターン A: 並列調査を参照）
5. 作業指示者レビューは作業指示者が直接記入

## レビューフロー

| 版 | 担当 | 作業内容 |
|---|---|---|
| 0.8 | レビュアー | レビュー実施・報告書作成 |
| 0.9 | レビューイ | レビューイFBを報告書に記入 → レビュアーが修正案反映完了 |
| 1.0 | 作業指示者 | 態度表明記入・指摘対応確認 → レビュアーが修正案反映完了 |

## 版数管理

### 版番号の定義

| 版 | 意味 |
|---|---|
| 0.8 | 初版（レビュアーによるレビュー完了） |
| 0.9 | レビューイFB取り込み完了（1回目） |
| 0.9.1, 0.9.2, ... | レビューイへの差戻し・再取り込みが発生した場合の細分化 |
| 1.0 | 最終承認者のレビュー取り込み完了（最終版） |

最終承認者のレビューが完了した版を 1.0 とし、それまでの版番号はレビューステップを逆算して決定する。

### 未到達版とスキップ版の表記

| 状態 | 定義 | 変更履歴の日付・内容欄 | 件数推移表のセル |
|---|---|---|---|
| 未到達 | 将来到達する可能性があるが、まだ到達していない | 空欄 | 空欄 |
| スキップ | フロー上発生しない（例: 作業指示者レビュー不要の成果物の 1.0 版） | `-` | `-` |

「忘れた（記入漏れ）」と「スキップ（構造的に不要）」を区別するために、スキップには必ず `-` を明記する。

## 指摘ラベルの定義

クロスレビューはコードに限定したものではないため、以下の定義を `code-review.md` から独立して管理する。レビュー観点の整理に伴い、必要に応じてこちらを改訂すること。

| ラベル | 意味 | 対応 |
|---|---|---|
| **CRITICAL** | 重大な論理的誤り・結論の誤り・調査目的との根本的不整合・活動の継続に支障を与える問題 | 必ず修正 |
| **IMPORTANT** | 論理性・正確性・品質に関わる問題 | 修正を強く推奨 |
| **SUGGESTION** | 改善提案・表現・読みやすさ | 任意対応 |
| **POSITIVE** | 適切な判断・良い記述 | 維持を推奨 |

## 作業指示者の態度区分

| 態度 | 意味 |
|---|---|
| **採用** | 指摘を受け入れ、修正案を適用する |
| **条件付き採用** | 修正案を一部変更・条件を加えて採用する |
| **差戻し** | レビューイに追加情報・再検討を求める（0.9版フェーズに戻る） |
| **保留** | 現フェーズでは判断しない（後続フェーズで判断） |
| **却下** | 指摘を受け入れない |

「保留」の内訳:

| 分類 | 意味 | 後続対応 |
|---|---|---|
| 情報収集型保留 | 判断材料が不足。後続フェーズで情報収集後に判断する | レビューイFBフェーズ（0.9版）で多くが解消される見込み |
| 意思決定型保留 | 現フェーズでは判断を下さない（後続フェーズの設計判断と組み合わせる等） | 申し送り事項になる可能性あり |

## 保留・却下の運用範囲

- **保留**: 「意思決定型保留」に限定する。「現時点で判断を下すことが本活動に影響がない」または「本活動のスコープ外」のいずれかを判断根拠とする
- **却下**: 作業指示者固有のコンテキスト（プロジェクト制約・スコープ外）により指摘が無効と判明した場合に限定する

## レビュー観点の取捨選択

各レビュアーが担当する観点（論理整合性テンプレートは 4 観点、実用性テンプレートは 4 観点）は、レビュー対象に応じて取捨選択可能。

- 観点をスキップする場合は、観点別指摘件数表の当該観点のステータスを「スコープ外」と記入する
- スコープ外とした理由は、報告書のメタ情報セクションの「スコープ外」欄に記載する

> **注意**: 本ファイル（Level 1）のデフォルト値は、下位の `research-for-xxx/CLAUDE.md`（Level 2）または各サブフォルダ `CLAUDE.md`（Level 3）で上書き可能。`/init` 等で CLAUDE.md を新規作成する際は、上書きが必要なルールがあれば「レビュー実施ルール」節に明記すること。

## 設計方針

- **指摘エントリごとに「作業指示者の態度表明」テーブルを内蔵** — 指摘とその態度を 1 箇所にまとめ、別ファイルやドキュメント末尾を行き来する負担を排除
- **接頭辞で出所を区別** — `C/I/S/P` (論理) / `C-/I-/S-/P-` (実用) / `U-C/U-I/U-S/U-P` (作業指示者)
- **件数サマリは記入完了後に更新** — 雛型では `<TBD>` プレースホルダ
- **変更履歴セクションを末尾に必ず保持** — 改訂履歴の追跡は各ファイル内で完結させる方針
