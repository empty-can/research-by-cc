# check-model

現セッションのモデル妥当性を評価し、必要に応じて切替を提案する。

## 引数

`/check-model [作業内容の説明]` の形式で呼び出せる。

- **引数あり**: 指定された説明を評価対象の作業内容として直接使用する
- **引数なし**: 会話履歴から直近の作業指示を自動推定する（hook 経由の自動発動時はこちら）

引数なしで直近の作業指示が特定できない場合は、作業指示者に「評価対象の作業内容」を確認する。

## 評価基準

| モデル | 適性領域 |
|---|---|
| **Opus** | 設計判断、複雑な多段推論、論理整合性が問われる検討、独立クロスレビュー、新規アーキテクチャの方針策定、トレードオフ分析 |
| **Sonnet** | 通常の実装・デバッグ・リファクタリング、中規模の設計、調査と要約、コードレビュー実施 |
| **Haiku** | 単純な変換・整形、決定論的 lookup、軽量な質問への応答、テンプレ生成 |

## 出力フォーマット（固定）

判定結果に関わらず、常に以下の形式で出力する:

適合の場合:

```
**直近の作業指示**: <作業内容>
**判定結果**: 適合
**モデル情報**: 現モデル: <現モデル名>
```

切替推奨の場合:

```
**直近の作業指示**: <作業内容>
**判定結果**: 切替推奨（過剰）／ 切替推奨（不足）
**モデル情報**: 現モデル: <現モデル名> → 推奨モデル: <推奨モデル名>
**理由**: <1〜2文>
```

- 「切替推奨」の場合は出力後、作業指示者に切替の判断を仰ぐ
- フォーマット外の補足説明・見出し・追加セクションは原則追加しない

## 実行手順

1. 引数が指定されていれば、その内容を作業内容として確定する。引数なしの場合は会話履歴から直近の作業指示を特定する
2. 現セッションのモデル（system prompt の自己認識）を確認する
3. 評価基準に照らして判定する:
   - **適合**: 現モデルが作業内容に対して過不足ない
   - **切替推奨（過剰）**: Opus を使っているが Sonnet/Haiku で十分な作業
   - **切替推奨（不足）**: Sonnet/Haiku を使っているが Opus 相当の思考深度が必要な作業
4. 上記フォーマットで出力する。「切替推奨」の場合は作業指示者に切替の判断を仰ぐ

## 判定が曖昧な場合

タスクの規模・期待される思考深度・反復回数のいずれかを作業指示者に質問して情報を補完してから再判定する。

## 適用範囲

- メインセッションのモデル妥当性のみを対象とする
- sub-agent として呼び出された状態でこの Skill を実行することは想定しない（sub-agent のモデルは Agent 定義 frontmatter で固定されており切替不可のため）
