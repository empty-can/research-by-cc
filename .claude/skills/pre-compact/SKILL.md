# pre-compact（コンパクション前事前準備）

`/compact` 実行前に呼び出し、コンパクション後の次セッション再開時に最低限の文脈が復元できる状態を整える Skill。

## 出力方針

**作業指示者の判断を要する情報と、最終的な `/compact` コメント提案のみを出力する。** ステップ 1・3 は完全 silent。ステップ 2 は未コミット変更がある場合のみ出力する。コンテキスト消費を抑えるための方針。

**silent ステップでの禁止事項**: 「サイレントで実行中」「ステップ N を処理中」「メモリを確認しています」等の進捗説明・確認メッセージ・実行状況報告を含め、**いかなるテキストも出力してはならない**。完全無言で処理する。

## 実行手順

以下を順番に実施する。

### 1. メモリ最新化（silent）

auto-memory（`memory/` ディレクトリ）配下のメモリファイルを確認し、現在の会話で変化した情報を更新する。**出力しない**。確認観点:

- 進行中のタスクの最新ステータス・中断箇所
- 次セッション再開時の継続ポイント
- 作業指示者との合意事項で未記録のもの
- 保留中の判断事項

### 2. 未コミット変更の確認

`git status` で未コミット変更を確認する。

- **変更なし**: 出力しない
- **変更あり**: コミットメッセージ案と対象ファイルを提示し、作業指示者の判断を仰ぐ（この場合のみ出力する）

### 3. 継続ポイントの収集（silent）

次セッション再開時に必要な情報をステップ 4 の入力として収集する。**出力しない**:

- 現在実施中のタスクと中断箇所
- 保留中の判断事項（作業指示者が決める必要があるもの）
- 次セッションの最初のアクション

### 4. 最適なコンパクション指示コメントの提案

ステップ 1〜3 の内容と会話コンテキストをもとに、`/compact <指示>` に渡す最適な指示コメントを生成して提示する。

**コメントの書き方（公式ドキュメントに基づく指針）**:

公式例: `/compact Focus on the API changes`

- **短く・焦点を絞る**: コンパクターは intent（意図）を解釈するため、詳細なタスクリストより端的な保存指示が有効
- **「Preserve X」「Focus on Y」フレーミング**: 「現在の作業文脈と次アクションに集中して」のように意図を伝える
- **ファイルパスや手順の羅列は避ける**: コンパクターが会話から自動抽出するため冗長になる

**セルフチェックリスト**（コメント案を出力する前に必ず確認する）:

- [ ] コメントが概ね 200 文字以下か（公式例 `Focus on the API changes` から大きく逸脱していないか）
- [ ] 「Preserve X」「Focus on Y」フレーミングを使っているか
- [ ] ファイルパス・指摘 ID（C1 / I1 等）・手順の具体的羅列を避けているか
- [ ] intent（次アクション + 保持すべき方針のメタ指示）に集中しているか

いずれかに不適合があれば、コメントを修正してから提示する。

**盛り込む観点**（優先順位順）:
1. 現在進行中のタスク（最も優先）
2. 未完了の残ステップの概要
3. 保留中の判断事項（あれば）
4. 未コミット変更（あれば）

**出力形式**（作業指示者がそのままコピーして使えるよう提示）:

```
【/compact コメント提案】
/compact <生成した指示コメント>
```

作業指示者は提案をそのまま使うか、必要に応じて編集してから `/compact` コマンドに渡す。

## 完了確認

ステップ 4 の出力の後、「上記コメントを使って `/compact` を実行してください」と作業指示者に伝える。

## /compact コメントに関する公式情報

参照元: `research-for-local-RAG-for-cc/resources/references/claude-code-llms-full.txt`（約 4667 行〜）

> For more control, run `/compact <instructions>`, like `/compact Focus on the API changes`

> Customize compaction behavior in CLAUDE.md with instructions like `"When compacting, always preserve the full list of modified files and any test commands"` to ensure critical context survives summarization

コメントは自由記述でコンパクターが intent を解釈して処理する。常時保持したい保存指示は CLAUDE.md に書く方法もある。

## 設計背景

`/compact` は built-in コマンドであり `PreCompact` hook で前処理を挟む方法があるが、hook は Claude のコンテキスト外（シェル/別 LLM 呼び出し）で動作するため、現在の会話コンテキストを踏まえた Claude 自身による能動的な準備は実行できない。詳細は `references/decision-flow.md` §2.1 参照。
