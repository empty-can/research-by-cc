# 全ブランチ横断資産マップ（全マシン × 全ブランチ HEAD 断面）

> 既存の [配布可能資産インベントリ](../01.全マシン資産インベントリ/配布可能資産インベントリ.md)（作業ツリー 1 断面）・[配布計画](../02.配布計画/配布計画_Plugin可否とリポジトリ割当.md)を補完する、**全リポジトリ × 全ブランチ HEAD の `.claude` 資産マップ**。
>
> 収集は 8 体の SubAgent が各リポジトリの全ブランチ（local + origin-only）HEAD 断面を `organize-assets/` にエクスポートして実施。リポジトリ単位の詳細は各 `<略号>/_MANIFEST.md` を正とし、本文書はその統合・横断要約に徹する。**ファイル件数の正本は各 `<略号>/_INDEX.txt`**（後述の 0 バイトバグの影響で一部マニフェスト本文中の件数は過少。必ず `_INDEX.txt` の数値を採用する）。

## 0. 目的とスコープ

### 0-1. なぜ全ブランチ断面を採ったか
01（作業ツリー 1 断面）は「いまチェックアウトされているブランチ」しか見えず、別ブランチに眠る正本候補・世代差・未 push 変更を取りこぼす。都度 `git checkout` で HEAD を移動して確認するのはコンテキスト・作業コストが高く、誤チェックアウトのリスクもある。そこで各リポジトリの全ブランチ HEAD を一度だけ `organize-assets/<略号>/<ブランチ>/` へエクスポートし、**チェックアウト不要で全断面を横断比較**できる状態を作った。

### 0-2. スコープ境界
- **対象**: 全階層の `CLAUDE.md` と、全階層の `.claude/` 配下の **git 追跡済みファイルのみ**。
- **対象外**: `.mcp.json`、リポジトリ root の `plugins/`、LLMs データ本体（`official-llms-txts/` 等）、`settings.local.json` / `CLAUDE.local.md`（個人ローカル）、機密、`reports/`（研究成果物。ただし `.claude/reports/` に混入したものは追跡混入として記録する）。
- **マシン × ユーザスコープ**: 本断面は**リポジトリのみ**。ユーザスコープ（`U-USR` = `C:\Users\empty\.claude`）は本収集の対象外で、01 の記述が引き続き正本（§5 参照）。

### 0-3. 件数の正本と収集方式
- **件数正本 = `_INDEX.txt`**（書式: `ブランチ | ref | local/origin | sync | files`）。
- エクスポートは **git tree（`git ls-tree` / `git cat-file`）ベース**で、追跡済みファイルのみを出力。未追跡ファイルは原理的に入らない。
- MSYS / `core.quotepath` 由来のパス化けと、Windows Git Bash で `git show "<branch>:<path>"` がスラッシュ・コロンを誤変換する問題に対策済み（`git ls-tree` + blob-SHA `cat-file` の 2 段階回避）。ただし一部の早期エクスポートで**スラッシュを含むブランチの `.claude` ファイルが 0 バイト出力**となる副作用が残った（§4-異常 11）。**git リポジトリ側のデータは正常**で、件数は `_INDEX.txt`（blob 列挙ベース）が正しい。
