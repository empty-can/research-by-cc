### CR-B `publish-share.ps1` が submodule checkout を配布先として受理し、robocopy が gitlink を破壊して親リポジトリへ commit/push する
**統合元**: 実用C2（Fable が scratchpad で**実測再現**）

**私の検証（CONFIRMED・コードレベル）**:
- `publish-share.ps1` **L23**: `if (-not (Test-Path (Join-Path $ShareBody '.git')))` ―― **`-PathType` 未指定**。`Test-Path` はファイルにも `$true` を返す。
- 対して `publish-share.sh` **L31**: `[ -d "$SHARE_BODY/.git" ]` ―― **ディレクトリであることを要求**（正しい）。
- submodule の `.git` は**ファイル**（gitlink）である。したがって **PS 版のみ、submodule checkout（例: `basic_cc_project\.claude`）を「共有本体」として受理してしまう**。
- `publish-share.ps1` **L50**: `robocopy $src $ShareBody /MIR /XD .git /XF ...` ―― **`/XD .git` はディレクトリのみ除外**。`.git` が**ファイル**の場合は除外されず、`/MIR` により**削除される**（Fable が実測: `.git file survived? False`）。
- 続く L56-61 の `git -C $ShareBody add -A / commit / push` は、gitlink を失った結果**上方探索で親リポジトリ（C-BCP）に対して実行される**。

**帰結**: 利用者が「手元にある `.claude` の実体」を配布先と誤認して指定すると、**submodule が壊れ、親リポジトリへ意図しない commit/push が走る**。

**修正案**: bash / PS 両版で「`.git` が**ディレクトリ**であること」＋「`git -C $ShareBody rev-parse --show-toplevel` が `$ShareBody` 自身と一致すること（＝リポジトリルートであり submodule/サブディレクトリでない）」を検査する。

### CR-C `publish-share.ps1` の `/XF .gitignore` が、CR-1（配布先セーフティネットの payload 搬送）を Windows で無効化する
**統合元**: 実用I2

**私の検証（CONFIRMED）**:
- `publish-share.ps1` **L50**: `robocopy $src $ShareBody /MIR /XD .git /XF README.md LICENSE .gitignore`
- **robocopy の `/XF` はファイル名マッチで全階層に効く**。したがって payload 内の `.gitignore` は**どの階層にあってもコピーされない**。
- 一方 `publish-share.sh` は keep-list（`find ... ! -name '.gitignore' ...`）で**削除から守るだけ**であり、その後の `cp -R "$tmp/.claude/." "$SHARE_BODY/"` が payload 側で**上書きする**。

**帰結（CR-1 実装への直撃）**:

| CR-1 で搬送するファイル | bash 版 publish | **PowerShell 版 publish** |
|---|---|---|
| `.claude/.gitattributes` | 届く ✓ | 届く ✓（`/XF` に無い） |
| `.claude/.gitignore` | 届く ✓ | **届かない ❌** |

→ **PR #2 で実装した CR-1 は片肺だった**。Windows から publish した場合、配布先 C-BDC に個人実体（`custom.env` / `option-settings.*`）の除外が届かない。改行固定（`.gitattributes`）だけが届く、という中途半端な状態になる。

**修正案**: `/XF` の意図は「**配布先ルート直下**の `README.md` / `LICENSE` / `.gitignore` を保護する」ことのはずだが、robocopy の `/XF` は全階層に効くため意図と実装が乖離している。bash 版と同じセマンティクス（**dest 直下のみ選択削除 → payload を全コピー（payload 優先で上書き）**）に書き直す。あわせて「payload に同名ファイルがある場合の優先規則」を両版で明文化・一致させる。

### IM-2 `.gitattributes` 不在 ― autocrlf=true の Windows clone で `scripts/*.sh` が CRLF 化し、publish パイプライン自体が死ぬ
**統合元**: 論理I5 ／ 実用I4 ／ 作業U-I2（3 観点全到達）
**検証（CONFIRMED）**: `chore/groom-as-share` に **`.gitattributes` が存在しない**（`git ls-tree` で 0 件）。blob は LF 格納（`git cat-file blob | tr -cd '\r' | wc -c` → **0**）。本マシンは `core.autocrlf=false` のため露見していないが、**Git for Windows の既定は `true`**。PR #2 の root `.gitattributes` は「既存の `scripts/*.ps1` 等に副作用を与えないよう**ランチャーのパスに限定**」しており、`scripts/` は**意図的に対象外**。
