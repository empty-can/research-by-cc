## 組織セキュリティ制約・機微情報の取扱い

### MCP サーバの利用制約

- **本環境では MCP サーバは一切利用できない**（情報セキュリティ保護上の制約により、組織として正式に認められていない）。
- ルート `.mcp.json` / `research-for-xxx/.mcp.json` も配置しない（本調査における「調査対象としての MCP Server」は除く）。
- 過去ドキュメント（`research-for-local-RAG-for-cc/` 等）に MCP 経由の手順記載が残っているが、それらは過去の検討記録として保存しているもので、**現在の作業で MCP ツールを呼び出してはならない**。`mcp__*` 系ツールは「使えない」前提で代替経路を選ぶ。
- 外部情報の調査経路は MCP 抜きの構成（ローカル DL ファイル + WebFetch + Web 検索）で組み立てる。

## 調査の目的

MCP Server の脆弱性（特に、構築環境の個人情報や機密情報の漏洩に繋がるようなもの）を、MCP Server のソースコードのレビューによって調査・判定するための仕組みを調査・確立すること。

## 背景

### 本実行環境における現状の MCP サーバ利用制約

本リポジトリの実行環境（および利用者の所属組織の業務環境）では、**情報セキュリティ保護上の制約により、MCP サーバの利用が現状正式には認められておらず、一切セットアップされていない**。

この制約は MCP サーバの仕組み自体（Claude Code とサードパーティ製サーバ間の双方向通信、サーバ側コードの任意実行性、トークン・認証情報・ローカルファイルへのアクセス可能性）が、構築環境の個人情報や機密情報の漏洩経路となる潜在リスクを持つことに起因する。

### 本ブランチが達成しようとしているゴール

情報セキュリティ所管部署に対して、以下を満たした上で MCP サーバの利用許諾を得られるようにすること:

1. **しっかりとした審査基準を設けた上で**、
2. **対象 MCP サーバのソースコードレビュー（インスペクション）を実施し**、
3. **充分な確認を行ったものに限って利用する**

という運用フローを確立し、それによって「利用にリスクは無い」と **説得力と自信を持って所管部署に回答・説明できる状態** を目指す。

そのために本調査では以下を整備する:
- MCP サーバのソースコードレビューによる脆弱性（特に構築環境の個人情報・機密情報漏洩に繋がるもの）の調査・判定の仕組み
- 判定基準・観点・チェックリスト
- 実施プロセスと成果物フォーマット

### レビュー繰り返し
- Claude Code 単独での **セルフレビュー / クロスレビュー** は、**新規 NG 検出がゼロ** になるまで繰り返し実施する
- 多段構成（例: セルフレビュー → 別 Agent クロスレビュー）の場合、**各段で全 NG への対応を完了した状態で次段へ進む**

### 必須レビュー（作業指示者承認を兼ねる）
以下の成果物は **作業指示者によるレビュー** を必須とする:
- 計画書（v1.0 完成時）
- 各フェーズ完了時の報告書
- 最終報告書

### 個別レビューの依頼
以下の場合は、必須レビュー以外でも作業指示者に個別にレビューを依頼する:
- セルフ／クロスレビューで作業指示者の判断を仰ぐべき指摘が検出された場合
- NG が検出されていなくても、判断ミスによる後続工程への大きな手戻り懸念がある場合

レビュー対象は報告書である必要はなく、**相談用ドキュメント** または **GitHub Issue** でも可。判断が必要な事項を分類する場合は **「課題」** という分類名を使用する。
