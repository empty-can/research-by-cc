## ドキュメント構造運用ルール

Phase 0c 配下のドキュメントは規模が大きくなる見込みのため、**Claude のドキュメント読込負荷を抑える構造ルール** を定める。

### 目次セクション（§0.1）

- **各ドキュメントの §0 メタ情報の冒頭サブセクション §0.1 を「ドキュメントの目次」とする**
- 目次は **Markdown 内リンク形式** で記述（`[見出し名](#見出し名)`）
- **目次に含める階層**: h2（`##`、§N）と h3（`###`、§N.M）までを基本ルール化。h4 以下は必要時のみ
- 各セクションタイトル（見出し）は **そのセクションで扱う内容を端的に表す** ものとする。目次の見出し文を見るだけで参照すべきセクションを特定できる粒度にする
- **本文の見出し追加・変更時は同時に目次を更新する**（手動運用、自動生成ツール非導入）
- 日本語見出しの anchor は GitHub flavored markdown 仕様（小文字化・空白→ハイフン・記号除去）で動作。極端な記号混在は避ける

### 効果

| 効果 | メカニズム |
|---|---|
| **意味的検索の効率化** | grep では拾えない概念キーワードでも、目次の見出し文を見て該当セクションを特定できる |
| **部分読み込みの正確性向上** | Read tool の `offset / limit` パラメタと組み合わせ、目次から行範囲を逆算して必要部だけ読込可能 |
| **レビュー時の段階的アプローチ** | 全文読み込みを避けて、目次から関心セクションを抽出し、必要に応じて隣接セクションを追加読み込み |
| **ファイル分割判断の自然化** | 目次が長くなったら自然と分割を意識する → 閾値超過前に構造見直しのトリガーとして機能 |

### 適用範囲と例外

- **適用対象**: Phase 0c 配下の成果物ドキュメント（信頼性スコア集計表・公開ナレッジ整理・二軸分類等）
- **例外**: 全文横断レビュー時はこの構造の恩恵は限定的（許容）。一時的なメモ・ドラフトレベルでは目次省略可（成果物としてリリースする前に目次を整備）

## ファイルサイズ閾値運用

| 状態 | 行数目安 | 対応 |
|---|---|---|
| **通常** | 〜1500 行 | 単一ファイル運用継続 |
| **注意水域** | 1500〜2500 行 | 構造の自然な分割境界（章単位）があれば分割検討、なければ継続可 |
| **強制分割推奨** | 2500 行超 | スナップショット退避 + 新構造で複数ファイル化 |

**閾値の根拠**: Claude Code の Read tool は既定で 2000 行まで読込可能 + コンテキスト消費が線形に増えるため、2500 行超えると全文一括レビューが現実的でなくなる。1500 行は「注意水域開始」の目安で、**内容の自然な区切りが優先**（細かい数値より構造的区切り）。

## 版管理運用（フォルダで版管理）

ファイル名にバージョン情報を含めず、**フォルダで版管理** する方針。ファイル名は固定（例: `Phase0c.md`）を維持できるため、ファイル内リンクが壊れず、命名の負担もない。

### フォルダ構成

├── CLAUDE.md                              ← 本ファイル（運用ルール + 現役フォルダ案内）

### スナップショット退避の発動条件

| 条件 | 発動契機 | 対応 |
|---|---|---|

### フォルダ命名規則

| 種別 | 命名 | 例 |
|---|---|---|
| **先行着手中** | `_draft_先行着手/` | （現役）|
| **正式版** | `v{N}_<契機キーワード>/` | `v1_Phase0b-2-γ完了反映/`, `v2_分割構造/` |

先頭 `_` でフォルダ一覧の上端に出現させ、現役と過去版の視認性を高める。
