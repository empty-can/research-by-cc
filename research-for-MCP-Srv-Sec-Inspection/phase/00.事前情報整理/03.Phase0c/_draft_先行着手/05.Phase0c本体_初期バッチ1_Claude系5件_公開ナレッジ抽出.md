## §4 二軸分類ドラフト（仮）

> **重要**: 本セクションはドラフトのみ。軸の確定には後続ステップでの上位者（Opus レビュア）承認が必要。軸は今後の作業（Phase 01 計画書策定）で変更される可能性がある。

### §4.1 二軸候補の定義

本バッチで抽出した公開ナレッジを整理するにあたり、以下の 2 軸を仮定義する。

**軸 A（検知軸）: コードインスペクションで検知可能か**
- A1: コードインスペクション（静的解析・手動レビュー）で検知可能
- A2: 実行時・設定・運用層でのみ顕在化（コードレビューでは検知困難）
- A3: 両方の側面を持つ（実装不備 + 設定ミスが重なる場合など）

**軸 B（攻撃/リスク分類）: 攻撃/リスクの本質的カテゴリ**
- B1: RCE / コマンドインジェクション / パストラバーサル（コード実装不備系）
- B2: プロンプトインジェクション / ツールポイズニング（AI 固有攻撃）
- B3: SSRF / DNS リバインディング（リクエスト偽装系）
- B4: 認証情報漏洩 / シークレット流出（秘密情報取扱い不備）
- B5: 依存関係脆弱性 / サプライチェーン（外部依存起点）
- B6: 過剰権限 / 最小権限違反（設計・設定層）

## §5 工程上の所感・課題

### §5.1 採点困難ケース

- **CVE-2026-27735**: #16 の Explore agent のみが言及する将来年度 CVE。他 AI での確認なし。NVD への直接検証が必要
- **GHSA シリーズ 6 件**: #16 のみ言及。Explore agent が発見したが、他 AI（#19/#20 の Web 検索）が発見していない点が不審。検証が必要
- **#18 の「意図的な CVE 回避」**: 学習データに CVE 情報があった可能性が高いが、自発的に開示しなかった。実際の知識量と開示量が乖離するケースとして記録

### §5.2 同一性判断の問題

- **Semgrep vs Opengrep**: #19 は「Semgrep の FOSS fork として Opengrep を推奨」と明言。同一ツールファミリーと見なすか別ツールとカウントするか要整理
- **mcp-scan の帰属**: #18 は「Invariant Labs」、#20 は「Invariant Labs/Snyk」と表記差あり。同一ツールだが出典帰属の違いが確認できた
- **OWASP GenAI Guides vs OWASP Top 10 Agentic Applications 2026**: 同一シリーズ内の別ドキュメント。関係性の整理が必要

### §5.3 信頼性スコア方法論の課題

- **Web 検索 AI の偏り**: #19/#20 は明示的な Web 検索許可後に大量の CVE を取得したが、これは「探索条件の差異」による偏り。同条件で比較するには、全 AI に同一の Web 検索条件を与えた場合の比較実験が必要
- **学習データの深度差**: #07（カットオフ 2024-08）と #20（カットオフ 2026-01）では知識の深度が根本的に異なる。言及カウントだけでは「知らない」と「知っているが言わない」の区別ができない
- **重み付けの未定義**: Web 検索由来（NVD 直接参照）と学習データ由来では信頼性に差があるが、本バッチでは定量的な重み付けを未定義のまま記録に留めた

### §5.4 後続バッチへの改善提案

- **Google 系・GPT 系の追加バッチ**: 本バッチは Claude 系 5 件のみ。別モデルシリーズとの比較で「Claude ファミリー固有の傾向」を分離できる
- **Web 検索条件の統一化**: 後続バッチでは「Web 検索可/不可」を明示し、同一条件での比較テーブルを作成する
- **GHSA 検証タスク**: #16 発見の GHSA 6 件は後続タスクで NVD/GitHub Advisory に対して直接確認する
- **「Invariant Labs 起因ナレッジ」の集約**: Tool Poisoning/Rug Pull/mcp-scan が全て Invariant Labs 起源。ベンダー帰属を軸にした整理も有効
