### 2.3 差分の意味解釈

観察される差分を「モデル能力差 / インフラ差 / 学習時点差 / 質問者側の促し要因」の 4 分類で意味解釈する。

| 観点 # | 支配的な差の出処 | 解釈 |
|---|---|---|
| 1, 8, 9 | **質問者側の促し要因 + インフラ差** | Q1 質問文に WebFetch/WebSearch 明示許可文言が含まれているかで自発検索の起動が変わる（Sonnet 版索引 §6.1 末尾の論点）。明示許可がない場合、Bedrock 経由 Opus はハルシネーション抑制ポリシーで検索を回避する傾向 |
| 2 | **インフラ差**（Web 検索可否に起因） | 検索を回避した Bedrock 側は学習データに直接保持していない 2026 年 CVE を出せず 0 件、検索した Anthropic 純正側は 13 件超 |
| 3 | **インフラ差** | Sources セクション + 処理時間表示は Anthropic 純正 Claude Code の出力フォーマット仕様。Bedrock 経由は学習データ完結のため出典管理機能を呼び出さない |
| 4, 5 | **インフラ差（Plugin 環境差）** | Insight ブロック生成は Learning Style Plugin 機能であり、Plugin が無効な Anthropic 純正側では構造的に出ない。**モデル能力差ではない** |
| 6 | **インフラ差**（カットオフ後質問への模範応答） | 両者とも 2026-01 学習時点だが、Anthropic 純正側で Q0.ex1 が実施された。質問構造側の違い |
| 7 | 区別不能（**モデル個性 + 質問者所感記載差**） | 両者ともスキップ自体は共通。理由表現が異なるのみで意味解釈の差は薄い |
| 10 | **インフラ差の質問者側評価** | 質問者所感は「観察事実 + 評価」の混成。Anthropic 純正側で「Opus はオーバースペック」評価が出ているのは Web 検索の存在で Sonnet との差が縮まったため |
| 11 | **モデル能力差 + インフラ差の合成** | Opus の緻密性は両側で保たれるが、Plugin ON 環境ではメタ的観察を Insight に集約する形で顕在化 |

**統合解釈**: 観点 2/3/4/5/8/9 はすべてインフラ差（経由先 + Plugin 環境）に帰着。観点 1 と 10 は質問者側の促し要因が一定割合を占める。**モデル能力差は本ペアではほぼ観察されない**（同じ Opus 4.7 のため）。学習時点差も該当しない（両者 2026-01）。

### 2.4 Phase 0c 本体での利用方法

**用途 A: 「経由先が回答性質を支配する」を主張する**
- 観察観点 1/2/3/8/9 を根拠として提示
- 同モデル・同バージョン・同学習時点の条件で経由先のみ変更した結果、CVE 提示件数が 0 件 vs 13 件超に分かれる事実は強力な主張根拠
- ただし観点 1 については Q1 質問文の明示許可文言の有無が交絡することを必ず注記する

**用途 B: 「Insight ブロックは Plugin 環境差であり、モデル能力差ではない」を主張する**
- 観察観点 4/5 を根拠
- 同モデルでも Plugin 環境の差で Insight ブロック有無が決定論的に分岐する事実を示す
- 「Plugin 有環境の回答が情報源として優位」と誤解しないよう注記

**用途 C: 「Bedrock 経由 Opus のハルシネーション抑制ポリシーは情報源として独自価値」を主張する**
- 観察観点 5/9/11 を根拠
- メタ的観察（カーブの概念・合成系脆弱性・URL 出さない誠実さ）は他経由先で得られない独自洞察
- Phase 0c の「観点・枠組み抽出」素材として優位、ただし具体 CVE 裏取りには使えないことを明示

**用途 D: 信頼性スコア算出時の「経由先別重み付け」根拠**
- #18 と #20 は経由先が違うため挙動が両極化 → **独立した観察として重み 1.0 ずつ** カウント（並行作業 C §5.2 の暫定ルール）
- 同じ CVE を両者が言及した場合は二重確認として信頼性加点、片側のみの場合は経由先依存の素材として注記

### 2.5 観察上の注意点

**注意点 1: Q1 質問文の明示許可文言の有無が交絡する**

Sonnet 版索引 §6.1 末尾の論点:
> 「Q1 の質問文に WebFetch/WebSearch 利用の明示許可を含めるか」が Anthropic 純正 vs Bedrock の差を決める要因の一つとして観察されている（#19 Q1 と #18 Q1 の比較）

本ペアで観察される Web 検索有無の差は、純粋な経由先効果ではなく **「経由先 + 質問文の明示許可文言」の合成効果**。Phase 0c 本体で「経由先差が支配的」と結論付ける場合は、両者の Q1 質問文を実際に確認し、明示許可の有無を脚注に明示する。

**注意点 2: Insight ブロックは内容の独立価値と経由先環境差を分けて評価する**

#18 の Insight は Plugin 環境配下でしか出ないが、内容そのもの（SARIF 統合方針・mcp-scan の Invariant Labs 由来・NIST SP 800-216 への言及）は他経由先・他モデルでも検証可能な情報源を含む。Phase 0c 本体で Insight 由来の情報を引用する場合は「#18 の Insight 由来」として出典を残しつつ、内容自体は他経路でも追跡可能なものとして扱う。

**注意点 3: 「Opus はオーバースペック」評価の解釈**

#20 の質問者所感「情報収集には Sonnet で十分」は、本ペアの観察結果（Web 検索積極時の Sonnet 4.6 (#19) と Opus 4.7 (#20) の情報量が遜色ない）から派生した評価。**経由先・Plugin 環境の交絡を除けば**、ベースモデル能力差そのものが情報収集タスクで縮小することを示唆している（情報収集タスクには Sonnet で十分、構造化・洞察抽出タスクには Opus 優位の境界線）。

**注意点 4: Q4 スキップは両者共通のため経由先差の素材として使えない**

観点 7 は意味解釈の差が薄いため、Phase 0c 本体の経由先差主張には使わない。Sonnet 版索引が Q4 スキップ理由まで記録した精密性は別途参照素材。
