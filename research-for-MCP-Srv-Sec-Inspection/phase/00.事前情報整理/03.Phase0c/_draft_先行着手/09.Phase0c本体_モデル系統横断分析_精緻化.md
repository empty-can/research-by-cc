### §0.3 前提・用語定義

**系統定義（統合一覧 §0.2 / §3 を継承。母数 10 件）**:

| 系統 | AI 識別子 | 系統サイズ |
|---|---|---|
| Claude 系 (C) | #07, #16, #18, #19, #20 | 5 |
| Gemini 系 (G) | #01, #10, #21 | 3 |
| GPT 系 (P) | #13, #14 | 2 |

**本ドキュメントで導入する用語**:

| 用語 | 定義 |
|---|---|
| **言及率（系統内）** | ある系統内で当該ナレッジに言及した AI 数 ÷ 系統サイズ。Claude 系なら C 言及数 / 5、Gemini 系なら G / 3、GPT 系なら P / 2 |
| **系統横断スコア（CBS: Cross-System Score）** | 3 系統の言及率の単純平均。`(C率 + G率 + P率) / 3`。系統サイズ非対称を正規化した「公平な系統横断性」の指標 |
| **被覆系統数** | 1 件以上の言及がある系統の数（0〜3）。構造的信頼性の段階を決める |
| **系統集中度（CR: Concentration Ratio）** | 最大系統の生言及数 ÷ 統合言及数。1.0 = 単一系統集中、低いほど分散 |

> **注意**: 言及率・CBS・CR はすべて統合一覧 §3 の生言及数（系統スコア C/G/P）から機械的に算出した派生値であり、生言及数自体を改変しない。

## §1 系統サイズ非対称性の正規化（言及率指標）

### §1.1 正規化の必要性

統合一覧 §3 は「系統別の生の言及数（C 言及数 / G 言及数 / P 言及数）」を可視化しているが、系統サイズが C=5 / G=3 / P=2 と非対称なため、生言及数同士の単純比較は系統間で歪む。

具体例:
- あるナレッジが「C=2, P=2」だった場合、生の数は同じ 2 だが、**意味は大きく異なる**。Claude 系では 5 件中 2 件（40%）の支持に過ぎないが、GPT 系では 2 件中 2 件（100% = 全 GPT 系が言及）である。
- 「全 GPT 系が言及」は GPT 系内での合意が強いことを示すが、生言及数 2 だけを見ると過小評価される。

そこで **系統内言及率（系統サイズで正規化した支持割合）** を導入し、系統間で公平に比較できる土台を整える。

### §1.2 言及率の定義

```
C 言及率 = C 言及数 / 5
G 言及率 = G 言及数 / 3
P 言及率 = P 言及数 / 2
系統横断スコア（CBS） = (C 言及率 + G 言及率 + P 言及率) / 3
```

CBS は 0.0〜1.0 の値を取り、**3 系統すべてで全員が言及すると 1.0**、いずれかの系統で支持が薄いと低下する。生の統合言及数と異なり、母数の大きい Claude 系に引っ張られない。

## §2 系統重複（redundancy）の検出

### §2.1 redundancy 検出の考え方

統合言及数 N が高くても、その言及がすべて単一系統内から来ていれば、独立性は見かけ倒しの可能性がある。同一系統の AI は学習データ・調査経路・バイアスを共有しやすいため、**「同じ情報源を別の口で繰り返している（redundant）」状態と、「独立に複数系統が到達した」状態を区別する必要がある**。

検出指標として **系統集中度（CR: 最大系統の生言及数 / 統合言及数）** を用いる。CR=1.0 は全言及が単一系統に集中していることを示し、信頼性の割り引き候補となる。

### §2.2 統合言及数は高いが単一系統集中のナレッジ（信頼性割引候補）

統合一覧 §2.4（中信頼性 4-6 件）・§2.5（低信頼性 2-3 件）から、**統合言及数が 2 以上ありながら CR=1.0（単一系統集中）** のナレッジを抽出する。これらは「複数 AI が言及している」という見かけの信頼性に対し、系統独立性の裏付けが弱く、**系統固有バイアスの可能性を割り引くべき候補**である。

### §2.3 系統集中度（HHI 類似指標）による補強

CR（最大系統集中率）に加え、分散の度合いを見るために系統別言及数の偏りを概観する。統合言及数が同程度でも CR が大きく異なるペアを示す:

| ペア | 統合言及数 | 系統スコア | CR | 解釈 |
|---|---|---|---|---|
| パストラバーサル vs NIST AI RMF | 共に 5 | C2/G2/P2 vs C4/G0/P1 | 0.40 vs 0.80 | パストラバーサルは完全分散（CR最小0.40）、NIST AI RMF は Claude 系集中（CR0.80）。同じ「5」でも独立性は前者が圧倒的に高い |
| OWASP ASVS vs eslint-plugin-security | 5 vs 6 | C3/G0/P2 vs C4/G1/P1 | 0.60 vs 0.67 | ASVS は Gemini 系ゼロだが GPT 系全員。eslint は 3 系統分散だが薄い |

**含意**: 統合言及数が同値でも CR で頑健性を層別できる。**CR=1.0 のナレッジ群（§2.2 の表）は、統合言及数による信頼性区分から一段割り引いて扱うべき候補**である（確定はしない。§5 の提案・判断 2 で扱う）。

## §3 構造的信頼性の段階整理

### §3.1 3 段階の定義と頑健性解釈

被覆系統数（言及がある系統の数）で 3 段階に整理する。これは統合一覧 §2.1 の「言及数による区分」とは独立の軸であり、**系統固有バイアスへの頑健性**を表す。

| 段階 | 被覆系統数 | 頑健性解釈 |
|---|---|---|
| **段階 I: 系統横断** | 3 | 3 系統すべてで独立言及。学習データ・調査経路の系統固有バイアスを最も受けにくく、構造的に最も頑健。1 系統が偏っても他 2 系統が補正する |
| **段階 II: 2 系統言及** | 2 | 2 系統で言及。1 系統の欠落があり、欠落系統の固有バイアス（その系統だけが「知らない」possibility）が残る。中程度の頑健性 |
| **段階 III: 単一系統** | 1 | 1 系統のみ。系統固有バイアス・ハルシネーションの可能性を最も排除しにくい。独立検証が必須 |

**頑健性の原理**: 段階 I は、ある系統が特定ナレッジを過大／過小に扱う固有バイアスを持っていても、他 2 系統の独立到達がそれを相殺する。段階 III は相殺機構が一切働かず、その系統の偏りがそのまま結論に乗る。これが「系統横断 = 最も頑健」の構造的根拠である。

統合一覧 §3.1 / §3.2 および §2 系列から、主要ナレッジを段階別に分類する（CVE 個別の単一言及群は §2.6 の件数で代表）。

| **段階 I（3 系統）** | 3 | OWASP LLM Top 10 / Bandit / Semgrep / Trivy / pip-audit / CWE / MITRE ATLAS / eslint-plugin-security / SSRF / サプライチェーン攻撃 / パストラバーサル / CVE-2025-49596 / CVE-2025-68143〜145 / ツールポイズニング / プロンプトインジェクション | 基礎ツール・普遍的攻撃概念が中心。CVE は 49596 と 68143〜145 のみ |
| **段階 II（2 系統）** | 2 | NIST AI RMF（C+P）/ OWASP ASVS（C+P）/ Anthropic MCP Security Best Practices（C+G）/ mcp-scan（C+G）/ njsscan（C+G）/ CodeQL（C+P）/ mcpserver-audit（C+P）/ Opengrep（C+P）/ OX Security レポート（G+P）/ CVE-2026-21852（C+G）/ CVE-2026-23744（C+P）/ CVE-2026-39861（G+P）| 異系統ペアでの補強。GPT 系を含むペアが標準系の橋渡しになる |
| **段階 III（単一系統）** | 1 | §2.2 の CR=1.0 群（garak / promptfoo / MCP 公式仕様 Security 等の Claude 系集中）+ §2.6 の全単一言及 CVE・ツール・ガイドライン群（trusted-but-malicious / SLSA / ISO 29147 等の GPT 系、VIPER-MCP / Agent Scan 等の Gemini 系）| 系統固有ナレッジ・2026 年 CVE 疑義の大半がここに集中 |

**重要な観察**: 段階 II の CVE（CVE-2026-21852 / 23744 / 39861）はいずれも 2026 年 CVE フラグ付きだが、**異系統 2 つで言及されている**点で、段階 III の単一系統 2026 年 CVE 群より構造的信頼性が一段高い。特に CVE-2026-23744 は GPT 系 2 AI + Claude 系 1 AI（NVD 確認済み）で、2026 年 CVE 群の中では最も頑健（統合一覧 §2.5 の評価とも整合）。

### §3.3 系統横断と単一系統集中の頑健性差の定量裏付け

段階 I のナレッジ群と段階 III（CR=1.0）のナレッジ群を CBS で対比すると、頑健性差が定量的に表れる:

| 段階 | CBS の典型レンジ | 解釈 |
|---|---|---|
| 段階 I（系統横断） | 0.66〜1.00（基礎ツール・概念は 0.89〜1.00、CVE は 0.31〜0.41） | 全系統に支持が分散。CBS が高い |
| 段階 II（2 系統） | 0.43〜0.53（NIST AI RMF / OWASP ASVS 等） | 1 系統欠落で CBS が中域に低下 |
| 段階 III（単一系統集中） | 0.13〜0.27（§2.2 の Claude 系集中群） | 単一系統のみのため CBS が構造的に低い（上限が 系統サイズ/3 で頭打ち） |

**定量裏付けの要点**: 段階 III の CR=1.0 ナレッジは、統合言及数が 4（garak/promptfoo）でも CBS は 0.27 に留まる。一方、段階 I のパストラバーサルは統合言及数 5 で CBS 0.69。**「統合言及数 4 の段階 III」より「統合言及数 5 の段階 I」が頑健性で明確に上回る**ことが CBS により数値で示される。これは「系統横断は系統固有バイアスを受けにくく最も頑健」という定性的解釈の定量裏付けとなる。

> **CVE の段階 I が低 CBS である点の注釈**: 段階 I の CVE（49596: CBS 0.31、68143〜145: CBS 0.41）は基礎ツール群より CBS が低い。これは「3 系統に被覆されているが各系統内では少数の AI しか言及していない」状態を示す。被覆系統数（段階 I）と言及率（CBS）は別観点であり、CVE は「広く薄く」型、基礎ツールは「広く厚く」型と層別される。

## §5 信頼性スコアへの系統重み付け接続（提案レベル）

### §5.1 提案の位置付け

統合一覧 §3 冒頭の注記「並行作業 C §5.2 の重み付け方針との接続」を受け、系統横断性を信頼性スコアに反映する重み付けの考え方を **提案として** 整理する。

> **重要（確定しない）**: 本節は作業指示者の **判断 2「信頼性スコア方法論の改訂」** で扱う論点への素材提供であり、確定的な方法論ではない。既存の信頼性スコア区分（統合一覧 §2.1）を本ドキュメントで上書きしない。過去バッチの再計算を伴う改訂は判断 2 の決定後に行う。

### §5.2 重み付けの基本アイデア

現行の信頼性スコア（統合一覧 §2.1）は **統合言及数（生の独立言及 AI 数）の単一指標**でランク付けしている。これに対し、本分析が示した課題は次の 3 点:

1. **系統サイズ非対称の歪み**: 生言及数は母数 5 の Claude 系に有利。GPT 系の「全員言及（P率1.00）」が過小評価される（§1）
2. **redundancy の見落とし**: 統合言及数が高くても単一系統集中（CR=1.0）なら独立性が弱い。garak/promptfoo が「中信頼性」に入る過大評価が実例（§2）
3. **構造的頑健性の未反映**: 被覆系統数（段階 I/II/III）が信頼性区分に反映されていない（§3）

重み付けの基本アイデアは、**統合言及数（量）に加えて、被覆系統数（構造的頑健性）と CBS（正規化された系統横断性）を補助指標として組み合わせる**こと。

### §5.3 提案する複合指標（素材）

確定しない前提で、判断 2 の検討素材として 2 案を提示する。

**案 A: 被覆系統数によるボーナス／ペナルティ方式**

- ベースは現行の統合言及数区分を維持
- 被覆系統数 3（段階 I）= 信頼性を 1 段階引き上げ候補
- 被覆系統数 1（段階 III）かつ統合言及数 ≥ 2（= CR 1.0 の redundancy）= 信頼性を 1 段階引き下げ候補
- 利点: 現行区分の連続性を保ちつつ、redundancy 割引と系統横断ボーナスを後付けできる。過去バッチの全面再計算が不要（フラグ付与のみ）

**案 B: CBS を主指標に格上げする方式**

- 統合言及数の代わりに CBS（または CBS と統合言及数の加重和）でランク付け
- 利点: 系統サイズ非対称を根本的に正規化。GPT 系支持を公平評価
- 欠点: 全ナレッジの CBS 再計算が必要（過去バッチ含む）。区分境界の再設計が必要で改訂コストが大きい

| 観点 | 案 A（ボーナス/ペナルティ） | 案 B（CBS 主指標化） |
|---|---|---|
| 改訂コスト | 低（フラグ付与のみ） | 高（全面再計算） |
| 系統非対称の正規化 | 部分的（段階単位） | 完全（言及率ベース） |
| 既存区分との連続性 | 高 | 低（境界再設計） |
| redundancy 検出 | 明示（引き下げルール） | 暗黙（CBS に内包） |

### §5.4 判断 2 への引き継ぎ論点

判断 2（信頼性スコア方法論の改訂）で決めるべき論点を素材として列挙する:

1. **量（統合言及数）と構造（被覆系統数・CBS）のどちらを主指標にするか**（案 A か 案 B か、またはハイブリッド）
2. **redundancy 割引を適用するか**: §2.2 の CR=1.0 群（特に garak/promptfoo の「中信頼性」）を引き下げるか。引き下げる場合の閾値（統合言及数いくつ以上を対象にするか）
3. **系統横断ボーナスの強度**: 段階 I を何段階引き上げるか。CVE のような「広く薄く」型（CBS 低だが段階 I）をどう扱うか
4. **GPT 系小母数（2）の感度問題**: P 率は 1 AI で 0.50、2 AI で 1.00 と粒度が粗い。CBS で GPT 系を過大／過小評価しないための補正要否
5. **2026 年 CVE 疑義との二重割引**: §2.2 の CVE-2026-25536 等は「単一系統集中」かつ「2026 年 CVE 疑義」。両割引を重複適用するか、Phase 1 の実在検証を優先するか

> 上記はいずれも本タスクのスコープ外の確定事項であり、判断 2 の意思決定に委ねる。本ドキュメントは正規化指標（言及率・CBS・CR・被覆系統数）という素材を提供するに留める。
