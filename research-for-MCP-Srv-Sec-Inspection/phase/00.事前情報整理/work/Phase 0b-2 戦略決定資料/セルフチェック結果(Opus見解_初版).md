# セルフチェック結果（Opus 見解 初版）

## 本ファイルの目的・位置付け

- 同フォルダ内の [Phase 0b-2-α 完了報告とPhase 0b-2-β 戦略提案(Opus見解).md](Phase%200b-2-%CE%B1%20%E5%AE%8C%E4%BA%86%E5%A0%B1%E5%91%8A%E3%81%A8Phase%200b-2-%CE%B2%20%E6%88%A6%E7%95%A5%E6%8F%90%E6%A1%88(Opus%E8%A6%8B%E8%A7%A3).md)（以下「提案資料 初版」）の内容について、Opus 自身がセルフチェックを実施した結果を記録する
- セルフチェックの観点は以下:
  - 数値整合（各分布表の合計、各群件数の一貫性）
  - サービス分類の一貫性（同一サービスが複数表で矛盾なく分類されているか）
  - 学習時点の境界値（境界外配置の有無）
  - 自己申告 vs 実態の混在（特に hallucination 含むサービスの位置付け）
  - 観察 → 提案の因果（観察が各群配置の根拠として整合しているか）
  - 表記ゆれ・誤記
- 検出した疑義は以下の 2 区分で整理:
  - **A セクション**: 議論の余地なく明確な修正 → セルフチェック実施時に **即修正済み**
  - **B セクション**: 判断を仰ぐべき疑義 → 提案資料 初版に **未修正のまま** 残し、本ファイルで作業指示者の判断を待つ

## B. 判断を仰ぎたい疑義（提案資料 初版で未修正）

### 疑義 1: 1.2 節の「詳細レベル把握」グループに #14 (OpenAI ChatGPT) を入れた根拠

**現状**: 詳細レベル把握 6 件 (`01 / 14 / 17 / 18 / 19 / 20`)

**疑義の内容**: A 群配置理由には「実装寄りレベル」と書かれているが、Sampling/Roots といった具体プリミティブへの言及は #14 の Q0 回答にはなく、`<mcp-request>` タグ的な誤情報も無いため、Roots/Sampling まで把握しているグループ（#01 / #17 / #18 / #19 / #20）と同列扱いが妥当か疑問。

**執筆時の判断根拠**: #14 の Q0 回答に含まれる「prompt injection 経由 tool abuse / credential leakage / SSRF / multi-hop tool chaining / context poisoning / agentic workflow の権限境界問題」といった **セキュリティ・脅威モデル観点の網羅性** を高く評価し、「実装寄り・設計寄りのレベル」を「詳細レベル」と同義に扱っていた。一方、Roots/Sampling といった具体プリミティブへの言及有無は、グループ分けの基準として **明示的には使っていなかった**（暗黙的に「実装層・セキュリティ観点が網羅されていれば詳細レベル」と扱っていた）。Roots/Sampling の言及有無を厳密な基準とするなら、#14 と #19 / #20 の差は無視できないため、降格が妥当となる可能性がある。

**選択肢**:

- (a) 現状通り「詳細レベル把握」に残す（実装層・セキュリティ観点が網羅されているため）
- (b) 「概要〜中程度の実装詳細」に降格（Roots/Sampling 言及がないため、グループ基準を厳格化）

### 疑義 2: 1.2 節の「概要レベルのみ」に #09 を入れた一方、E 群でもある扱い

**現状**: 概要レベルのみ 3 件 (`06 / 08 / 09`)、E 群（要警戒）2 件 (`09 / 11`)

**疑義の内容**: #09 は **自己申告は「概要レベル」、実態は「誤情報」** という二層構造。「概要レベルのみ」グループに分類すると「正しく概要を把握している」ような印象を与え、観察 1（古い + ハルシネーション傾向）との論理が見えづらい。

**執筆時の判断根拠**: 1.2 節の表は **AI の自己申告内容に基づく分類** として書いていた（暗黙的にそう扱っており、節の見出しや表ヘッダーには明示していなかった）。一方、E 群配置（2.2 節）は **実態の誤情報を含むかどうか** を基準にしており、両者は異なる軸を見ている。執筆時はこの二軸の使い分けを意識していたつもりだったが、節構成上は明示できていなかった。なお #11 は「概要レベルのみ」ではなく「キーワード断片〜限定的」グループに入っているが、これは **#11 の自己申告ベースで判断するなら本来「詳細レベル把握」相当**（仕様概要・主要コンポーネント・リクエスト/レスポンス形式・公開情報源・脆弱性既知問題の表組み列挙まで含む）であり、実態として詳細表組み内容が hallucination だったため、執筆時は無意識に「実態判断」へ寄せて低い分類にしてしまった可能性がある。つまり #09 と #11 で **自己申告基準と実態基準を無自覚に使い分けてしまった** という不整合がある。

**選択肢**:

- (a) 現状通り（自己申告ベースの分類なのでこの位置で OK と割り切る）
- (b) 1.2 節に **「（自己申告ベース）」** の注記を追加し、誤情報含むものは別途明示
- (c) 1.2 節から #09 / #11 を **「自己申告と実態に乖離あり」枠** として独立分離

### 疑義 3: 観察 1 の「学習が新しい + MCP 知識「有」 → 自己警告で正直」

**現状**: 「#18 / #20 が最も顕著」とのみ言及

**疑義の内容**: 同じ 2026-01 学習の #19 にも本来同じ性質があるはず（Q0 回答で「個別 CVE は不確実」と自己申告）。なぜ #19 が観察対象から外れているか説明がない。

**執筆時の判断根拠**: 「最も顕著」を選ぶ際、#18 / #20 の Q0 回答が **「比較的しっかり把握 / 中程度 / 低い・不確実」の 3 段階自己区分** という構造化された自己警告だったのに対し、#19 の自己申告は構造化ではなくテキスト形式だった点を無意識に重視していた。ただし #19 も「個別 CVE は不確実」という自己警告自体は同等に含んでおり、「顕著」基準を「自己警告の有無」に置くなら #19 も含めるべき、「顕著」基準を「自己警告の構造化度合い」に置くなら現状でよい、という二択になる。執筆時はこの基準を明示的に決めていなかった（暗黙的に構造化度合いで選んでいた）。

**選択肢**:

- (a) 観察 1 に #19 も追加（`#18 / #19 / #20 が最も顕著`）
- (b) 現状維持（#19 は学習時点揺れ a/b があるため、純粋な観察対象から外したい意図があれば残す）

### 疑義 4: 観察 4 の Gemini 系で #08 が「概要のみ」と表現

**現状**: `#08 Gemini 3.0 Pro: 2024 数ヶ月前 + 検索併用、概要のみ`

**疑義の内容**: 1.2 節では #08 は「概要レベルのみ」グループだが、Q0 回答実物は「事前学習単体では概要レベル、検索補完前提で詳細可能」と申告している。「検索併用前提なら詳細も可能」という二層性が観察 4 から欠落。

**執筆時の判断根拠**: 観察 4 では Gemini 系内の **「事前学習単体での解像度」** を比較軸にしていた（`#10 が最良の比較基準` と書いた際、#10 は検索併用なし環境での自己申告であるため、同一基準で揃えていた）。一方 1.2 節も同じ「事前学習単体」基準で「概要レベルのみ」と分類しているため、観察 4 の表現は 1.2 節と整合してはいる。ただし、観察 4 の表記が短すぎて「検索併用前提では別の解像度になる」という重要情報が読み取れず、表記の **省略** が問題と言える。なお観察 2（Web 検索併用の有無による回答品質差）で #08 は検索併用型として登場しており、検索併用前提の補完能力には別途言及があるため、観察 4 はあえて事前学習単体での比較に絞っていた、という整理も可能。

**選択肢**:

- (a) 観察 4 の #08 行を `2023 末〜2024 数ヶ月前 + 検索併用、事前学習単体は概要のみ・検索補完で詳細可能と自己申告` に書き換え
- (b) 現状維持

### 疑義 5: 2.1 節の運用方針「Q1〜Q6 未実施」と「採用判定: 不採用」の整合

**現状**: D 群「採用判定: 不採用 / 運用方針: Q1〜Q6 未実施」

**疑義の内容**: 採用判定 = 不採用なら、運用方針列に「Q1〜Q6 未実施」と書くのは情報重複。一方 E 群は「採用 / 全 Q1〜Q6 実施 / 信頼性スコアの負例」と 3 セルが情報をもっており、D 群との対称性が崩れている。

**執筆時の判断根拠**: 各列を **「採用判定 = Q1〜Q6 を実施するかしないか」/「運用方針 = どう実施するか」/「信頼性スコア集計上の位置付け = 集計時にどう扱うか」** という 3 段階の意思決定として設計していた。この設計の下では、不採用 → 運用方針なし、というのが論理的に整合する（運用方針は採用前提の概念）。執筆時に「未実施」と書いてしまったのは、表が空欄になるのを避けたい無意識の動機が働いた可能性がある。一方、Q0 集計表（正本）の「運用方針」列には D 群相当のサービスでも「（実施しないため運用方針なし）」のような文言ではなく、より具体的な内容を書く運用にしているため、対称性を揃える場合は本提案資料と Q0 集計表の両方で同じ書き方にする必要がある。

**選択肢**:

- (a) 現状維持（明示的に書いてある方が分かりやすい）
- (b) D 群の運用方針を `（実施しないため運用方針なし）` 等に簡略化
- (c) E 群と同じ詳細度に揃え、D 群運用方針を `Q0 結果のみ信頼性スコア集計の学習時点フィルタ素材として利用` に書き換え

### 疑義 6: 2.3 節の実施順 4 と 5 の順序

**現状**: 「4. E 群 2 件を最後に実施」「5. D 群 4 件はスキップ」

**疑義の内容**: 番号順だと「最後に実施」よりさらに後の番号が「スキップ」となっており、時系列の順序付けが破綻している（スキップは時系列の最後ではなく、実施しない選択肢）。

**執筆時の判断根拠**: 番号付きリストを **「優先度の低い順に並べる」** という意図で書いていたが、リスト内に「実施しない」項目を混在させたことで時系列との両立が崩れた。執筆時、D 群はスキップだから単純に最下位に置けばよい、と無意識に判断していた。実態としては「実施対象 (A〜C / E)」と「非実施対象 (D)」は **異なる軸の情報** であり、同じ番号付きリストで並べるべきではなかった。

**選択肢**:

- (a) 4 と 5 を入れ替え、「4. D 群 4 件はスキップ」「5. E 群 2 件を最後に実施」
- (b) 番号付きリストではなく、実施対象（A〜C / E）と非実施対象（D）を別記載に再構成

### 疑義 7: 4.2 節の追加観察ポイント「#19 の学習時点揺れ」

**現状**: `#19 (Anthropic Sonnet 4.6) の学習時点揺れ（2026-01 / 2025-08）の解明`

**疑義の内容**: 他の観察ポイント 2 件は「Phase 0b-2-γ で観察できる事項」なのに対し、これは **既存の Q0 回答 a/b に含まれている事項** で、Phase 0b-2-γ で新たに観察するわけではない。実態は「Q0 段階で既に観察済みだが、解明できていない疑問」で、別カテゴリの申し送り。

**執筆時の判断根拠**: 4.2 節を「Phase 0b-2-γ 中に注目したい事項」のリストとして構築したつもりだったが、執筆時に「揺れの解明には Q1〜Q6 の追加データが役立つ」という連想が働き、無意識に Phase 0b-2-γ で観察できる事項として位置付けてしまった。実際には **Q0 段階で既に観察済みの事象であり、Phase 0b-2-γ で追加データを取れば手がかりが増える可能性はあるが、Phase 0b-2-γ で初めて観察するわけではない** ため、性質が他 2 件と異なる。執筆時は「観察ポイント」という言葉に対して「(1) これから観察する事項 / (2) 既に観察済みで解明したい事項」の両方を内包させてしまっていた。

**選択肢**:

- (a) 4.2 節から削除し、別の節（例: 4.3「未解明事項」）として独立
- (b) 4.2 節内で「Q1〜Q6 実施中の『〜と思っていたが実は〜だった』を観察」のような形に書き直し、Phase 0b-2-γ 中の追加観察項目として整合させる
- (c) 現状維持
