## 2. 検討の起点: §1 で扱う分類が AI 選定基準としてどの程度重要か

### 2.1 §1 が果たすべき役割

そもそも §1（俯瞰分析）が後続フェーズに対して果たすべき役割は何か、から再度問い直す。

提案資料 初版では §1 を「20 サービスの Q0 結果を網羅的に整理する場」として位置付けていたが、これは **「整理することそのもの」を目的化** していた可能性がある。本来 §1 は、§2（採用判定・運用方針）の **意思決定の根拠** を提供することが目的であり、§2 の意思決定に寄与しない情報は §1 から削除されるべきである。

そこで §2 が必要とする意思決定を逆引きすることで、§1 で扱うべき情報を絞り込む。

### 2.2 §2 が必要とする意思決定の整理

§2 が下す意思決定は以下の 3 つに集約される:

| 意思決定 | 内容 |
|---|---|
| 意思決定 1 | Phase 0b-2-γ で **Q1〜Q6 を実施するか / しないか** |
| 意思決定 2 | 実施する場合、**全 Q1〜Q6 を実施するか / 一部に絞るか** |
| 意思決定 3 | 取得した回答を **信頼性スコア集計の正例として扱うか / 負例として扱うか / 集計対象外とするか** |

各意思決定に必要な判断材料を逆引きすると、§1 で扱うべき情報は以下に集約できる:

| 意思決定 | 必要な判断材料 |
|---|---|
| 意思決定 1 | (1) 学習時点の鮮度、(2) MCP に関する基本的な認識の有無、(3) 自己申告内容の正確性（≒ハルシネーション傾向の有無） |
| 意思決定 2 | (4) 各 Q（特に Q1 の CVE 列挙）に対して有意な回答が期待できるか、(5) 検索併用の有無（Q1 の学習由来 vs 検索由来の切り分け可否） |
| 意思決定 3 | (6) モデル系統（信頼性スコア集計時の系統重複検出のため）、(7) 自己申告の構造化度合い（自己警告の信頼性の指標）、(8) 経由先（同モデルでの Bedrock 経由 vs Anthropic 直の差分抽出） |

### 2.3 §1 で扱うべき情報の絞り込み（仮説）

§1 で扱うべき情報を以下の 4 軸 + α に絞ることを提案する。

#### 必須軸（4 軸）

| # | 軸 | §2 への寄与 | 重要度の根拠・仮説 |
|---|---|---|---|
| 軸 1 | 学習時点 | 意思決定 1・2 | MCP 自体が 2024-11 公開のため、学習時点が古い AI は Q1 の回答が学習データから出ない（仕様上の限界）。判断 1 に直接寄与 |
| 軸 2 | MCP 知識の正確性 | 意思決定 1・3 | MCP 認識の有無が「無 / 誤解釈」の場合、回答全体が不採用または負例素材としての扱いに直結。判断 1・3 の根拠 |
| 軸 3 | 検索併用の有無 | 意思決定 2・3 | 学習データに無い情報を検索で補完する AI は、Q1 の回答が学習由来か検索由来か区別できないため、回答の信頼性スコア集計時に補正が必要 |
| 軸 4 | モデル系統 | 意思決定 3 | 同系統 AI（特に Claude 系 7 種）が独立 N 票でなく系統重複を含む可能性があるため、信頼性スコア集計時の層別化に必須 |

#### 補助軸（必要に応じて）

| # | 軸 | §2 への寄与 | 重要度の根拠・仮説 |
|---|---|---|---|
| 軸 5 | モデル提供形態 | 意思決定 1（補助） | オンライン継続更新型 / スナップショット固定型の差は、学習時点の単独情報を超えた回答鮮度の補足情報となるが、軸 1（学習時点）でほぼカバーされるため補助的 |
| 軸 6 | 経由先（Bedrock / Anthropic 直 / 等）| 意思決定 3（補助） | 同モデルの経由先差の抽出に使うが、特定の Phase 0b-2-γ 観察ポイントとして使う以上の意義は限定的 |

#### 削除候補

提案資料 初版で扱っていた以下の情報は、§2 への寄与が乏しいため §1 から削除を提案する:

- **MCP 知識解像度の細分類**（「詳細レベル把握 / 概要〜中程度の実装詳細 / 概要レベルのみ / キーワード断片〜限定的 / 誤解釈」の 5 段階）
  - 削除理由: §2 の意思決定で必要なのは「無 / 誤解釈」かそれ以外か、の二値判断であり、5 段階の細分類は §2 で使われていない（提案資料 初版でも、§2 で実際に判断に使ったのは「Roots/Sampling 言及の有無」のような個別事項であって、5 段階分類ではなかった）
  - 代替: 軸 2「MCP 知識の正確性」として「有 / 誤情報含む / 無 / 誤解釈」の 4 値分類に簡素化（次節 3 章で定義）

### 2.4 「不要な分類を設けない」観点での再設計の利点

提案資料 初版のセルフチェック結果で発生した疑義 1〜3 は、5 段階の細分類を作ったことで「詳細とは何か」「概要とは何か」の境界線が曖昧になったことに起因していた。軸 2 を 4 値（しかも各値の判断基準が単純）に簡素化することで、これらの疑義は構造的に発生しなくなる。

つまり §2 に寄与しない不要な分類を削除することは、**疑義 1〜3 の根本解消** にも繋がる。

## 3. §1 で扱うべき分類軸の定義

### 3.1 軸 1: 学習時点

| 項目 | 内容 |
|---|---|
| 取得方法 | Q0 自己申告から転記 |
| 表記形式 | `YYYY-MM`（例: `2024-06`）または `継続更新型` |
| 補足項目 | 検索併用前提の場合は併記（例: `2024-06 + 検索併用`）|
| §2 への利用 | 意思決定 1 で「2024-11 以降を含むか」を判断軸とする（MCP 公開 2024-11 が境界）|

### 3.2 軸 2: MCP 知識の正確性

| 値 | 定義 | §2 への利用 |
|---|---|---|
| `有` | Anthropic の MCP として正しく認識し、Q0 回答内容に明らかな誤情報を含まない | 意思決定 1: 採用候補 |
| `誤情報含む` | Anthropic の MCP として認識しているが、Q0 回答内容に実 MCP 仕様と矛盾する具体的内容を含む（XML 風タグ・存在しないリソース・実在しない数値仕様等）| 意思決定 1: 負例として採用候補 |
| `無` | MCP 自体は認識しているが、内容の解像度が極めて低い（キーワード断片レベル、または「概要レベルすら不確か」と自己申告）| 意思決定 1: 不採用候補 |
| `誤解釈` | Anthropic の MCP ではなく、別の意味（Minecraft Control Panel 等）として解釈している | 意思決定 1: 不採用候補 |

判断時の留意事項: 自己申告内容の正確性は、提案資料 初版執筆時点で **作業指示者と Opus が一次情報（MCP 公式仕様）を参照可能な範囲** で判断する。Phase 0c の裏取り段階で判断が変わる可能性は許容する。

### 3.3 軸 3: 検索併用の有無

| 値 | 定義 | §2 への利用 |
|---|---|---|
| `併用` | Q0 回答時点で「検索を併用できる」または「検索で最新情報を補完可能」と自己申告 | 意思決定 2: Q1 回答の学習由来 vs 検索由来の区別不能であることを前提に評価 |

| `不明` | Q0 回答から判定できない | 意思決定 2: Q1 実施後の回答内容（検索由来情報の混入有無）から判定 |

### 3.4 軸 4: モデル系統

## 4. §1 で扱う観察事項の取捨選択

### 4.1 観察事項とは何か（位置付けの整理）

提案資料 初版の §1.4 では「重要な観察」として 4 件を記載していたが、これらの位置付けが曖昧であり、§2 の意思決定にどう寄与するかが明示されていなかった。

そこで観察事項を以下の 2 種類に整理する:

- **観察種別 A**: §2 の意思決定に直接寄与する観察（§2 で判断材料として参照するため §1 に残す）
- **観察種別 B**: §2 の意思決定に直接寄与しないが、Phase 0c の信頼性スコア集計時に活かせる可能性のある観察（§1 ではなく Phase 0c の作業計画に申し送る）

### 4.2 提案資料 初版の各観察事項の再評価

| 観察 | 内容 | 提案する位置付け |
|---|---|---|
| 観察 1 | 学習時点とハルシネーションの相関 | **観察種別 A**（軸 2 の判断時の補強情報。残すべき）|

| 観察 3 | Claude Code 6 種の学習カットオフ階段 | **観察種別 B**（系統内の鮮度差は Phase 0c の系統内層別化に寄与するが §2 の意思決定では未使用）|

- **観察 1・2 を §1 に残す**（観察種別 A、§2 の判断材料として）

## 5. 不足情報の扱いに関する考察と推奨案

作業指示者返答 #01 の実施判断 No.2 への対応として、不足情報のインパクト評価から考察を組み立てる。

### 5.1 不足情報の一覧と Phase 0b-2-β への影響度評価

| 不足情報 | Phase 0b-2-β（採用判定）への影響度 | 影響内容 |
|---|---|---|
| #10 の Web 検索併用可否 | **小〜中** | #10 の採用判定（A 群か B 群か）に影響するが、#10 は学習時点・MCP 知識ともに採用候補レベルであり、検索併用の有無で「採用 / 不採用」の境を跨ぐことはない |
| Sonnet 4.6 の真の学習カットオフ（#19 の a/b 揺れ）| **極小** | #19 自体は採用候補レベルが確定しており、揺れの解明は Phase 0c の信頼性スコア集計に活きる程度（Phase 0b-2-β の意思決定には不要）|
| 同一モデル（Opus 4.7）の Bedrock 経由 vs Anthropic 直の差 | **極小** | #18 / #20 ともに採用候補レベルが確定しており、Phase 0b-2-β の意思決定では差分が問題にならない |
| Web 検索併用の自発的言及（学習由来 vs 検索由来の切り分け）| **小〜中** | 軸 3「検索併用の有無」が Q0 で「不明」となった AI（#02 / #06 / #11 / #12 / #15-#20 等）の判定に影響するが、Phase 0b-2-β の意思決定 2（一部 Q に絞るか）の判断材料として使うのは Phase 0b-2-γ 実施後でも遅くない |

### 5.2 §1 での不足情報の扱い方の選択肢候補

不足情報がいずれも Phase 0b-2-β の意思決定への影響度が **「小〜中」または「極小」** に留まることから、§1 での扱い方は以下の 3 案に絞られる:

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| 案 X | §1 で「不足情報あり」と明記し、Phase 0b-2-β の意思決定を限定的に書く（Phase 0b-2-γ 完了後の再判断を前提にする）| 透明性が高い、判断の限界が明示される | Phase 0b-2-β の意思決定が中途半端になる可能性 |
| 案 Y | §1 で不足情報を Phase 0b-2-γ 中の追加観察ポイントとして申し送り、Phase 0b-2-β の意思決定は **不足情報を仮置き** で進める | Phase 0b-2-β がスムーズに完了する、判断ミス時のリカバリ余地もある | 仮置き判断の精度が低い場合、Phase 0b-2-γ で大幅な見直しが発生するリスク |
| 案 Z | §1 で不足情報を取得するための **Q0 追加質問（Q0.ex）** を全 AI に投げる | 不足情報を完全に解消した上で Phase 0b-2-β を進められる | 追加質問のコストが大きい、Phase 0b-2-α 完了が遅れる |

### 5.3 推奨案

**案 Y を推奨**。

理由:

- 不足情報のインパクトが Phase 0b-2-β の意思決定に対して「小〜中」または「極小」に留まる以上、案 Z の追加質問コストを払うのは過剰投資である
- 案 X は判断の透明性が高いが、Phase 0b-2-β を「限定的な意思決定」で完了させると、Phase 0b-2-γ 着手時に再度意思決定が必要になり、二度手間になる
- 案 Y であれば、Phase 0b-2-γ 中の追加観察で不足情報を補完しつつ、Phase 0b-2-β の意思決定は仮置きで完了させ、Phase 0b-2-γ 完了時に必要なら再判断する、というフローが最も効率的

ただし、Phase 0b-2-β の意思決定で **「仮置きの不足情報が判断を左右する境界ケース」** が出た場合は、案 X（限定的な意思決定）への切り替えを検討する余地を残す。
