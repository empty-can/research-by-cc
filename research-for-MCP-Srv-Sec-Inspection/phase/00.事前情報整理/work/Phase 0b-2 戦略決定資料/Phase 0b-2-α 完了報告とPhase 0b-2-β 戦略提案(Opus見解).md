### 1.4 重要な観察

#### 観察 1: 学習時点とハルシネーションの相関

- 学習が **古い** + MCP 知識「有」と申告 → ハルシネーション傾向（#09 / #11）
- 学習が **新しい** + MCP 知識「有」 → 自己警告で正直（#18 / #20 が最も顕著）

#### 観察 2: Web 検索併用の有無による回答品質差

- 検索併用型（#01 / #02 / #08 / #13 / #14）は学習時点が古めでも MCP 知識を補完できている
- API/CLI 経由型（#03〜#07 / #09 / #10〜#12 / #15〜#20）は学習データのみで勝負

#### 観察 3: Claude Code 6 種の学習カットオフ階段

- Claude Code 系 (#15〜#20) において、4.5 (2025-01) → 4.6 (2025-05〜2025-08) → 4.7 (2026-01) の段階的進化
- バージョン進行と学習時点が **強相関** → 系統内層別化が機能する
- #18 と #20 はカットオフ・系統が同一のため、**Bedrock 経由 vs Anthropic 直の経由先差** が抽出できる純粋な比較実験になる
- なお #07 (AWS Bedrock の Claude 4.5 Sonnet・API 経由) は 2024-08 で、同じ 4.5 Sonnet の Claude Code 版 (#15: 2025-01) とカットオフが異なる。Claude Code 化に伴う追加学習または別ベースモデル系統の可能性

#### 観察 4: Gemini 系 4 種は学習時点・解像度のばらつきが大きい

- #01 Google AI モード: 2025 年初頭 + 検索併用、詳細把握
- #08 Gemini 3.0 Pro: 2024 数ヶ月前 + 検索併用、概要のみ
- #09 Gemini 2.5 Pro: 2023 年初頭、有と申告するも誤情報
- #10 Gemini 3 Flash: 2024 中盤、JSON-RPC 2.0 把握

→ Gemini 系内では **#10 が最良の比較基準**、#09 が最良の負例素材。

## 3. 作業指示者へ判断をお願いしたい論点

### 論点 1: E 群（#09 / #11）の扱い

**現状提案**: E 群「要警戒・素材化のみ」として全 Q1〜Q6 を実施し、信頼性スコアの **負例** として活用。

**代替案**:

- (a) 提案通り E 群として実施（負例検証の精度向上に寄与、ただし実施コストはかかる）
- (b) D 群に統合（実施コスト削減、ただし「詳細申告したのに誤情報」という珍しい挙動の検証機会を失う）
- (c) E 群は **Q1 のみ実施**（CVE 列挙のハルシネーション検証には Q1 だけで十分、他 Q は省略）

### 論点 2: 旧バージョン（#15 Bedrock Sonnet 4.5 / #17 Bedrock Opus 4.5）の扱い

**現状提案**: B 群（通常運用・補助）として全 Q1〜Q6 を実施し、新バージョンとの差分を抽出。

**代替案**:

- (a) 提案通り B 群として実施
- (b) 当初方針通り「優先度: 低」を維持、時間に余裕がある場合のみ実施
- (c) Q1 のみ実施（CVE 列挙のバージョン差分が最も顕著に出る項目に絞る）

### 論点 3: D 群（#03 / #04 / #05 / #06）の Q0 結果の扱い

**現状提案**: 不採用として Q1〜Q6 はスキップ。Q0 結果は信頼性スコア集計の **学習時点フィルタ** の素材としてのみ利用。

**代替案**:

- (a) 提案通りスキップ
- (b) #05 のみ「Minecraft 誤解釈」の負例として E 群相当に格上げ
- (c) 全件 Q1〜Q6 実施（取得コストはかかるが、Phase 0c で「学習が古い LLM の典型的な回答パターン」を確認する素材になる）

### 論点 4: C 群の運用方針

**現状提案**: Q1 をスキップして Q2〜Q6 のみ実施。

**確認事項**:

- Q1 スキップとした場合、AI への質問の流れに不自然さが生じる可能性。**Q1 を「概念質問のみ」に短縮した文面で実施** する代替案も検討候補
- 例: 「**MCP サーバの脆弱性事例として、CVE 番号や URL ではなく、概念レベル・カテゴリレベルでどのような懸念があるかを教えてください**」のような短縮版
