### 1.2 論点 2（軸 2「MCP 知識の正確性」の 4 値定義）への応答

3 つの観点に分けて応答します。

#### 1.2.1 論点 2-a: 値ラベルの再配置

ご指摘の通り、Opus 見解 2nd §3.2 の値ラベル定義に **不整合がありました**。修正案として以下の再配置を採用します。

| 旧（Opus 見解 2nd）| 新（本ファイルで確定）| 定義 |
|---|---|---|
| `有` | `有` | Anthropic の MCP として正しく認識し、Q0 回答内容に明らかな誤情報を含まない |
| `誤情報含む` | `誤情報含む` | Anthropic の MCP として認識しているが、Q0 回答内容に実 MCP 仕様と矛盾する具体的内容を含む（XML 風タグ・存在しないリソース・実在しない数値仕様等）|
| `無`（旧）| **`低`**（新）| MCP 自体は認識しているが、内容の解像度が極めて低い（キーワード断片レベル、または「概要レベルすら不確か」と自己申告）|
| `誤解釈`（旧）| **`無`**（新）| Anthropic の MCP ではなく、別の意味（Minecraft Control Panel 等）として解釈している、または MCP 自体を認識していない |

**意味的な妥当性**: 「無」は「該当の知識自体が無い」を意味するべきであり、「低解像度だが認識している」は「低」、「別物として解釈している」は「正しい MCP の知識が無い」=「無」と扱うのが自然。ご指摘通りで反映します。

#### 1.2.2 論点 2-b: 「負例として採用候補」の意味明確化

「負例として採用候補」という表現が伝わりにくかった点、お詫びします。Opus 見解 2nd 執筆時に意図していた意味は以下です:

> 軸 2 = `誤情報含む` の AI は、Q0 自己申告に誤情報を含むため **「採用」して回答内容を信頼性スコアの正例として扱うことは不可** だが、Phase 0b-2-γ で Q1〜Q6 を実施し、**「LLM 回答にこのような誤情報が紛れ込むサンプル」として収集することで、Phase 0c の信頼性スコア集計時に「ハルシネーション検出フィルタの精度評価素材」として活用できる**。この用途を指して「負例として」と呼んだ。

確かに「採用候補」と書くと「信頼できる回答として採用」と読めてしまうため、本ファイル §2 以降の §1 改訂版および後続の §2 改訂では **「採用（負例素材として）」または「不採用扱いだが負例素材として Phase 0b-2-γ で実施」** のような明示表現に書き換えます。

**確認したい論点**（§5 論点 2 で再度問います）: 上記の運用意図自体に問題ないか（「誤情報を含む AI の Q1〜Q6 を実施するコストを払う価値があるか」のご判断）。

#### 1.2.3 論点 2-c: 「意思決定 1: 不採用候補」表現の意図

> 「意思決定 1: 不採用候補」と表現しているのは、あくまで採用不採用の決定は§2で実施するものであるためこの表で断言を敢えて避けている、ということでしょうか？

Opus 見解 2nd §4.3 で「観察 3 を Phase 0c に申し送る」と整理しました。作業指示者返答にて「その情報をどのように活かすことができるのか？の検討も含めて」申し送る必要があるとのご指示を受け、申し送り内容と活かし方を以下に整理します。

### 3.1 観察 3 の内容（再掲）

Claude Code 6 種（#15〜#20）において、4.5 (#15: 2025-01) → 4.6 (#16: 2025-08) → 4.7 (#18: 2026-01) の **段階的な学習カットオフ階段** が存在する。バージョン進行と学習時点が強相関しており、系統内層別化が機能する構造を持つ。加えて、#18 (Bedrock Opus 4.7) と #20 (Anthropic Opus 4.7) はカットオフ・系統が同一のため、**経由先（Bedrock 経由 vs Anthropic 直）の差** を抽出する純粋な比較実験になる。さらに #07 (AWS Bedrock の Claude 4.5 Sonnet・API 経由、2024-08) は同じ 4.5 Sonnet の Claude Code 版 (#15: 2025-01) とカットオフが異なるため、**Claude Code 化に伴う追加学習** または別ベースモデル系統の可能性を示唆。

### 3.2 Phase 0c での活かし方の検討

観察 3 は §2（採用判定・運用方針）の意思決定では直接使用しないが、Phase 0c の **信頼性スコア集計** において以下のように活用できる。

| 活かし方 | 概要 | Phase 0c の作業に与える効果 |
|---|---|---|
| 系統内バージョン層別化 | Claude 系 7 種を「ベースモデル × バージョン × 経由先」の三次元で層別化し、各層内で言及数を集計 | 単純な「N LLM 言及 = 信頼度高」を回避し、系統内重複バイアスを補正できる |
| 経由先差分の抽出 | #18 (Bedrock Opus 4.7) と #20 (Anthropic Opus 4.7) の Q1〜Q6 回答差分を分析 | 同モデルでの Bedrock 経由特有の挙動（再学習・チューニング差等）の有無を検証できる |
| Claude Code 化差分の抽出 | #07 (Bedrock Claude 4.5 Sonnet API 経由) と #15 (Claude Code 化 Sonnet 4.5) の Q1〜Q6 回答差分を分析 | Claude Code 化に伴う追加学習の有無を検証でき、Claude Code 系を「Claude 系の独立サブカテゴリ」として扱うべきかの判断材料になる |
| バージョン進行軸での回答進化分析 | 4.5 → 4.6 → 4.7 の同経由先でのカットオフ階段における回答内容変化を時系列で観察 | MCP 仕様の認識深度がバージョンと連動して進化することを検証でき、Phase 6（継続運用）で「新モデル登場時にどの程度信頼性スコア再評価が必要か」の運用基準の根拠になる |

### 3.3 Phase 0c 着手前に整備すべき準備

上記の活かし方を Phase 0c 着手時に即座に着手するため、以下を Phase 0b-2-γ 完了時点で整備しておくことを推奨します。

- Claude 系 7 種の Q1〜Q6 回答を **「ベースモデル × バージョン × 経由先」で索引できる形式** に整理（Q0 集計表の拡張または別シート）
- #18 vs #20 / #07 vs #15 の **差分比較対象ペア** を Phase 0c 作業計画に明示
- バージョン階段（4.5 → 4.6 → 4.7）の **時系列比較対象シーケンス** を Phase 0c 作業計画に明示

## 4. Phase 0b-2-γ への追加確認方法の提案（Web 検索併用可否判定）

作業指示者返答 §4 のご指示「Web 検索併用可否について、学習年月日に存在しなかった情報を質問し、回答を以って判断する」を Phase 0b-2-γ に組み込むための **動作検証質問** を提案します。

### 4.1 動作検証質問の基本設計

| 項目 | 案 |
|---|---|
| 質問対象 | 軸 3 が `不明` の 16 サービス（および「併用」自己申告の 4 サービスも念のため再確認）|
| 質問タイミング | Phase 0b-2-γ の **冒頭**（Q1 投入前）。先に動作検証で軸 3 を確定させてから Q1 以降に進む |
| 質問内容 | AI の自己申告学習時点よりも **明らかに後** の時点に発生した、かつ **存在自体が一次情報で確認可能** な事象について質問。学習データに無い情報を出力するなら検索由来と確定できる |
| 質問パターン | 各 AI の学習時点に応じて 1〜2 パターン用意。原則 **MCP 関連の事象を選ぶ** ことで、本活動の質問項目票全体との文脈一貫性を維持する |

### 4.2 動作検証質問のサンプル文面

**質問サンプル A（学習時点 2024-11 以前の AI 向け）**:

```txt
以下の事象について、知っている範囲で教えてください。情報元が学習データなのか、外部検索なのかも併せて教えてください。

* Anthropic 社が「Model Context Protocol（MCP）」を一般公開した時期（公開のアナウンスがあった年月）
* MCP プロトコルがベースとしている JSON-RPC のバージョン
```

**質問サンプル B（学習時点 2025-06 以前の AI 向け、より新しい事象を質問）**:

```txt
以下の事象について、知っている範囲で教えてください。情報元が学習データなのか、外部検索なのかも併せて教えてください。

* Anthropic 公式の Filesystem MCP Server に対して 2025 年に CVE が割り当てられた件（通称「EscapeRoute」）の CVE 番号と概要
* MCP Inspector に 2025 年に割り当てられた重大な CVE 番号と CVSS 値
```

**質問サンプル C（学習時点 2025-12 以前の AI 向け、最新事象を質問）**:

```txt
以下の事象について、知っている範囲で教えてください。情報元が学習データなのか、外部検索なのかも併せて教えてください。

* Anthropic 社が 2026 年 3 月に発生させたとされる Claude Code ソースコードの意図せぬ公開事象
* 同事象を発端として割り当てられた CVE 番号
```

### 4.3 判定ロジック

| 回答パターン | 軸 3 判定 |
|---|---|
| 「外部検索を使った」と明示し、かつ事実関係の正確な回答を返した | `併用` 確定 |
| 「学習データのみ」と明示し、かつ事実関係を **知らない / 不確実** と返答した | `なし` 確定 |
| 「学習データのみ」と明示し、かつ事実関係を「知っている」と返答したが内容が **不正確（ハルシネーション）** | `なし` 確定（ただし軸 2 もハルシネーション傾向ありに更新）|
| 情報源を明示しないが事実関係の正確な回答を返した | 暫定 `併用`（追加質問で情報源を明示要求）|
| 回答拒否・回答不能 | `不明` のまま継続 |

### 4.4 Phase 0b-2-γ 計画への組み込み案

質問項目票（[02.AI向け事前情報収集質問項目票.md](../../02.AI向け事前情報収集質問項目票.md)）は Phase 0a で凍結済みのため、本動作検証質問は **質問項目票の追加項目ではなく、Phase 0b-2-γ 運用ルールとして規定** する形を推奨します（凍結を解かない）。具体的には:

- [01.活動の概要.md](../../01.活動の概要.md) の「Phase 0b の 3 ステップワークフロー」節を **「Phase 0b-2 の 2 ステップワークフロー」（α 動作検証 → β Q1〜Q6 本実施）に拡張** し、動作検証ステップを明記
- 動作検証質問のサンプル文面（A / B / C）は Phase 0b-2-γ の運用補助資料として別ファイル化（質問項目票本体には記載しない）
