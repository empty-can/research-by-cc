# AI向け事前情報収集質問項目票

## 本質問項目票の運用前提

### 複数 LLM サービスへの同一質問の意図

本質問項目票の質問は、複数の LLM・ChatGPT サービスに **同一質問を投入する** 運用を前提としている。これは:

- LLM 回答の品質には揺らぎがある（同一モデルへの同一質問でも回答品質が変動する）
- 情報の誤りは裏取り検証で判別可能だが、観点の不足は専門家でない限り検知困難

という制約を踏まえ、**異なる LLM・ChatGPT サービスへの回答の重複・差分から、本活動コンテキスト上での重要性ランクの妥当性を確保する** という仮説に基づく運用である。

具体的には、各回答内容について「複数の回答で言及されているか否か」「いくつの LLM・ChatGPT サービスで言及されているか」を信頼性スコアの根拠として扱う。

### Q4 の運用上の特性

「Q4」は他の Q とは性質が異なり、**Q3 の回答内容を受けた追加質問** であるため、**LLM・ChatGPT サービスごとに具体的な質問文面が異なる** 可能性がある。Q4 の参考文面は、ある特定の LLM・ChatGPT サービスへの追加質問の例として参照する。

### 後続フェーズでの本質問項目票の参照想定

本質問項目票は Phase 0（事前情報収集）限定のインプット資料ではなく、本活動全体を貫く **根拠アーティファクト** として後続フェーズでも以下の用途で参照する想定:

| Phase | 参照タイミング・目的 |
|---|---|
| Phase 1（活動憲章整備・計画書 v1.0 作成） | スコープ定義の根拠資料 / Q3-3 の回答を「想定リスク」節の素材として参照 |
| Phase 2（正式情報収集） | 打ち切り基準の精度検証 / 追加質問の設計元として質問構造を踏襲 |
| Phase 3（審査ロジック・基準ドラフト作成） | チェックリスト項目の根拠資料 / Q3-2 の業界基準回答をチェックリスト基盤選定の根拠に |
| Phase 5（実適用） | 説得相手（チームリーダー / マネージャー / 事業責任者）への説明資料の素材 |

このため本質問項目票は **Phase 0a で確定した時点で内容を凍結** し、後続フェーズで内容を変更しない（変更すると Phase 0 で得た回答との整合が崩れ、根拠としての性質を失うため）。


## Q5

```txt
MCP実装例」「MCP Server の脆弱性発覚時のメンテナ・利用者側のインシデント対応の標準的な進め方（脆弱性開示プロセス、利用者通知、パッチ提供等）の規約・慣習」について、何らかの情報を持っていますか？

補足1:
```
