# 用語集

版: v0.4（変更履歴は [【別紙】改訂履歴_用語集](【別紙】改訂履歴_用語集.md)）

本活動の語の正本（用語集）のうち、main とサブエージェントが常に読む核である。活動の CLAUDE.md から読み込む。核に無い語は、詳細（同じフォルダの `【別紙】用語集_詳細.md`）を grep する。

- 新しい語は、使う前に足す
  - 複数の Phase にまたがる語（活動の CLAUDE.md・計画書に出る語を含む）と、今後ほかの Phase の文書に出る見込みのある語は核に、1 つの Phase の文書にだけ出る語は詳細のその Phase の節に置く。1 つの文書にだけ出て、ほかの文書に出る見込みの無い語は載せない
  - 詳細の語を別の Phase の文書で使うようになったら、核へ移す
  - 定義には、本活動で何を指すかを短く書く。似た語との違いは、取り違えが起きうるときだけ書く
  - ID とラベルは、付け方だけを 4 に書き、今ある番号やラベルを並べない
  - 識別子（設定のキー、表と列、フォルダとファイル、HTTP のヘッダ、環境変数などの名前）は載せない。識別子は、それを決める文書の表で、何を表すかを説明する。ほかの文書で使うときは、節の中で初めて出す所に、短い説明か、その表の節への案内を添える（説明の無いまま識別子だけを書かない。2026-11-02 の作業指示者の指示）。cc の変数と属性は仕様別紙で説明する
  - ある文書が別の文書の語を引くだけのときは、引く側を語を使わない書き方に直し、用語集に載せない
- 語を改めたら、旧語を詳細の「改めた語」に残す
- 文書の略称は 7 のものを使う

「詳しくは」は、その語が指すものを詳しく書いた節である（文書は 7 の略称で書く）。

## 4. ID とラベルの付け方

`{…}` は差し込む部分で、`{n}` は数、`{nn}` は 2 桁の数を表す。今ある番号やラベルの一覧と中身は、採番する文書にある。

ID とラベルの使い方（2026-11-02 の作業指示者の承認）:

1. ID は参照のためだけに使う。採番する文書がある事項にだけ付け、ほかの文書で引くときは、節の中で初めて出す所に短い名前を添える（例「J-35（正式リリース物の構成）」）
2. 名前の代わりにラベルを作らない。案・部品・概念には、読めば分かる名前を付ける。比べる間だけ短い記号が要るときは、その文書の中だけで使い、ほかの文書へ持ち出すときは名前に戻す
3. 選択肢の記号は、判断が済んだら中身の名前で書く（「案 1 を採った」ではなく「受信サーバを手で起動する」）
4. 部品・設定・列・フォルダの名前に、ラベルや選択肢の記号を入れない
5. 増減しうる数（件数・行数など）を名前に入れない。名前の一部としての番号（`http2` の 2 など）はよい
6. 新しい ID の形は、使う前にこの節の表に足す。足す前に「5. 紛れやすい記号」の表と照らし、既存の形と同じ形にしない

| 形 | 意味 | 採番する文書 |
|---|---|---|
| `{分野の頭文字}{n}` | 2026-11-02 に名前に改めた旧ラベルで、Phase 1 のまとめが Phase 2 に渡した 2 案に付けたもの<br>分野の頭文字は、保存 S・思考 T・タグ L・画面 D<br>新しく書く文では使わず、3 の名前で書く（旧ラベルと名前の対応は詳細の「改めた語」）<br>今ある文書は、J-35（正式リリース物の構成）の裁定の後に書き換える | まとめの冒頭の「本書で使うラベル」 |

| `Q{n}` | まとめで作業指示者に判断を仰いだ事項 | まとめ §5.1 |
| `P2-{n}` | 進め方で作業指示者に諮った事項。「P2-{n} の {m}」は、その m 番目の事項 | 進め方 §1 |

## 5. 紛れやすい記号

同じ形の記号が、文書や文脈で別のものを指す。取り違えても文が通るので、次の手がかりで見分ける。

| 記号の形 | 見分け方 |
|---|---|
| `S{n}` | 保存を述べる所なら、保存の案の旧ラベル（2026-11-02 に 3 の `SQLite`・`生の受信記録` に改めた）<br>スリム化の規則を引く所なら規則の番号、レビュー報告書の指摘なら SUGGESTION、v2.1 の中なら情報源（`'` を付けたものを含む）<br>後ろにハイフンと 2 桁が続けば割り当て表の行 |
| `D{n}` | 画面を述べる所なら、画面の案の旧ラベル（2026-11-02 に 3 の `自作画面`・`Observable F/W` に改めた）<br>影響調査報告書の §2 と、それを引く所なら影響調査の差分の番号<br>角括弧で囲んだものは 1-4 の出典 |
| `L{n}` | タグを述べる所なら、タグの案の旧ラベル（2026-11-02 に 3 の `即時分類方式`・`事後分類方式` に改めた）<br>後ろにハイフンと 2 桁が続けば割り当て表の行<br>docs や文書の位置を指す所（レビュー報告書の該当箇所など）なら行番号 |
| `T{n}` | 思考を述べる所なら、思考の案のラベル（Phase 2 に渡した 2 案のものは、2026-11-02 に 3 の `transcript 単経路方式`・`transcript・レスポンスボディ二経路併用方式` に改めた）。1-3 §5.1 の V-5 の測定の中なら、測定に使った MCP の tool |
| `P{n}` | ハイフンと数が続けば進め方の諮った事項。ハイフンが無ければ、影響調査報告書の §4 と、それを「VerUP IAR(cc v2.1.xxx) の P{m}」の形で引く所なら計画書の変更、レビュー報告書の指摘なら POSITIVE、組 A §2.1 ならプロセスの分け方の案 |
| `C{n}` | ハイフンと英字が付けば VerUP IAR(cc v2.1.287) の実機の確認。付かなければ、レビュー報告書の指摘（CRITICAL） |
| `R{n}` | ハイフンが付けば v2.1 のリスク。付かなければ、v2.1 と、それを「v2.1 要件」と引く所なら要件、VerUP IAR(cc v2.1.287) §3 とそれを引く所なら再確認が要る事実 |
| `案 {記号}`・`({英大文字})` | J の項を述べる所なら、その J の選択肢（「案」を付けずに記号だけで書く所もある）<br>1-4・まとめ・計画書 Phase 1 の `({英大文字})` は、受信・保存の候補<br>1-3 の v0.2 までとそのレビュー報告書の `案 {n}` は、タグ方式の旧語（詳細の「改めた語」） |
| `{丸数字}` | 前に「問い」があれば、計画書 §1.1 の問い。前に「候補」があるか、作業分類タグの付与方式を述べる所なら、1-3 の候補（`'` を付けたものはその変形） |
| `v{版}` | 前に文書の名前があれば、その文書の版。`v2.1` だけなら引継ぎ資料 v2.1（7 の略称） |

| `段` | Phase 2 の作業の順序の単位。ほかに基線の段・ゴールの段・統合の見直しの段があり、文脈で見分ける | 〃 |
| `判断の節目` | 段 2 の後に、作業指示者が決める事項をまとめて諮った回 | 進め方 P2-2 |
| `結果を待つ 5 つ` | 割り当て表の行のうち、Phase 3 か Phase 7 の結果を待って決める 5 行 | 統合 §6.1 |
| `基線` | 本活動の文書で確かめた cc と docs の版 | 計画書 §2 冒頭 |
| `追補` | cc の新しい版の差分を確かめて、各文書に入れること | 活動の CLAUDE.md |
| `スリム化` | 太った生きている文書を、スリム化の規則に従って刈り込むこと | スリム化の規則 |
| `照合` | 落ちを探す確かめ<br>割り当て表の行と設計書、スリム化の前後の文などを突き合わせる | 進め方 §4、スリム化の規則 S9 |
| `クロスレビュー`・`観点` | 書いた文書を、観点（論理整合性・実用性など）ごとに別のモデルが読む検査 | cross-review skill |
| `ブロック指摘`・`態度表明` | ブロック指摘は、レビュー報告書の判断依頼サマリに載った指摘<br>態度表明は、それへの作業指示者の受け止め | 〃 |

## 7. 文書の略称

パスは詳細の「文書のパス」にある。

| 略称 | 指す文書 |
|---|---|
| `計画書` | 活動計画書。Phase 2 の進め方の計画書は「進め方」と書く |
| `承認依頼書` | 【別紙】計画書v<版>承認依頼書（計画書の版を上げる承認の依頼。版ごとに 1 本） |
| `仕様別紙` | 【別紙】公式仕様の調査結果 |
| `v2.1` | 引継ぎ資料 v2.1（計画書の v2.1 と別） |

| `VerUP IAR(cc v2.1.{xxx})` | 影響調査報告書（IAR）。cc の版を上げた時に、その差分が本活動に及ぼす影響を調べた報告書（影響調査は IA）。xxx は作った時の cc の版 |
| `まとめ` | 基礎調査まとめ報告書 |
| `V-ID 別紙` | 【別紙】V-ID別状況とPhase3実測項目（V-ID は v2.1 の検証項目の番号。4 の `V-{ID}`） |

| `進め方` | Phase 2 の進め方の計画書 |
| `組 A`・`組 B`・`組 C`・`組 D` | 組 A 全体構成、組 B データモデルと集計、組 C 作業分類タグ、組 D 有効化とデータ保全の設計書 |
| `定義の別紙` | 組 B の【別紙】スキーマと指標の定義 |
| `統合` | 統合の設計書（Phase 2 の設計まとめ） |
| `割り当て表` | 【別紙】Phase 2 の割り当て表 |
