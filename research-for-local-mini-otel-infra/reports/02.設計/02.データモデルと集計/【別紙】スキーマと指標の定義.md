| `thinking_status` | TEXT | `final`・`unconfirmed`・`not_in_transcript`・`no_key` |
| `duration_ms`・`ttft_ms` | INTEGER（NULL 可） | 要求の所要時間と最初のトークンまでの時間 |
| `cost_usd`・`cost_usd_micros` | REAL・INTEGER（NULL 可） | cc の値（`api_request` があるときだけ） |
| `cost_calc_usd` | REAL（NULL 可） | 見なし費用 |
| `cost_status` | TEXT | `priced`・`unpriced_model`（表にモデルが無い）・`unpriced_key`（モデルはあるが `speed` か区分の行が無い）・`no_price_set` |

| `label_l1`・`label_l2` | TEXT（NULL 可） | `prompt_label` から写す（受け渡し H-01） |

- `transcript_usage` に持たない列（`client_request_id`・`query_source`・`query_source_safe`・`cost_usd`・`cost_usd_micros`・`skill_name`・`agent_name`・`duration_ms`・`ttft_ms`・`inference_geo`・`agent_id`・`parent_agent_id`）と、`prompt_id`・`label_l1`・`label_l2`・`unclassified_kind`・`api_rec_id`・`span_rec_id`・`join_key` は NULL にする

- `thinking_status`・`prompt_length_band`・`system_prompt_variant`・見なし費用は、ほかの行と同じ規則で付ける

## 2. `query_source` の写し方

**`query_source_map`**（設計書 [§1.2](設計書.md#sec-1-2)。受け渡し H-22）

| 列 | 中身 |
|---|---|
| `signal` | `event`・`span`・`metric` |
| `pattern` | 生の値。末尾の `*` は前方一致 |
| `query_source_class` | `main`・`subagent`・`auxiliary` |

### 4.5 計算

1 行の見なし費用は、次のとおりに計算する。まず `total_input_tokens` と行の `band_threshold_tokens` でプロンプトの長さの区分を決め、(`price_set`, `model_key`, `prompt_length_band`, `speed`) で単価の行を引く。

```text
cost_calc_usd =
  ( input_tokens       × usd_per_mtok_input
  + output_tokens      × usd_per_mtok_output
  + cache_read_tokens  × usd_per_mtok_cache_read
  + cache 書き込みの費用 ) ÷ 1,000,000
  × data residency の倍率（inference_geo が us の行と、環境の設定で US だけの推論の期間とした行。それ以外と不明は掛けない）

cache 書き込みの費用 =
  内訳があるとき:  cache_creation_5m_tokens × usd_per_mtok_cache_write_5m
                  + cache_creation_1h_tokens × usd_per_mtok_cache_write_1h        cost_basis = ttl_breakdown
  内訳が無いとき:  cache_creation_tokens × 既定の TTL の cache 書き込みの単価       cost_basis = ttl_default
```

- 区分は、`total_input_tokens` が `band_threshold_tokens` 以下なら `le_threshold`、超えれば `gt_threshold` である。区分の無いモデルは `all`
- 既定の TTL は、`billing_form` と `ttl_request_class` で決まる（[仕様別紙 §1](../../00.活動計画/【別紙】公式仕様の調査結果.md#1-取れるシグナルと属性) の cache 書き込みの既定の TTL）。定額の契約の枠内の主の会話は 1 時間、それ以外は 5 分である。利用枠の中でサーバーが決める一部の補助の要求は 1 時間だが、行では見分けられないので 5 分で計算する。`ttl_request_class` が `unknown` の行も 5 分で計算し、注記する
- `transcript_only` の行は、transcript の usage の値で同じ式を当て、`cost_basis` を `transcript_ttl_breakdown`・`transcript_ttl_default` にする（[§1.3](#sec-1-3)）
- 1 回ごとの料金は行の式に入れず、回数 × 1 回の単価を別に足す（[§4.2](#sec-4-2)）
- 単価が見つからない行は `cost_calc_usd` を NULL にし、`cost_status` を `unpriced_model`・`unpriced_key`・`no_price_set` のどれかにする（[§1.3](#sec-1-3)）
