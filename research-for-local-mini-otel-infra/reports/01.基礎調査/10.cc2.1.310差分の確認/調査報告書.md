## 要約

- **調査内容**: cc 2.1.310（2026-10-23 公開）の changelog の 26 行すべてと、6 段目の docs（cf8ad11 と、1-9 で取得したオンラインのページ）から ed2bfc5（10-26）までの差分を確かめた。本活動に関わる項目を D66〜D71 にまとめた（[§2](#sec-2)）。cc 2.1.310 の `-p` の 3 run（1-9 の qk1〜qk3 に当たる）で、属性集合と events を 2.1.309 と比べた（[§3](#sec-3)。費用は約 0.11 USD）
- **調査結果**
  - **変わらなかったこと**: 本活動が依存する属性の削除・改名・型の変化は無かった（changelog・docs・2.1.310 の実機の 3 点で確認）。events と span の種類、`query_source`・モデル・effort、plugin の構成、`prompt_id` の結合（3 件中 3 件）、transcript の突合（7 件中 6 件。外れは compact の 1 件）、transcript の記録型とキーは、2.1.309 と同じだった（[§3](#sec-3)）。1-9 のときオンラインにだけあった 2.1.309 の changelog と `safety_event` の節は、10-24 の取得版（5536db3）からローカル docs に入り、語は変わっていなかった（[§1](#sec-1)）
  - **変わったこと**: (1) サブエージェントが出したイベントに `agent_id`（入れ子なら `parent_agent_id` も）が、`tool_decision`・`tool_result` に `request_id` が付くようになった。docs は v2.1.310 以降と書き、changelog には記載が無い。実機でも付き、値は span・transcript の id と一致した（D66）。(2) 一部のゲートウェイが `effort-2025-11-24` の beta 値か会話途中の system message を拒否すると、2.1.309 以前はリクエストが失敗した。2.1.310 の cc は、それらを外して再試行する。effort の再試行の後は、そのモデルへの要求に effort を付けない（docs。D67）。(3) Git Bash の無い Windows で hook の command が引用符の文字列だけのとき、PowerShell はそれを実行せずに出力する（docs）。`PreToolUse`・`PermissionRequest` の hook がそのまま tool call を通していた不具合が直った（D68）。(4) `cleanupPeriodDays` を非常に大きくすると最近のファイルを消していた不具合が直った（D69）。(5) "Prompt is too long" の後の compaction の不具合が直り、`-p` の compaction のメモリの使い方が改善された（D70）
  - **Phase 1 の記述の修正**: 崩れた事実が 1 件あった。「`api_request` にはサブエージェントの個体の ID が無い（`agent_id` は span だけ）」である。2.1.309 までは正しく、2.1.310 で崩れたもので、Phase 1 の誤りではない。反映候補は計画書のほかに 19 件、計画書の変更（作業指示者の承認が要る）が 8 件ある（[§4](#sec-4)）
- **判断事項への影響**: 推奨・既定・選択肢を変える J・Q は無く、新しい J も作らない。J-18 は、基線の版の句（「現時点では 2.1.309」）が 2.1.310 になる。J-18 の第 2 の問い（職場の下限。先送り）は先送りのままで、材料が増える（2.1.309 以前は、ゲートウェイが effort の beta 値か system message を拒否するとリクエストが失敗する。D67）。J-3 の推奨は変わらず、Mod の `turn.step` を使う理由の 1 つが OTel で足りるようになっただけである（D66）
- **結論・示唆**: 本活動が依存する属性は 2.1.310 でも使える。Phase 2 の設計では次の 3 点を考えに入れる。データモデルで `agent_id`・`parent_agent_id`・tool のイベントの `request_id` を持つか（2.1.310 以降、サブエージェントの個体とツール結果を API リクエストの単位で分けられる。D66）、`effort` の付かない行を既定の effort と読まないこと（ゲートウェイの再試行の後。D67）、L1 を `"shell": "powershell"` で動かすときは引用符付きのパスの前に `&` を置き、引用符の文字列だけの command にしないこと（D68）。職場（Phase 7）の確認には、ゲートウェイの effort の beta 値・system message の拒否と、tool のイベントに `request_id` が付くかを足す（[§5](#sec-5)）
