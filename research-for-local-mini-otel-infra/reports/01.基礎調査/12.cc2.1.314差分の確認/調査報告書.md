## 要約

- **調査結果**
  - **変わらなかったこと**: OTel の属性集合（25 種・455 組）、events と span の種類、`query_source`・モデル・effort、plugin の構成、`agent_id`・tool のイベントの `request_id` の値の一致、`prompt_id` の結合（3 件中 3 件）、transcript の突合（7 件中 6 件。外れは compact の 1 件）、transcript の記録型と各型のキー、hook の入力のキーは、2.1.311 と同じだった（[§3](#sec-3)）。`api_request` の TTL 別の cache 書き込みの内訳は、4 run の 9 件とも和が `cache_creation_tokens` と一致した
  - **変わったこと**

    - (3) docs の `api_request` の属性の一覧に、TTL 別の cache 書き込みの内訳が載った。API の応答が内訳を返さないときは、`cache_creation_tokens` が正でも 2 つとも 0 になる（D82）
    - (4) アイドル時の compaction は、2.1.314 から、VS Code の拡張と desktop app の Code タブで、Anthropic が選んだアカウントに限らず動くようになった（docs は、2.1.310 の版（1-10 D70）から f43c40d まで、それらのアカウントに限っていた）。telemetry を切った定額の契約の利用者と、1 時間の prompt cache の TTL を使う LLM ゲートウェイでも動く【推定】（changelog による。docs の条件の一覧は feature flag の取得を条件に残しており、食い違う。実機では確かめていない。D83）
    - (5) `--setting-sources` で外した settings のファイルが、auto mode の規則と保存した承認を渡し続けていた不具合が、2.1.314 で直った。[組 D §1.4](../../02.設計/04.有効化とデータ保全/設計書.md#sec-1-4) の計測用のセッションの起動の形の前提である（D85）

  - **崩れた事実**: 2 件ある。`safety_event` が tool call を止めたときに出ることは、2.1.307〜2.1.311 に限る事実になった（D80）。TTL 別の内訳が docs の属性の一覧に無いことは、7ff696f で崩れた（D82）
