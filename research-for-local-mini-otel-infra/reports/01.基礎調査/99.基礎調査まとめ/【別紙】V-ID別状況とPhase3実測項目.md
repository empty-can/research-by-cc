## 2. Phase 3 で実測する項目

個別報告書と V-11(b) の別紙から集約した。v0.2 で [1-8 §6](../08.cc2.1.287差分の確認/調査報告書.md#sec-6) の未確認事項を、v0.6 で cc 2.1.296 の追補の未確認事項（[1-8 §7.5](../08.cc2.1.287差分の確認/調査報告書.md#sec-7-5)）を、v0.8 で docs 2.1.296 の反映（1-8 §7 の「2026-10-12 追記」）を加えた。計画書 Phase 3 の確認観点（受信サーバが止まっていても cc の操作に影響しないか、2 セッション同時で欠落しないか等）に加えて行う。

- Phase 3 の測定は cc 2.1.293 以降で行うことを提案する（v0.5 までは 2.1.287 以降としていた。[裁定待ち事項](../作業指示者裁定待ち事項.md#sec-1) J-18 で裁定待ち）。下限は本環境の測定に課す。職場環境では確認時の cc の版を記録し、下限未満なら、その版で測った値は本環境の値と比べず、職場の中の比較に限る（managed settings のキーと拒否の行の確認は版に依らないので、そのまま行う）。理由は、2.1.288 の OTel の値の修正（`-p` の `claude_code.tool.blocked_on_user` の source・decision が `unknown` になる不具合と、未回答の permission ask で `tool_decision` が出ない不具合）、2.1.288〜2.1.290 の transcript の回帰（終了時に最後のメッセージが失われうる。2.1.291 で修正）、2.1.287〜2.1.292 の Mod の不具合（worker の再起動中に `classic.*` hook が飛ばされる。2.1.293 で修正）である。hook と Mod の上乗せは版で動く（2.1.296 の `-p` では Mod の方が大きくなった）ので、測定では `service.version` を必ず記録し、hook と Mod の比較は同じ版の値どうしで行う
- 版の検知: cc の自動更新は止めない（更新は利用者の操作なしに起き、次の起動で効く）。測定の前後で `claude --version` を記録する。`service.version` が前のセッションと変わった最初のセッションを「版上げ直後」とみなし、測定の途中で版が変わったら、変わった後のセッションをその比較から除く。職場環境でも同じく、確認のたびに cc の版を記録し、前回と違えば最初のセッションを測定に使わない
- Phase 1 の 1-1〜1-6 は 2.1.283 の実測で、2.1.287 での再確認の結果は [1-8 §3](../08.cc2.1.287差分の確認/調査報告書.md#sec-3)、2.1.296 での再確認の結果は [1-8 §7.3](../08.cc2.1.287差分の確認/調査報告書.md#sec-7-3) にある
- モデルは完全な ID で指定し、エイリアス（`haiku` 等）では指定しない。2.1.293 から、Anthropic API の `haiku` は Haiku 5.5（`claude-haiku-5-5`）に解決し、過去の実測の Haiku 4.5（`claude-haiku-4-5-20251001`）とは違う。基準モデルは、版をまたぐ継続比較（属性集合・遅延・突合）は Haiku 4.5、auto mode が有効なまま動く条件（auto mode の比較を含む）の基準は Haiku 5.5、と用途で分ける案である（[裁定待ち事項](../作業指示者裁定待ち事項.md#sec-1) J-14 で裁定待ち）
- 測定の注意（[1-8 §7.1](../08.cc2.1.287差分の確認/調査報告書.md#sec-7-1)・[§7.2](../08.cc2.1.287差分の確認/調査報告書.md#sec-7-2)）
  - permission mode は `--permission-mode` で明示して固定する（比較実験の値は、auto mode の行の案のとおり `default`）。本環境はユーザ settings の `permissions.defaultMode` の設定により、対話モードも `-p` も auto で起動する（組み込みの既定ではない）。J-12 の判定に使う日常のセッションは固定せず、mode を記録する（hook の行）
  - `-p` は 2.1.292 から、main が起動した background コマンドと `/loop` の wakeup を待ち、結果を受けてもう 1 ターン走る。計測用の `-p` では background コマンドを使わない（ターン数と `api_request` の件数が増えうる）
  - Git Bash から `-p "/compact"` などのスラッシュコマンドを渡すときは `MSYS_NO_PATHCONV=1` を付ける（付けないとパスに変換される）
  - Claude が起動する対話モードの計測用のセッション（probe と比較実験）は、Remote Control を切って行い、各 run の Remote Control の有無を記録する（2026-10-10 の作業指示者の指示。J-12 の判定に使う日常のセッションは切らない。[裁定待ち事項](../作業指示者裁定待ち事項.md#sec-2) J-19）。切り方: `remoteControlAtStartup` を false にする 1 キーだけの JSON ファイルを作り、そのパスを `--settings` に渡す（JSON の文字列を直接渡すと、シェルごとの引用符の扱いが要る）。確かめ方: debug log に、Remote Control の接続を示す行（接頭辞 `[remote-bridge]`・`[bridge:repl]`・`[bridge]`）が 0 件であること。`--plugin-dir` を使う実行では、ファイル識別の行にも「bridge」の語が出るので、接頭辞で判定する（[1-8 §7.3.4](../08.cc2.1.287差分の確認/調査報告書.md#sec-7-3-4)）。`-p` は Remote Control に接続しない。職場環境（Amazon Bedrock）では Remote Control は使えないので、この項目は本環境だけ
- 「判定の目安」は、手順書の作成担当が基準を独自に決めずに済むよう、Claude が置いた案である（v0.4。クロスレビュー 実用 I3）。Phase 2 の設計で変わり得る。合否を置かず値を記録するだけの項目は「記録のみ」と書いた
- hook の待ち時間の基準（タグ案 L1 から L2、または ① だけへの切替の基準）は作業指示者の判断事項で、暫定値を [作業指示者裁定待ち事項](../作業指示者裁定待ち事項.md) J-12 に記録した
