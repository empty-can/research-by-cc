## 2. Phase 3 で実測する項目と、Phase 7 で確認する項目

ファイル名の「Phase3実測項目」は、本環境の表では Phase 3 の実測項目（画面案の行だけは Phase 5）を、職場環境の表では Phase 7 の確認項目を指す（ファイル名は他の文書からのリンクのため変えない）。

個別報告書（1-1〜1-9。1-8 は [§6](../08.cc2.1.287差分の確認/調査報告書.md#sec-6)・[§7.5](../08.cc2.1.287差分の確認/調査報告書.md#sec-7-5) の未確認事項、§7 の docs 2.1.296 の追記、[§8](../08.cc2.1.287差分の確認/調査報告書.md#sec-8) の cc 2.1.302 の再確認。1-9 は [§5](../09.cc2.1.304差分の確認/調査報告書.md#sec-5) の職場の確認項目と未確認事項）、V-11(b) の別紙、職場の接続の形の回答（J-26）と docs 2026-10-18 取得版の差分から集約した。計画書 Phase 3 の確認観点（受信サーバが止まっていても cc の操作に影響しないか、2 セッション同時で欠落しないか等）に加えて行う。

- 測定版の下限（[裁定待ち事項](../作業指示者裁定待ち事項.md#sec-1) J-18 で裁定待ち）: Phase 3 の測定は、Phase 3 着手時点の最新の基線の版以降（基線は本活動の文書で確かめた cc の版で、計画書 §2 冒頭にある。2026-10-23 時点では cc 2.1.309）で行うことを提案する。下限は Phase 3 着手時点で一度だけ決め、Phase 3 の途中の反映では上げない（途中で上げると、先に測った値が新しい下限を下回り、判定に使えなくなる）。Phase 3 着手の前に、基線の版に回帰が見つかったら、下限を自動では上げず、作業指示者に諮る
  - 理由: Phase 3 で測る項目に、2.1.300〜2.1.302 で入った属性を使うものがある。span の `gen_ai.provider.name` と `api_request` の `cache_creation_5m_tokens`・`cache_creation_1h_tokens` は 2.1.300、`tool_decision` の `classifier_verdict`・`permission_mode` は 2.1.301、`classifier_category` の欠落の修正は 2.1.302 で入った。span の `gen_ai.operation.name` は、2.1.296 では出ず、2.1.302 では出た（changelog に名前が無く、出始めた版は確かめていない）。R6 の行で使う `safety_event` は 2.1.307 で入った（[1-9 §2](../09.cc2.1.304差分の確認/調査報告書.md#sec-2) の D56）。前の提案の下限（cc 2.1.293 以降）では、それらが出ない版を許してしまう。属性ごとの最低版は [1-8 §8.4](../08.cc2.1.287差分の確認/調査報告書.md#sec-8-4) の表の 4 にある
  - 前の提案（2.1.293 以降。J-18 の選択肢 (3) の下限）の理由: 2.1.288 の OTel の値の修正（`-p` の `claude_code.tool.blocked_on_user` の source・decision が `unknown` になる不具合と、未回答の permission ask で `tool_decision` が出ない不具合）、2.1.288〜2.1.290 の transcript の回帰（終了時に最後のメッセージが失われうる。2.1.291 で修正）、2.1.287〜2.1.292 の Mod の不具合（worker の再起動中に `classic.*` hook が飛ばされる。2.1.293 で修正）
  - 職場環境: 下限は本環境の測定に課す。職場環境では確認時の cc の版を記録し、下限未満なら、その版で測った値は本環境の値と比べず、職場の中の比較に限る（managed settings のキーと拒否の行の確認は版に依らないので、そのまま行う）。作業指示者の情報（2026-10-12）では、職場の cc は起動ランチャーで常に最新版に更新している。職場の確認には 2.1.304 を使わない（ゲートウェイが tool search を拒否すると全リクエストが失敗する。[1-9 §5](../09.cc2.1.304差分の確認/調査報告書.md#sec-5)、D59）
  - 記録: hook と Mod の上乗せは版で動く（2.1.296 の `-p` では Mod の方が大きくなった）ので、測定では `service.version` を必ず記録し、hook と Mod の比較は同じ版の値どうしで行う

- Phase 1 の 1-1〜1-6 は 2.1.283 の実測で、2.1.287 での再確認の結果は [1-8 §3](../08.cc2.1.287差分の確認/調査報告書.md#sec-3)、2.1.296 での再確認の結果は [1-8 §7.3](../08.cc2.1.287差分の確認/調査報告書.md#sec-7-3)、2.1.302 での再確認の結果は [1-8 §8.3](../08.cc2.1.287差分の確認/調査報告書.md#sec-8-3)、2.1.309 での再確認の結果は [1-9 §3](../09.cc2.1.304差分の確認/調査報告書.md#sec-3) にある

  - probe と Phase 3 の比較実験での plugin の扱い（[裁定待ち事項](../作業指示者裁定待ち事項.md#sec-2) J-25）。規則: plugin の構成を、比べる相手の測定（前回の基線）と同じにする。前回の測定の後にユーザ設定で有効になった plugin は、hook を登録しないものも含めて無効にする（2.1.302 の測定では、2.1.296 の後に増えた 4 つすべて）。手順: `--settings` に渡す JSON ファイルの `enabledPlugins` で、それらの plugin を false にする。Remote Control を切る設定（`remoteControlAtStartup` を false）と同じファイルにしてよい。ファイルは plugin の名前を含むので、repo には置かず、repo の外の作業用フォルダに置く。確認: OTel の `plugin_loaded` にそれらの plugin が出ないこと、`hook_registered` が probe の作業フォルダの hook だけになること（[1-8 §8.3.5](../08.cc2.1.287差分の確認/調査報告書.md#sec-8-3-5)）。対象: Claude が起動する計測用のセッション（probe と Phase 3 の比較実験）。日常のセッション（J-19）は対象外で、無効にせず、plugin の構成を記録する（hook の行の (3)〜(4)）
- 「判定の目安」は、手順書の作成担当が基準を独自に決めずに済むよう、Claude が置いた案である。Phase 2 の設計で変わり得る。合否を置かず値を記録するだけの項目は「記録のみ」と書いた
- 起こし方を決めていない項目（R6 の block・ask、R12 の `classifier_category`、plugin の hook の受け渡しの失敗、`error.type`、`retention_sweep` など日常利用の中で観測する項目）は、Phase 3 の期間内に観測できなければ、「未観測（起こらなかった条件）」と記録して閉じてよい。閉じた項目は Phase 3 の完了判定に残さず、日常利用で後に観測できたときに追記する
