**J-12 の暫定値（2026-10-24 に承認）**

- 測るもの: 対話モードの日常のセッション（Remote Control・モデル・permission mode は普段のまま。J-19）で、llm_request の開始までの上乗せ（測定点 A。interaction span の開始から最初の llm_request span の開始までの時間と、同じ条件（Remote Control の有無・モデル・permission mode）の hook なしの中央値との差。[1-8 §4.3](08.cc2.1.287差分の確認/調査報告書.md#sec-4-3)）
- 許容とする基準: 上乗せの中央値が 1 秒以下で、かつ、上乗せが 2 秒を超えるプロンプトが全体の 1 割以下（上乗せはプロンプトごとに、測定点 A の値から hook なしの中央値を引いて求める。プロンプト全体の遅延の絶対値ではない）
  - 新しいウィンドウの最初のプロンプトも判定に含め、別にも集計して記録する（2.1.283 の 2 秒超の 2 回は、どちらも最初のプロンプトだった）
  - `/model` で切り替えた直後のプロンプトは、判定（中央値・1 割）から除き、別に集計して記録する。モデル切替直後のリクエストは最大 1.5 秒待つことがあり（changelog）、この待ちは hook に起因しないので、上乗せの計算に混ぜない
  - command hook と Mod は、それぞれ別に判定する
- 標本: 実装手段ごとに 20 プロンプト以上（3 セッション以上）、hook なしの基準は 10 プロンプト以上。判定に使う組（日常の主な条件。次の項目）で数える
- 判定に使う組: 日常のセッションは、モデルや permission mode が混ざることがある（`/model` で切り替える使い方など）。判定は「モデル × permission mode × Remote Control の有無 × plugin の構成（hook（command hook・Mod）を登録する plugin の集合）」の組ごとに行う（plugin の構成を組に入れるのは、日常に近い条件の hook なしの値が、plugin の構成で約 450 ms 変わったため。J-25）。実装手段ごとに、標本（プロンプト数）が最も多い組を日常の主な条件とし、その組で判定する。20 プロンプトに満たない組は判定せず、参考値として記録する。主な組でも 20 プロンプトに満たないときは、測定期間を延ばす。測定期間を延ばしても足りないときは、自動では判定せず、測定値を添えて諮る
- 根拠: 2.1.302 の対話モード（Remote Control を切り、ユーザ環境の plugin を無効にした状態）では、上乗せが command hook 約 270 ms・Mod 約 94 ms で、2 秒超は出なかった（[1-8 §8.3.2](08.cc2.1.287差分の確認/調査報告書.md#sec-8-3-2)。各 n=3）。1 秒は、2.1.287〜2.1.302 の測定（各 n=3）で上乗せも hook 単体の所要時間も 0.5 秒未満だったことに、2 倍程度の余裕を見た値で、Claude の判断である。2 秒は、1-3 v0.3 までが懸念とした値（2.1〜2.8 秒）を下回る位置に、測定点 A の目安として置いた。2.1〜2.8 秒は hook 単体の所要時間（測定点 B）の値で、測り方が違う
- 測り方の注記:
  - 測定点 B（`hook_execution_complete.total_duration_ms`）は、同じイベントでマッチした全 hook（並列に走る）の経過時間である（docs）。同じイベントに plugin の hook があると、それも含む
