### I1. J-12 の hook 遅延の判定が、どの条件（Remote Control・モデル・permission mode）の値で行われるか定まらない

**作業指示者判断**: 要（後続作業をブロックしない。既定は修正案 1）。要るのは、Remote Control の扱い（2026-10-10 の作業指示者の指示の範囲の解釈）と、J-14 (C) の区分に J-12 の判定を入れる位置である

#### I1. 問題点

* **概要**: J-12 は「L1 の hook の待ち時間を許容できるか」を、Phase 3 の対話モードの測定値で判定する基準である。その測定条件が、Remote Control（以下 RC）、モデル、permission mode の 3 軸で、文書により食い違うか、決まっていない。作業指示者が J-12 の暫定値を承認しても、どの値に当てはめるかが定まらない。
* **問題点**:
  1. RC: 「切って計測する」と「あり・なしの両方を並べる」が同居する。切る側は、活動 `CLAUDE.md` L22「実機検証の対話セッションは RC を切って起動する」、1-8 L593「今後の実機検証は、RC を切って行う（作業指示者の指示、2026-10-10）」、V-ID L40「対話モードの計測は RC を切って行い」、計画書 L200。並べる側は、1-8 L537「Phase 3 の基準と J-12 の根拠には、RC あり・なしの両方を並べる」、V-ID L56 の (3)「判定の根拠には接続あり・なしの両方の値を並べる」。全 run が RC なしなら、計画書 L200 と V-ID L40 が言う「RC の有無の記録」は常に「なし」になる。
  2. 標本数: V-ID L56 は「実装手段ごとに 20 プロンプト以上（3 セッション以上）、hook なしの基準を 10 プロンプト以上」と書くが、これが RC の条件ごとか不明。条件ごとなら、command hook 20＋Mod 20＋hook なし 10 の 50 プロンプトが 2 倍の 100 以上になり、RC を接続した対話セッションを起動する必要も生じる（上記の指示と衝突）。
  3. モデル: J-14 (C) は「版をまたぐ継続比較（属性集合・遅延・transcript との突合）は Haiku 4.5、auto mode の比較と日常利用に近い基準は Haiku 5.5」と区分する（裁定待ち事項 L34）。J-12 の測定は「対話モードの日常のセッションでの遅延」で、両方の区分に当たる。V-ID L56 にモデルの指定は無い。1-8 L562 によれば、`-p` の hook なしの測定点 A は Haiku 4.5 で約 115 ms、Haiku 5.5 で約 293 ms と、モデルで大きく違う。
  4. permission mode: V-ID L37 は「明示して固定する」とするが、値の案は auto mode の行（L51「検証は `default` に固定する（案）」）にあるだけで、hook の行（L56）からは参照されない。
* **影響**:
  1. 判定値の取り違えや、「条件が違う」ことによる再測定が起きる。
  2. 手順書の作成担当が、標本数（50 か 100 以上か）と、RC を接続したセッションを作ってよいかを独自に決めることになる。V-ID L41 が避けようとした状態（基準を担当が独自に決める）に戻る。
  3. J-12 の判定は L1 から L2 または ① だけへの切替の根拠になる。条件の曖昧さが、そのまま切替の判断の曖昧さになる。
* **詳細**:
  1. 1-8 L536 は、RC を切ると上乗せが command hook で約 24 ms、Mod で約 50 ms 小さくなり、順位と「0.5 秒未満」は変わらないと書く（n=3）。つまり、どの値で判定しても結論が変わる見込みは小さい。だからこそ、条件を 1 つに決めて標本を節約できる。
  2. J-12 の基準は絶対値（上乗せの中央値 1 秒以下、2 秒超が 1 割以下）で、版をまたぐ継続比較ではない。モデルを Haiku 4.5 に揃える必然性は、J-12 の判定には無い。
* **根拠**:
  1. 計画書 L200、活動 `CLAUDE.md` L22、V-ID L40・L56、1-8 L536・L537・L593 の本文。
  2. 裁定待ち事項 L34（J-14 の推奨 (C) の区分）、L44（J-12 の測り方の注記）。
  3. scratchpad `G_fact-sheet.md` L65〜L66 にも同じ併記がある（L65「今後の検証は RC なしで行う」、L66「RC あり・なしの両方を並べる」）。作成時点から食い違いが残っていた。

### S6. J-12 の「判定に使う条件（日常の条件）」が RC だけで定義され、モデル・permission mode が混ざる場合の組と、標本不足時の扱いが無い

**観点**: 検証パターン具体性
**作業指示者判断**: 不要
**追加**: 0.9（Round 3）。I1 の修正（日常のセッションをそのまま測る形）で生じた細部の指摘

**該当箇所**: 裁定待ち事項 L43・L50（J-12 暫定値）、V-ID 別紙 L57 の (3)、計画書 L201

#### S6. 観点

* **概要**: I1 の修正で、J-12 は「日常の条件の値で判定し、標本（実装手段ごとに 20 プロンプト以上、hook なしは 10 プロンプト以上）はその条件で数える」ことになった。「日常の条件」の定義は、V-ID 別紙 L57 の (3) に「本環境では、ユーザ settings の設定により RC に接続した状態」とあるだけで、モデルと permission mode は「普段のまま」記録し、条件ごとに別に集計するとされる。どの組を判定に使うかが決まっていない。
* **問題点**:
  1. 日常のセッションでモデルや permission mode が混ざると（`/model` で切り替える使い方は J-12 自身が想定している）、条件の組（RC・モデル・mode）が複数できる。判定に使う組が書かれていない。
  2. 判定に使う組が 20 プロンプト（hook なしは 10 プロンプト）に満たない場合に、足して測るのか、他の組を合算するのか、判定を保留するのかが書かれていない。J-12 L43 は「同じ条件の hook なしの中央値」で引くので、hook なしの基準も組ごとに要る。
* **影響**:
  1. 日常の使い方しだいで、判定に使える標本が足りない、または判定に使う組を後から選べてしまう。
* **詳細**:
  1. 1-8 L562 によれば、`-p` の hook なしの測定点 A はモデルで約 115 ms と約 293 ms に分かれた。上乗せは差分なので影響は小さい見込みだが、対話モードでは Haiku 4.5 と 5.5 を分けて測っていないため、差の大きさは未確認である。
* **根拠**:
  1. 裁定待ち事項 L43・L50、V-ID 別紙 L57、1-8 L562。

#### S6. 提案

1. **提案1.**:
   * 判定に使う組を「作業指示者の既定の構成（本環境では RC に接続、既定のモデル、既定の permission mode）」と明記する。それ以外の組は別に集計して参照値にする
2. **提案2.**:
   * 判定に使う組が標本に満たない場合は、同じ構成で追加して測る（他の組を合算しない）と書く。どうしても足りないときは判定を保留し、測定値を添えて諮る（J-12 の既定「自動では切り替えず諮る」と同じ扱い）

#### S6. レビューイからの見解・補足

* **レビューイの見解**（Round 3 追補）: 提案 1・2 を、判定に使う組の決め方を変えた形で採用した。「作業指示者の既定の構成」を先に決めておく案ではなく、日常のセッションで実際に標本が最も多い組を「日常の主な条件」とする規則にした。日常の使い方（モデルの切替の頻度など）は測ってみないと分からず、既定の構成を文書で先に置くと実態とずれうるためである。組を決める規則は標本数で機械的に決まるので、判定に使う組を後から選べる、という問題点 1 の懸念は残らないと考える。書いた内容は次のとおり
  1. 判定は「モデル × permission mode × Remote Control の有無」の組ごとに行う
  2. 実装手段ごとに、標本（プロンプト数）が最も多い組を日常の主な条件とし、その組で判定する。hook なしの基準（10 プロンプト以上）も、その組で数える（上乗せは同じ条件の hook なしの中央値から求める、という既存の規則のまま）
  3. 20 プロンプトに満たない組は判定せず、参考値として記録する（提案 1 の「別に集計して参照値にする」）
  4. 主な組でも 20 プロンプトに満たないときは、測定期間を延ばす（提案 2 の「同じ構成で追加して測る。他の組は合算しない」）
  5. 本環境の日常のセッションは Remote Control に接続して起動するので、接続ありの組が主になる見込みと添えた（見込みであり、判定は 2. の規則で決まる）
* **追加コメント**: 提案 2 の後半（どうしても足りないときは判定を保留し、測定値を添えて諮る）は、今回は書いていない。測定期間を延ばして足りるまで続ける扱いにした。延ばしても足りない場合の扱いは未定義なので、必要ならレビューアの確認で指摘いただきたい。反映先（いずれも同日の変更履歴の行に追記し、版数は上げていない）: 裁定待ち事項 J-12 の暫定値（L50 の標本の項目と、L51 に足した「判定に使う組」の項目）、V-ID 別紙 §2 の hook の行（L57 の「判定の目安」の欄、「測り方・標本数」の欄の標本数の括弧と (3)）。1-3 §4、まとめ §3.3・Q4 補足、計画書 Phase 3 は、V-ID 別紙 §2 を参照する書き方（「条件ごとに集計する」）で、組の決め方は書いていないので直していない
