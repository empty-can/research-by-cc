## 使い方

- **態度表明は、各報告書の「ブロック指摘一覧」の表の「態度表明」列に書く**（採用 / 条件付き採用 / 差戻し / 保留 / 却下）。本書は読むための集約で、本書には記入しない。2026-09-28 の人間読み手の表には「反映先」列もあるので、あわせて見る
- **（v0.8）態度表明が要る 23 件を、[態度表明の区分](#sec-defer)で 3 つに分けた**（J-27・J-24）。Phase 2 の前に要るのは 18 件である。先送りの 3 件は Phase 7 の着手前に書く。前提が解消・対象が無くなった 2 件は、異論がある場合だけ書く
- 各 ID のリンクは、報告書の当該指摘の節に飛ぶ（見出しの直前の `<a id>`）
- 多くの指摘は、まとめ報告書 [§5.1 の Q1〜Q5](../99.基礎調査まとめ/報告書.md#sec-5-1) か、[裁定待ち事項](../作業指示者裁定待ち事項.md) の J に判断の中身が移っている。先に Q と J に答え、各指摘にはその回答に沿った態度を書くと手戻りが少ない。まとめ §5.2 の確認のお願い（v0.3 の時点のお願い。職場の Node.js の版）は、同じ v0.3 で新設した J-24 で回答を受けるとし、2026-10-18 に回答をいただいた（職場では任意の版の Node.js を使える）
- 「前提の変化」列に注記がある指摘は、態度表明の前に注記の参照先を読む
- J-27 の後は、本書と各報告書の「Phase 3 の職場環境の確認」「Phase 3 で確かめる」のうち職場の分は、Phase 7（職場環境の確認と差の吸収）の確認を指す。報告書の本文は直さない

## 態度表明の区分（v0.8。J-27・J-24）

作業指示者の裁定 J-27（2026-10-18）で、本活動のゴールを 3 段に分けた。第一のゴールは本環境（Anthropic 環境）で仕組みを作ること（Phase 0〜6）、第二のゴールは職場環境（LiteLLM + Amazon Bedrock。LLM ゲートウェイ環境）への対応（新しい Phase 7「職場環境の確認と差の吸収」）、第三のゴールは WSL + Docker 環境への対応（次の活動。J-27 の前の「第二のゴール」）である。本環境と職場環境で共通する部分がほとんどなので、職場環境の確認が要る事項は第二のゴールへ先送りにし、ゴールの段は直列に進める。同じ日に J-24 の回答（職場では任意の版の Node.js を使える。版の制約として扱わない）もいただいた。先送りにするものと J-24 で片付くものは、[裁定待ち事項 §3](../作業指示者裁定待ち事項.md#sec-3) の J-27 の行に挙がっている。

これを受けて、v0.7 で態度表明が要るとした 23 件を、次の 3 つに分けた。

| 区分 | 件数 | 意味と、書く時期 |
|---|---|---|
| [Phase 2 の前に態度表明が要る](#sec-defer-p2) | 18 | 本環境（第一のゴール）の設計・測定に効くか、職場の確認に依らない指摘 |
| [先送り（Phase 7 の着手前）](#sec-defer-p7) | 3 | 残る判断が職場環境の確認にだけ関わる指摘。Phase 7 の着手前に、報告書の態度表明欄に書いていただく |
| [前提が解消・対象が無くなった](#sec-defer-done) | 2 | 態度表明は任意。異論があれば、報告書の態度表明欄でお知らせいただく |

1 件の指摘が 2 つの区分にまたがる場合は、指摘を割らず、態度表明が早く要る方の区分に置き、残りの分を備考に書いた。2026-10-12 の見直しで「解消済み」とした 2 件（10-10 論理 I2、10-12 人間読み手 U-I2）は、23 件に入らない（記入不要のまま）。
