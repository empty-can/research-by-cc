### I1. probe の plugin 無効化の手順が、次に実行する人には再現できない

**観点**: 検証パターン具体性

**該当箇所**: 活動 `CLAUDE.md`「作業時の注意」の 4 項目目（2026-10-17 追加）、1-8 §8.3.5「測り方」、裁定待ち事項 J-25（§2 と §3）、V-ID 別紙 §2 冒頭の「測定の注意」

#### I1. 問題点

* **概要**: 隣の Remote Control を切る手順は、ファイルの形・確かめ方の基準・例外まで書かれている。plugin を無効にする手順は 1 文で、実行者が迷う点が 3 つ残る。
* **問題点**:
  1. 無効にする対象が文書で食い違う。`CLAUDE.md` は「有効な plugin のうち hook を登録するもの」と書く。1-8 §8.3.5 と J-25 は、実際に無効にしたのは「2.1.296 の後に増えた 4 つ」（うち hook を登録するのは 2 つ）と書く。hook を登録しない 2 つを無効にするかで、`plugin_loaded` の確かめ方が変わる。また「hook を登録するか」を実行前にどう知るかが無い（1-8 §8.3.1 に、`hook_registered` の `plugin.name`・`plugin_id_hash` が plugin を有効にした run だけに出るとあるが、手順としてつながっていない）
  2. `--settings` に渡すファイルの形（`enabledPlugins` に何をどう書くか）と置き場所が無い。plugin の名前はこのファイルに入るので、公開リポジトリに置けない。`.claude/workspace/` 等に置く旨が無く、Remote Control を切るファイルと同じ 1 つにまとめるのか、`--settings` を 2 回渡すのかも書かれていない
  3. 確かめ方の基準が「`plugin_loaded` で確かめる」だけである。1-8 §8.3.5 には「`hook_registered` は probe の作業フォルダの hook（2 件）だけになった」という合格の姿があるが、`CLAUDE.md` と V-ID 別紙にはない。V-ID 別紙 §2 の「測定の注意」には plugin の無効化自体が無く、`CLAUDE.md` の対象も「probe」だけなので、Phase 3 の比較実験（hook なし／あり、版の間の比較）が対象に入るのか読み取れない
* **影響**:
  1. 次の probe（Step 3 以降、または 2.1.303 以降の再確認）の実行者が、無効にした範囲を独自に決めると、2.1.296 や 2.1.302 のクリーンの値と比べられなくなる
  2. ファイルに plugin の名前を書いたまま commit する事故につながる（報告書には書かない、という規則は書かれているが、作業用ファイルの扱いは書かれていない）
  3. Phase 3 の比較実験が plugin 有効のまま走ると、J-25 が報告した「hook なしの基準そのものが成り立たない」状態を再現する
* **詳細**:
  1. `CLAUDE.md` の Remote Control の行は「`remoteControlAtStartup` を false にする JSON ファイルを `--settings` に渡す」で、V-ID 別紙 §2 に、1 キーだけのファイルにすること、引用符の問題、debug log の接頭辞 3 種が 0 件という確かめ方、`--plugin-dir` 使用時の例外まである。plugin の行はこれに並ぶ水準に達していない
* **根拠**:
  1. 差分の `CLAUDE.md` 追加行（4 項目目）、1-8 §8.3.5「測り方」、V-ID 別紙 §2 の「Claude が起動する対話モードの計測用のセッション…切り方…確かめ方」の項
