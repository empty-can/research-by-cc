### I1. 職場環境の確認に、plugin の hook の構成と L1 の hook の時間を確かめる項目が無い

**観点**: 検証パターン具体性

**該当箇所**: 計画書 §5 リスク表の最終行（L255）、Phase 3「職場環境の確認ステップ」（L206〜212）、Phase 3 の J-12 の判定の段落（L213）、Phase 2「作業分類タグ」4 つ目の項目（L185）

#### I1. 問題点

* **概要**: 第 12 稿が足した新しいリスク「職場は plugin の構成が違うので、本環境で隠れた L1 の hook の時間が、職場ではそのまま上乗せに出うる」の対策が、本環境の測定（Phase 3 の日常のセッション）にしか書かれていない。職場で何を記録するかが計画書に無い。
* **問題点**:
  1. §5 の対策は「J-12 の判定を plugin の構成（hook を登録する plugin の集合）を含む組ごとに行い、L1 の hook 自身の所要時間にも同じ基準を当てる」で、いずれも Phase 3 の本環境の測定である。職場環境の確認ステップは「Claude Code が確認手順書を用意し、作業指示者本人が職場環境で実施する（Claude Code は職場環境で検証しない）」と書かれ、その項目は、ループバック宛て送信、permission mode、managed settings、分類器、PowerShell の版である
  2. 職場の plugin については、「有効な plugin の manifest の名前」を同じ名前の衝突を確かめるために記録する項目があるだけで、どの plugin が hook を登録しているか（hook の数・イベント）を記録する項目は無い
  3. L1 の hook を職場で動かして時間を測る段は、Phase 3 にも Phase 4 の完了条件（「職場での継続は作業指示者が確認する」）にも無い
* **影響**:

  2. 作業指示者は、職場の確認手順書で何を記録するかを、計画書の段階では判断できない
* **詳細**:
  1. 職場で確かめられる範囲は、記録だけでも設計に効く（hook を登録する plugin の有無と数が分かれば、本環境の「隠れた」条件との違いが見積もれる）。1-8 §8.3.5 は、plugin の構成を OTel の `plugin_loaded`・`hook_registered` で見ると書くが、職場で OTel が受信できるのは Phase 3 の確認の結果次第である
* **根拠**:
  1. 計画書 L255（§5 の最終行）、L206〜212（職場の確認の項目）、1-8 §8.3.5（職場の plugin の構成が違えば、隠れた L1 の hook の時間が上乗せに出うる）、V-ID 別紙 §2 の職場環境の表（hook の待ち時間の行は本環境の表にだけある）

### I2. J-12 の判定を実施者が終えるまでの手順に、3 つの抜けがある

**観点**: 完了条件明瞭性

**該当箇所**: 計画書 Phase 3 の J-12 の判定の段落（L213）、Phase 3 の「作業」（L196）と「成果物」（L216）、Phase 2「作業分類タグ」4 つ目の項目（L185）、裁定待ち事項 J-12 の暫定値

#### I2. 問題点

* **概要**: 第 12 稿で、判定の組に plugin の構成を足し、L1 の hook 自身の所要時間に同じ基準を当てた。実施者が判定を終えるまでに必要な 3 点が、計画書から読み取れない。
* **問題点**:
  1. 「自分で記録した時間はプロセスの起動を含まないので、計測用のセッションで debug log の hook ごとの行と比べて差を確かめる」とあるが、差が出たときの扱い（補正するか、差の上限を置くか、記録するだけか）が無い。自己記録の値は起動分だけ小さく出るので、そのまま基準に当てると、合格側に偏る
  2. L1 の hook が自分の時間を記録するには、Phase 3 の日常のセッションで、記録機能の付いた試作の L1 の hook が動いている必要がある。Phase 3 の作業は「最小の受信 → 保存 → transcript 突合 → 簡易集計を実装し」で、成果物は PoC コードと報告書である。タグ付けの実装は Phase 4 の作業にある。試作の hook を Phase 3 で用意すること、記録の置き場所（受信側に送るか、ファイルか）が、どこにも書かれていない
  3. 判定の段落は「判定は『…plugin の構成』の組ごとに行い」と書く。V-ID 別紙 §2 と J-12 の暫定値は、標本が最も多い組を日常の主な条件とし、その組で判定する（20 プロンプトに満たない組は参考値）。段落の前半に「標本数は V-ID 別紙 §2 の案を出発点にする」とあるので矛盾はしないが、組が 4 つの軸の積になった今は、「組ごとに判定」と読むと、標本の足りない組が多く出て、完了にならない
* **影響**:
  1. 実施者が、自己記録の値を補正なしに基準に当てると、L1 の hook の時間を低く見積もって合格にしうる
  2. 実施者が試作の hook を用意する時期（Phase 3 の開始時か、Phase 2 の設計書か）を決められず、Phase 3 の途中で測定が止まる
  3. 組ごとの判定と読むと、判定が終わらない
* **詳細**:
