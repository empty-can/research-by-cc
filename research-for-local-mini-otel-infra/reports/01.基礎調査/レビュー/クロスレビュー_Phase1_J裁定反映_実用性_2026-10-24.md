### I2. 単価の組をレコードに当てる鍵と、表に無いモデルの扱いが、Phase 2 の決める項目に挙がっていない

**観点**: 検証パターン具体性

**該当箇所**: [計画書 Phase 2「分析指標」](../../00.活動計画/活動計画書.md#sec-p2-metrics)の見なし費用の「計算」「単価表」「費用に効くほかの要素」の項

#### I2. 問題点

* **概要**: 単価表の行の形（単価の組 × モデル × トークンの種類、出典、確かめた日、版）は具体的だが、計算のとき各レコードにどの単価の組を当てるか、`model` の値をどの行に結ぶかが書かれていない。
* **問題点**:
  1. 計算は「`model` と `speed` で選んだ単価」とあるが、単価の組（Anthropic の API の料金、Bedrock の global、jp）を選ぶ鍵が無い。職場の cc は `ANTHROPIC_BASE_URL` のゲートウェイにつなぎ、Anthropic の形のモデル ID で送る見込み（V-ID 別紙のモデル名の行）なので、`model` の値から Bedrock の推論プロファイルは読み取れない。環境（本環境か職場か）の識別と、職場で global・jp のどちらを使うかの設定が要る
  2. `model` の値と表のモデルの結び付け（日付つきの ID と無しの ID、ゲートウェイの別名。cc が知らない名前は docs で金額が決まらない）と、表に無いモデルのリクエストの扱いが決まっていない。「表に無い要素は計算できない」「集計の漏れとして注記する」とあるだけで、その件数を見える形にする規則が無い
  3. 単価表の保存形式と置き場（ファイルか DB の表か）が「データとして持つ」止まりで、取込層・集計のどこから読むかが未定
* **影響**:
  1. Phase 2 の設計担当が、データモデルと全体構成を決めるときに、この 3 点を自分で気づいて足す必要がある
  2. 気づかないと、職場のデータに Anthropic の単価の組が当たり、見なし費用が黙って誤る
* **詳細**:
  1. 「Phase 2 で決める」の見出しの下に置かれた項目なので、設計の対象ではあるが、決める事項として列挙されていない
  2. 計画書は TTL 別の内訳を使うかを「データモデルで決める」と明記しており、同じ形で書ける
* **根拠**:
  1. 計画書 Phase 2「分析指標」の見なし費用の小節。V-ID 別紙 §2 の職場の表のモデル名の行（ゲートウェイの別名と `api_request` の `model` の扱い）

### I4. 職場で `cache_read_tokens` を確かめる手順が、1 回の要求では偽の「無し」を出しうる

**観点**: 検証パターン具体性

**該当箇所**: [計画書 Phase 7](../../00.活動計画/活動計画書.md#sec-p7)の確かめること（V-10 の行）、[V-ID 別紙 §2](../99.基礎調査まとめ/【別紙】V-ID別状況とPhase3実測項目.md#sec-2)の職場の表の V-10 の行

#### I4. 問題点

* **概要**: 確かめることは「受信した `api_request` に、`cache_read_tokens` が 0 でない行があるか（有・無で記録する）」だが、どんな条件のセッションで見るかが書かれていない。
* **問題点**:
  1. プロンプトキャッシュの読み取りは、同じ接頭辞の 2 回目以降の要求で出る。1 回だけの `-p` や、初回の要求だけでは、ゲートウェイの先でキャッシュが効いていても `cache_read_tokens` は 0 になりうる。作業指示者が手順どおりに 1 回実行して「無し」と記録すると、見なし費用の見積もりの前提が誤って「効かない」になる
  2. 「受信した `api_request`」を見る行なので、ループバック宛ての送信が届かない場合（Phase 7 の別の行が「未実施（ループバック不可）」と書く場合）は、この確かめができない。transcript の `usage` にも cache 読み取りの数値があるので代わりに使えるが、その案内が無い
* **影響**:
  1. 職場の費用の見積もりの前提（キャッシュが効くか）が、誤った記録に基づいて決まる
  2. 受信できない場合に、行が空欄のまま残る
* **詳細**:
  1. V-10 の行の既存の確かめ（transcript と `api_request` のトークン 4 種の一致）は、同じ要求を対にして見るので、要求の回数の問題は出ない。今回足した項目だけが、複数回の要求を要する
* **根拠**:
  1. V-ID 別紙 §2 の V-10 の行（確認する場所・方法、記録する値の欄）
