# CLAUDE.md — research-for-local-mini-otel-infra

## 調査の目的

Claude Code（以下 cc）の OpenTelemetry テレメトリを、**Windows ローカルで完結する最小構成**で受信・蓄積・可視化する仕組みを構築する。

背景・ゴール・問い①〜③・前提・スコープ・フェーズ構成は `reports/00.活動計画/活動計画書.md`（以下「計画書」）を正本とする。最終的な効用は、分析結果をルート資産（「モデル選定原則」、`check-model` skill 等）へ還流させることであり、**分析そのものを目的化しない**（計画書 §1）。

## 作業時の制約

- **Windows ネイティブ・Docker 不要**で動く構成にする。WSL + Docker 前提の構成は本活動では作らない（第三のゴールとして次の活動で扱う。計画書 §1.4）
- ゴールは 3 段で、直列に進める（裁定待ち事項 J-27）。仕組みは第一のゴール（計画書 Phase 0〜6）で本環境（Anthropic 環境）に作り、第二のゴール（Phase 7）で LLM ゲートウェイ環境（社内のゲートウェイの先は Amazon Bedrock。呼び分けは計画書 §1.4）に広げる。第一のゴールの設計には、第二のゴールへの備えを含める（計画書 Phase 2「第二のゴールへの備え」）。**Claude Code は職場環境で検証しない**（確認手順書を用意し、作業指示者が実施する。計画書 Phase 7）
- 収集データを外部の SaaS・クラウドへ送らない。**収集データ（プロンプト本文等を含み得る）はコミットしない**
- 報告書（公開リポジトリに載る）には、`~/.claude` 配下のファイルの種類とキー名までを書く。認証情報・鍵のファイル名、利用統計の実数、識別子（メールアドレス・アカウント ID・request_id 等）の値は書かない
- 仕様は cc のバージョンに依存する。基線（cc と docs の版）は計画書 §2 冒頭。ただし今の基線は、VerUP IAR(cc v2.1.314) で上げた cc 2.1.314・docs daf68ae（2026-10-30 15:00 取得。2.1.314 の changelog を含む）で、計画書 §2 への反映は v2.5 の案として設計書と同じ回に承認を受ける（Phase 2 の進め方の P2-4）

- 表のセル（変更履歴の概要・内容を含む）は、1 セル 1〜2 文にする。収まらなければ重要なもの以外を「、他」で丸める（2026-11-08 の作業指示者の指摘）
  - 列は、見出しの語で主キーの列と説明の列に分ける。主キーの列は、行を分ける列（用語・ID・番号・J・案・選択肢・項目・日付・版数など）と、ほかの表の行を指す列（J の番号、割り当て表の行の ID など）。説明の列は、それ以外（定義・内容・概要・理由・長所・短所・詳しくは・備考など）。どちらとも決まらない見出しは、判断せずに報告し、決まったらこの項の見出しの語の例に足す
  - 1 つの事柄（表を RDB の表として見た時の 1 レコード）は、複数の行に分けない。主キーの列の値がすべて同じ行が続くなら 1 行にまとめ、セルの中の複数の事項を `<br>` で分ける（`.md` では 1 行のままなので、grep の 1 行で事柄の値がそろう）
  - 方針 A（既定）: 上の行と同じ値を「〃」と書けるのは、説明の列だけ。主キーの列は、行を探す時やほかの表と紐づける時に grep するので、同じ値でも書く
  - 方針 B: 方針 B の一覧に挙げた種類の表だけは、主キーから外しても支障の無い列をほかの列に含め、主キーの列を減らして書く。一覧は、レビューなどで種類を見つけた時にこの項に足す（今は空）
  - 変更履歴の表は方針 A で、主キーは日付と版数の組（版数は本紙と別紙の行を紐づける）。本紙は 1 改訂 1 行で、日付と版数が同じ行は 1 行にする。別紙は 1 変更 1 行で、日付と版数が同じ行が並んでよい。版数の欄には値だけ（複数の文書を受け持つ別紙では「設計書 v0.8」のように文書の名を付けた値）を書き、「〃」や「（同じ版）」を付けない。版数の列が無い CLAUDE.md の別紙は、「日ごとの概要」が日付を主キーに 1 日 1 行、「明細」が 1 変更 1 行。追記だけの別紙は既にある行を書き換えず、後日の変更も新しい行にする。この項の決まりは、追記だけの別紙では新しく足す行にだけ当てる
  - 体言止めを基本にする（文字数が減り、1 文に複数の事項を並べにくくなる）。厳守の決まりではなく、体言止めにすると分かりにくくなる文や、否定・条件・限定が落ちる文は、述語で終える
- 本活動フォルダのテキストファイルの改行は LF にそろえる。例外は PowerShell のファイル（`.ps1`・`.psm1`・`.psd1`。UTF-8 + BOM + CRLF）と `.bat`（CP932 + CRLF・BOM なし。`.cmd` は使わない）で、`.gitattributes` が拡張子ごとに改行を決める（`.claude/rules/win-file-encoding.md` の規約に合わせた）。Markdown 等は書き込みの後に CR が 0 であることを確かめる（2026-10-19 に、CRLF だった 1-7・VerUP IAR(cc v2.1.287) とレビュー報告書 3 本を LF にした。作業指示者の指示）
  - 文字コードの規約の正本（`win-file-encoding` の rule・skill・hook）は develop にある（2026-10-19、0e4c4a8）。本ブランチには、develop の 2 コミットを `git cherry-pick -x` で取り込んだ（2026-10-23。作業指示者の判断。報告書が引くコミットのハッシュを保つため、rebase はしない）。`.ps1`・`.bat` を扱うときは `.claude/rules/win-file-encoding.md` と hook に従う（hook は Python 3.10 以上が `python` として PATH に要る）
