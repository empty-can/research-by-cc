# 生きている文書のスリム化の規則（v0.1、2026-10-20）

改訂とレビューを重ねて太った「生きている文書」を刈り込むときの規則。新しく書くときの規則は執筆ガイドライン（writing-guideline）にあり、本書はその隙間を埋める。本活動で試し、確かめてから develop 経由で執筆ガイドラインに足す。

## 範囲

- 対象: 生きている文書（計画書、まとめ報告書、裁定待ち事項、別紙）
- 対象外: Phase の調査報告書（1-1〜1-8。記録であり、事実の正本）、レビュー報告書、ブロック指摘一覧、追記だけの別紙

## 規則

| # | 規則 | 中身 |
|---|---|---|
| S1 | 本文は今の状態だけ | 主旨・方針・結論・推奨が途中で変わった部分の**変わった経緯だけ**を、本文から**追記していくだけの別紙**へ移す（「…追記」「それまでは…」「…に改めた」「版 X では…、版 Y では…という変化」「訂正の理由」）。**今の方針・推奨・結論の根拠、理由、前提、測定値とその典拠は、日付や版が付いていても本文に残す。** 経緯か根拠か迷ったら残す。本文から別紙へは、要るときだけ 1 行でリンクする。1 つのセルに「今の扱い」と「日付付きの経緯の連なり」が混ざっている場合は、経緯の連なりだけを日付ごとに別紙の行へ分け、今の扱いと反映先は本文に残す |
| S2 | 追記だけの別紙はレビューしない | 既存の行を書き換えないので不整合が起きない。クロスレビューは本文だけを対象にする。本文から別紙へ移した回は、レビューではなく S9 の照合で落ちが無いことを確かめる |
| S3 | 事実の正本は 1 か所 | 値を書く・残す前に順に問い、最初に当たった所で止める。(1) 手元の情報から導けるか → 1 か所だけに書く（件数・合計・下の表の要約は、読み手が使う見出しか案内の行に 1 回だけ置き、ほかの文書には写さない）。(2) 別の文書・節が正本か → 値を写さず、結論 1 行とリンクにする。(3) ある時点の独立した観測か → 版・日付を付けて正本に残す。複数の文書を直すときは、先に「事実の種類 → 正本の文書・節」の割り当て表を作る |
| S4 | 削る前に節ごとに判定する | 節（または表の行）ごとに「残す / 詰める / 別紙へ移す / 削る（正本へのリンクに替える場合を含む）」を付けてから手を入れる。「別紙へ移す」は S1 の変わった経緯に限る。「冗長に見えた」は根拠にしない。基準は長さでなく情報の密度で、消すと理由・制約・紛れの防止・承認の中身のどれかが失われるなら残す |
| S5 | 承認・判断の中身は動かさない | 選択肢のラベルと文、推奨・既定の結論、基準値、ID（Q・J・V-ID・案のラベル・C-ID・D 番号）、`<a id>`、【推定】・見込み・未確認の印、承認の状態の印（計画書の `(保留: …)`・`(承認待ち: …)` と「承認と保留」の表）は変えない。中身を変える必要が見つかったら、スリム化と分けて報告する |
| S6 | 但し書きは本題の後に | 本題を先に書き、例外・限定は別の文か表に分ける。判断に効かない限定は削る。同じ限定が節の中で繰り返されるなら、節の頭で 1 回だけ書く |
| S7 | 案内は 1 行 | 相互参照は「詳しくは [文書 §n](…)」の 1 行にし、リンク先の中身の予告・要約を書かない。見出しで分かるなら案内を書かない |
| S8 | 文を詰める | 冗長な言い方（「〜することができる」→「〜できる」、「〜を行う」→「〜する」）、前置き、ぼかし、同じ文の言い換えを削る。並列の項目は段落に畳まず箇条書きにする |
| S9 | 削った後に直し、確かめる | 削って壊れた文（「下の 4 つの…」の数など）と、行き先の無い相互参照を直す。照合のうち、スクリプトにできるもの（本文から消えた日付・版・数値・ID の語が本文か別紙にあること、リンク切れ 0、`<a id>` が残ること、CR 0）はスクリプトで行う。スクリプトにできないもの（数値や ID を含まない理由・限定・条件が本文か別紙に残っているか）は、Haiku の subagent 2〜3 体に、互いに独立に同じ範囲を照合させ、どれか 1 体でも「行き先が無い」とした文を拾う。前後の文字数と削減率、読了目安を出す |

## 順序

1. 対象の文書ごとに、節（表の行）の判定表（S4）を作る。複数の文書をまとめて扱うときは、正本の割り当て表（S3）を先に作る
2. 変わった経緯を追記だけの別紙へ移す（S1）。別紙が無い文書は新しく作る
3. 写しを正本へのリンクに替える（S3）。正本の側を先に直す
4. 但し書き・案内・文を詰める（S6〜S8）
5. 直して確かめる（S9）。その後、本文だけをクロスレビューする（S2）

## 追記だけの別紙の形

- 文書ごとに 1 本。「改訂履歴」の表（1 版 1 行。`| 日付 | 版数 | 内容 |`）と「経緯」の表（1 出来事 1 行、数文まで。`| 日付 | 対象（文書 §n・J-n など） | 何が変わったか | 理由・典拠 |`）を持つ
- 既存の行は書き換えない。表の末尾に行を足すだけ
- 節ではなく表にするのは、追記が「表の末尾に 1 行足す」だけで済み、見出しやアンカーを増やさず、日付や対象で行を探せるため
- 本活動では、計画書とまとめは既存の `【別紙】改訂履歴.md` に「経緯」の表を足す。裁定待ち事項と V-ID 別紙は、同じフォルダに別紙を新しく作る

## 出典

考え方だけを借りた（文は写していない）。

- 作業指示者の指示（2026-10-20）: 変わった経緯を追記だけの別紙に分けること、その別紙はクロスレビューしないこと、照合に Haiku の複眼を使うこと、根拠を誤って移さないこと
- daymade/claude-code-skills の docs-cleaner（MIT）: 写し・派生値・日付付きの経緯を順に問う試験、削る前の節ごとの判定、削った後の修復
- mlwelles/technical-writing-density（MIT）: 長さでなく情報の密度で削るかを決め、理由・制約・紛れの防止を残す
- laurigates/claude-plugins の prose-distill（MIT）: 無損失の圧縮、削減率の報告
- ADR と changelog（今の状態と経緯の分離）、single source of truth、Plain Language、Information Mapping、Every Page is Page One（いずれも二次資料での確認。執筆ガイドラインに足す前に一次資料で確かめる）
