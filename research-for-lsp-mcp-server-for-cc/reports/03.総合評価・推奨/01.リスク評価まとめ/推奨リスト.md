## 最終推奨

### 🥇 第1推奨（低リスク × 要件適合）

**1. bug-ops/mcpls（A・Rust）** — 総合の最有力
- **Java=jdtls・Maven/Gradle を明示**（必達要件に最も近い）。**依存スキャン0件**で最クリーン。**Rust 単一バイナリ＝実行時依存ゼロ**で版上げ破損・他ツール衝突・重さの運用リスクが最小。活発（v0.3.6・2026-06）。
- 留意: ★43 と中規模。open issues 46（URI panic 等の堅牢性バグをメンテナが #167/#168 で tracking 中）→ 実運用での安定性は採用前に最新状況を確認。

**2. blackwell-systems/agent-lsp（A・Go）** — ほぼ同格
- **jdtls 明示・30言語CI検証・65ツール**で能力首位（85.2）。Go 単一バイナリで運用軽量、検出 CVE は Go ツールチェーン更新で解消する範囲（ネット系で局所低relevance）。活発（v0.15.0・2026-06）。
- 留意: ★59 で比較的新興 → 長期保守の継続観察。

### 🎯 用途特化・基盤推奨

**3. sunix/jdtls-mcp（B・Java）** — Java 機能を最重視するなら
- jdt.ls の **Java 機能カバレッジ最多（hover/定義/参照/補完/診断/symbol×2・7ツール）**、5プラットフォームの**自己完結プレビルドバイナリ**、依存クリーン。★3 だが機能・運用面は堅実。EPL-2.0 のみ留意。

**4. isaacphi/mcp-language-server（A・Go）** — 汎用の安定基盤
- ★1554 と最大級の実績、Go 単一バイナリ、依存クリーン＋govulncheck 組込。Java は汎用設定（jdt.ls 接続は構造上可・要設定検証）。「枯れた汎用ブリッジに jdt.ls を載せる」堅実路線。

### ⚖️ 条件付き

**oraios/serena（A・Python）** — 最大能力・最大エコシステムだが運用重
- 能力・実績（★25,604）・対応姿勢は突出。脅威モデル下でセキュリティ懸念は薄れるが、**Python 実行時211依存**の運用重量（破損・衝突・軽快さ）と **jdt.ls 未確認**が抑制要因。「能力最優先で Python 環境を許容」できるなら有力。

### 🔬 比較・代替（非LSP・カテゴリC）
**DeusData/codebase-memory-mcp** ほか tree-sitter 系は、jdt.ls の意味解析は持たないが、**単一バイナリで運用軽量**かつ大採用。「LSP を立てずに symbol/検索で済ます」代替路線として並走比較対象。

| agent-lsp | 新興ゆえの長期保守継続性 |

## 結論（当初依頼への回答）

> 「リスクの小さいもの」= **bug-ops/mcpls** と **blackwell-systems/agent-lsp** の2件を第1推奨とする。
> いずれも jdt.ls 連携・依存クリーン・単一バイナリで運用軽量・活発という低リスク条件を満たす。
> Java 機能の網羅性を最重視するなら **sunix/jdtls-mcp**、汎用の枯れた基盤なら **isaacphi/mcp-language-server** を併せて推奨。
> serena は能力最大だが Python 運用重量を許容できる場合の選択肢。
