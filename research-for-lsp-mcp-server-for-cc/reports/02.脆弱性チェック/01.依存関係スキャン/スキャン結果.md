# Phase 2: 依存関係スキャン結果（統合版）

作成日: 2026-06-21 / 統合: メインセッション（Opus）
対象: 採用候補10件（Primary 5 + Secondary 5）＋依存先 LSP 本体
手法: **ハイブリッド**（作業指示者確定 2026-06-21）

## 手法と重要な解釈上の注意

| パス | 対象 | 手法 |
|---|---|---|
| **深掘り（Primary 5）** | agent-lsp / serena / mcpls / LSP4J-MCP / DeusData | shallow clone → `osv-scanner 1.9.2` でロックファイル再帰スキャン（osv.dev 照合）。**install/build はせずロックファイル読取のみ** |
| **軽量（Secondary 5）** | jdtls-mcp / isaacphi / code-index-mcp / ProfessioneIT / tree-sitter-analyzer | GitHub API でマニフェスト取得 → GitHub Advisory DB 照合（詳細は `軽量スキャン_Secondary.md`） |

### 解釈上の必須注意（誤読防止）
- **テストフィクスチャを除外**: osv-scanner の生出力には serena の `test/resources/repos/*`（angular/go/java/rust のサンプルリポジトリ）や agent-lsp の `test/fixtures/*` が大量に含まれたが、**これらは製品依存ではなくテスト用サンプル**のため本報告から除外した。**生のヒット件数をそのまま脆弱性数として扱うのは誤り。**
- **Go stdlib のヒット**は go.mod が宣言する **Go ツールチェーンのバージョン**に対する勧告（GO-2026-xxxx 等）であり、**Go 更新で解消**する。govulncheck の "uncalled"（到達不能）分類も併記された。
- **dev依存**（devDependencies）はビルド時のみで MCP サーバ本体には同梱されないため、本番リスクは低いものとして区別した。
- serena の実依存は `uv.lock`（osv-scanner 1.9.2 非対応）を **requirements 形式に変換**して211パッケージをスキャンした。

## 利用環境の前提（脅威モデル）と評価軸 — 2026-06-21 追記

**利用前提（作業指示者確定）**: Claude Code・MCP サーバ・言語サーバが**同一ローカル環境で stdio 起動**し、言語サーバはローカル clone 済みリポジトリ（自社プロダクト or Spring 等の OSS）に対して動作する。**MCP サーバが外部ネットワークに出る必要はない**（依存ライブラリも gradle 等でローカル解決）。

この前提下では検出 CVE の**実効リスクは性質で大きく変わる**:
- **ネットワーク/Web/トランスポート系 → ほぼ無関係**（外部公開しないため攻撃面が無い）: 例 MCP SDK のデータリーク/DNSリバインド、starlette/tornado/python-multipart、logback SSRF系、Go stdlib の TLS/net 系。
- **対象リポジトリ内容の処理系 → 低残存**（信頼リポジトリのみなら低、未知 OSS 解析時のみ低〜中）: 例 gitpython、各種パーサ。
- **ReDoS/DoS → 自己DoS**で深刻度低。

→ **候補間のセキュリティ差はほぼ平坦化**（mcpls=0 を除く）。下記「リスク帯」は素の依存CVE視点であり、**脅威モデル適用後の実効リスクは別**である点に注意。

### 追加評価軸: 運用依存フットプリント（配布形態ベース）
利用前提に関わらず「依存は少ない方がよい」（版上げ破損・軽快さ・他ツール衝突）。ただし**生の依存数ではなく実行時フットプリント×配布形態**で測る:
- **Go/Rust 単一バイナリ**（agent-lsp / mcpls / isaacphi / DeusData コア）= 実行時依存ゼロ・衝突なし＝最軽量。**mcpls の Cargo.lock 240 はコンパイル時のみで、serena の Python 211 実行時依存とは運用上まったく別物。**
- **JVM jar / Node**（LSP4J-MCP・jdtls-mcp / ProfessioneIT）= 中。
- **Python 実行時環境**（serena 211 / code-index-mcp / tree-sitter-analyzer）= 数に比例して衝突・破損・重さ増 → serena 最重。

**→ この2点（CVE再重み付け＋運用フットプリント軸）を適用した risk-adjusted 最終ランキングは `../../03.総合評価・推奨/` で確定する。**

## Primary 5（深掘り・製品依存のみ）

### 1. bug-ops/mcpls（Rust）— ✅ クリーン
- `Cargo.lock` 240 パッケージ → **既知脆弱性 0 件**。
- **Primary 中で最もクリーン。**

### 2. blackwell-systems/agent-lsp（Go）— 低（ツールチェーン）
- ルート `go.mod`: **Go stdlib 1.26.1** に対する勧告（GO-2026-4866/4869/4870/4918/4946/4947/4971/5037/5039 が "called"=到達可、計9件）。第三者依存に CVE ヒットなし。`golang.org/x/sys 0.42.0` は "uncalled"。
- → **Go ツールチェーン更新で解消する範囲**。サードパーティ依存は健全。

### 3. stephanj/LSP4J-MCP（Java）— 中（要バージョン更新）
- `pom.xml`（14パッケージ）:
  - `ch.qos.logback:logback-core 1.5.12` — 4件（CVSS 5.9 / 2.4 / 5.9 / 1.8）: GHSA-25qh-j22f-pwp8 / 6v67-2wr5-gvf4 / pr98-23f8-jwxv / qqpg-mvqg-649v
  - `com.fasterxml.jackson.core:jackson-core 2.17.0` — 1件（CVSS 6.9）: GHSA-72hv-8253-57qq
- → **中程度。logback/jackson のマイナー更新で解消可能。**

### 4. DeusData/codebase-memory-mcp（Go + UI）— 中（dev/UI に集中）
- `pkg/go/go.mod`: Go stdlib 1.26.1 ツールチェーン勧告（agent-lsp と同種）。
- `graph-ui/package-lock.json`: **すべて devDependencies** — `vite 6.4.2`（CVSS 8.2 / 5.5）, `form-data 4.0.5`（8.7）, `@babel/core 7.29.0`（3.2）。**UI サブコンポーネントのビルド時依存で MCP サーバ本体には非同梱。**
- `vendored/`（mimalloc/sqlite3/nomic/xxhash 等の C ライブラリ）・`vendored/grammars`: **ロックファイル外の vendored ネイティブコード**でスキャン対象外 → **サプライチェーン観点で別途留意**（self-contained ゆえ自前ベンダリングが多い）。
- → コア（Go）は低（ツールチェーン）、dev/UI 依存は中だが非同梱。

### 5. oraios/serena（Python・211依存）— 中〜高（依存面が最大）
- `uv.lock`（211パッケージ）に複数の既知勧告:
  - **`gitpython 3.1.46` — 5件（CVSS 最大 8.8）**: GHSA-rpm5-65cw-6hj4(8.8) / x2qx-6953-8485(8.1) / 7545/v87r(7.8) / mv93(7.0)
  - `cryptography 46.0.7`（7.5）, `msgpack 1.1.2`（7.5）, `python-multipart 0.0.27`（4件）, `starlette 1.0.1`（4件・最大7.5）, `pyjwt 2.12.0`（PYSEC-2026 5件）, `tornado 6.5.6`（5.9）, `pydantic-settings`(5.3), `pygments`(3.3), `pytest`(6.8)
- 多くは Web ダッシュボード（starlette/tornado/python-multipart）や git 操作（gitpython）系の運用依存。
- → **Primary 中で依存脆弱性面が最大。**ただし機能利用範囲に依存（Web 機能不使用なら一部は非経路）。

## Secondary 5（軽量・マニフェストレベル）

詳細は `軽量スキャン_Secondary.md`。要点:

| 候補 | エコシステム | 結果 |
|---|---|---|
| **ProfessioneIT/lsp-mcp-server** | TS | **`@modelcontextprotocol/sdk ^1.0.0` に High 3件**（CVE-2026-25536 クロスクライアントデータリーク / ReDoS / DNS リバインディング）。`^1.0.0` は最新1.xを許容 → **package-lock の実ロック版確認要**（1.26.0+ なら解消） |
| tree-sitter-analyzer | Python | `anthropic` に勧告検出も**指定版は修正済み**＝実害なし |
| sunix/jdtls-mcp | Java | 直接依存ヒットなし（p2依存は未固定でスキャン外） |

## 依存先 LSP 本体の素性（Opus 申し送り・定性評価）

リスクはブリッジ側だけでなくラップする LSP 本体にも宿る。本スキャンは MCP リポジトリのみ対象のため、外部バイナリの LSP 本体は定性評価:

| LSP 本体 | 依存する候補 | 素性 |
|---|---|---|
| **Eclipse JDT LS（jdt.ls）** | agent-lsp / mcpls / jdtls-mcp / (serena?) | Eclipse Foundation・成熟・広範な利用と保守。確立度高く相対的に低リスクだが大規模コードベース。**別途インストールされる外部バイナリ**として版管理が必要 |
| **`idelice/jls`** | ProfessioneIT | ★120・2025-12 作成の**新興・低被監査**。サプライチェーン不確実性は jdt.ls より高い。要素性確認 |
| **tree-sitter グラマー群** | C 群（DeusData 等） | vendored ネイティブコード。グラマーのサプライチェーン健全性は個別確認対象 |

## 依存関係リスク・サマリ（Issue調査と合わせて 03 で最終評価）

| リスク帯 | 候補 | 根拠 |
|---|---|---|
| **最小（クリーン）** | **mcpls**（0件）/ tree-sitter-analyzer / code-index-mcp / isaacphi / jdtls-mcp | ヒットなし or 修正済み |
| **低（ツールチェーン/軽微更新で解消）** | agent-lsp（Go更新）/ LSP4J-MCP（logback・jackson更新） | 既知だが容易に解消可能 |
| **中（要確認・対応）** | ProfessioneIT（MCP SDK ロック版確認）/ DeusData（UI dev依存・vendored C） | 条件次第・非同梱が多い |
| **中〜高（依存面が広い）** | **serena**（211依存・gitpython 8.8 ほか複数 High） | 運用依存に複数勧告。利用機能に依存 |

**Issue調査（`../02.Issue調査/Issue調査結果.md`）との総合所見**: セキュリティ Issue の放置は全10件で確認されず、serena・code-index-mcp はむしろ**対応姿勢良好**（即時応答・18日で修正）。よって「依存面のリスク」と「メンテナのセキュリティ対応力」を分けて評価でき、03 の最終ランキングで両軸を統合する。

## 限界・申し送り
- osv-scanner 1.9.2 は **uv.lock 非対応**（変換で対処）・Maven の p2 依存・vendored ネイティブコードは未カバー。
- Go stdlib 勧告はツールチェーン版依存。各候補が CI で Go/依存を更新していれば実効リスクは下がる（最終評価で考慮）。
- クローンは `.claude/work/phase2-clones/`（gitignore 対象、コミットしない）。再スキャン用に一時保持。
