## Spring Boot / Gradle 対応の構造的結論（Agent C）

| 経路 | Spring Boot | Gradle |
|---|---|---|
| 専用 LSP MCP Server | **存在せず** | **存在せず** |
| 汎用ブリッジ（isaacphi 等） | **条件付き可**（spring-boot-language-server を stdio 起動できれば。要 jdt.ls 同時起動・未実証） | **不可**（gradle-language-server が named pipes 専用で stdio 非対応） |
| 参考: ビルド操作専用 | — | `rnett/gradle-mcp`（★52・LSPではない別物）|

- **Spring Boot**: `spring-boot-language-server`（spring-tools 内・970★）は実在。`.vsix` から JAR 抽出 + jdt.ls 2層構成が必要で**難度高・未実証**。
- **Gradle**: LSP 的なコード補完用途は現状の汎用ブリッジでは**ほぼ不可**（named pipes 制約）。

→ **現実の温度差**: Java(jdt.ls) ≫ Spring Boot(条件付き・未実証) ≫ Gradle(LSP用途は困難)。
