## ランキング考察

### トップ集団（総合 ≥ 80）— 4分類が拮抗
- **agent-lsp / mcpls**（A・jdtls明示）と **jdtls-mcp/LSP4J-MCP**（B・jdt.ls直）が、必達軸（jdt.ls）と保守の両立で上位。
- **serena**（A・★25604）は jdt.ls 未確認で方式が伸び切らないが、保守・実績・適合の総合力で2位。**jdt.ls 確定なら単独首位**になり得る。
- **DeusData**（C・★9820）が5位に食い込む。tree-sitter 型で Java 方式は構造的に低いが、保守・実績・Claude Code 適合が満点級で総合的に競争力。**「非LSP型でもここまで来る」という比較の核**。

### 中位集団（70〜79）
- jdt.ls 機能最多の **jdtls-mcp**（★3 で実績は低いが方式・適合は最上位）、汎用最大実績の **isaacphi**（Java未検証が足枷）、C型実用の **code-index-mcp/tree-sitter-analyzer**、jls 採用の **ProfessioneIT**。

### 下位・特殊
- HTTP/SSE で stdio 非対応の java-lsp-mcp-server、ctags の toktoken、clangd 起点の karellen、macOS限定 alpha の sts5-headless。
